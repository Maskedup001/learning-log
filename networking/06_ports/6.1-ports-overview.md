# Тема 6.1: Общее понятие портов

Изучение концепции портов как идентификаторов приложений на транспортном уровне, их роли в модели OSI, диапазонов значений и практического применения в диагностике сетей.

---

## 1. Порты — Базовые свойства

- **Уровень OSI:** Транспортный уровень (L4).
- **Сущность данных (PDU):** Сегмент (для TCP) / Датаграмма (для UDP).
- **Размер поля:** 2 байта (16 бит).
- **Количество портов:** $2^{16} = 65 536$ (от `0` до `65535`).
- **Принцип работы:** Порт уникально идентифицирует приложение на хосте. Пара `IP-адрес:Порт` однозначно определяет конкретное сетевое приложение в глобальной сети.

![Разные клиенты обращаются к разным приложениям на одном сервере через разные порты.png](/attachments/networking/06_ports/6.1-ports-overview/Разные%20клиенты%20обращаются%20к%20разным%20приложениям%20на%20одном%20сервере%20через%20разные%20порты.png)

*Рис. 1. Разные клиенты обращаются к разным приложениям на одном сервере через разные порты (`80` для HTTP, `25` для SMTP).*

### Иерархия адресации

| **Уровень** | **Что обеспечивает** | **Идентификатор** |
| :--- | :--- | :--- |
| Канальный уровень (L2) | Доставку данных в рамках одного сетевого сегмента | **MAC-адрес** |
| Сетевой уровень (L3) | Доставку данных между хостами | **IP-адрес** |
| **Транспортный уровень (L4)** | Доставку данных между **приложениями** | **Порт** |
*Таб. 1. Иерархия адресации.*

### 1.1. Пятикортежное соединение (Five-Tuple)

Каждое сетевое соединение однозначно определяется пятью параметрами:
1. `Src IP` (IP-адрес источника)
2. `Src Port` (порт источника)
3. `Dst IP` (IP-адрес назначения)
4. `Dst Port` (порт назначения)
5. `Protocol` (протокол: TCP или UDP)

> **Почему это важно:** Именно Five-Tuple позволяет NAT и Firewall различать миллионы одновременных соединений. Если поменяется хотя бы один параметр (например, порт клиента при переподключении), это уже считается новым соединением.

![Поля Source Port и Destination Port в заголовке TCP.png](/attachments/networking/06_ports/6.1-ports-overview/Поля%20Source%20Port%20и%20Destination%20Port%20в%20заголовке%20TCP.png)

*Рис. 2. Поля `Source Port` и `Destination Port` в заголовке TCP. Порт (в оранжевой рамке) идентифицирует приложение, в то время как MAC и IP отвечают за доставку до устройства.*

> **Важное уточнение:** Один порт не может быть открыт разными приложениями в одно и то же время. Однако одно и то же приложение может открыть несколько портов. Разные приложения могут использовать один и тот же порт в разное время (поочерёдный запуск веб-серверов на порту 80).

![Реальный пакет в Wireshark.png](/attachments/networking/06_ports/6.1-ports-overview/Реальный%20пакет%20в%20Wireshark.png)

*Рис. 3. Реальный пакет в Wireshark. Видно, как `Source Port: 56756` (временный порт клиента) обращается к `Destination Port: 443` (HTTPS-сервер). Это показывает, как порты идентифицируют приложения в реальном трафике.*

### 1.2. Эфемерный порт: почему клиент взял порт 56756?

Когда компьютер инициирует исходящее соединение (например, открывает сайт), операционная система автоматически выделяет ему **эфемерный (временный) порт** из диапазона `49152-65535` (`Dynamic / Private Ports`). 

В нашем примере браузер взял порт `56756`. Это число попадает ровно в этот диапазон. ОС выбирает его случайно, чтобы не конфликтовать с другими открытыми приложениями на том же хосте. Когда соединение закрывается, порт освобождается для новых задач.

## 2. Диапазоны портов и классификация

Согласно реестру IANA, порты делятся на три чётко определённых диапазона, что критично для понимания привилегий и безопасности.

| **Диапазон**      | **Название**                               | **Особенности**                                                                                                                                              |
| :---------------- | :----------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0` – `1023`      | **System Ports (Привилегированные)**       | Может открыть только администратор/суперпользователь. На этих портах работают известные службы (`HTTP: 80`, `HTTPS: 443`, `DNS: 53`, `SMTP: 25`, `SSH: 22`). |
| `1024` – `49151`  | **User Ports (Зарегистрированные)**        | Может открыть обычный пользователь. Используются для приложений, которые прошли регистрацию в IANA (например, `MySQL: 3306`, `RDP: 3389`).                   |
| `49152` – `65535` | **Dynamic / Private Ports (Динамические)** | Не назначаются. Используются для временных соединений (эфемерные порты), которые выделяются операционной системой клиенту для исходящих запросов.            |
*Таб. 2. Диапазоны портов и их классификация (источник: [RFC6335](https://www.ietf.org/rfc/rfc6335)).*

> **Почему это важно для администратора:** Привилегированные порты (`0-1023`) открываются только от имени root. Это защита от того, чтобы обычный пользователь мог запустить сервис, маскирующийся под легитимный (например, поддельный HTTP-сервер).

> **Интересный факт из реестра:** Порт `666` официально закреплён за игрой **Doom**, а порт `466` — за `Oracle SQL*NET`.

![Порты в стеке TCP_IP.png](/attachments/networking/06_ports/6.1-ports-overview/Порты%20в%20стеке%20TCP_IP.png)

*Рис. 4. Порты в стеке TCP/IP: SMTP использует порт `25`, HTTP — `80`, DNS — `53`. Это примеры "хорошо известных" портов.*

## 3. Практическая диагностика: netstat и ss

Для просмотра открытых и активных портов используются утилиты `netstat` (Windows/Linux) и `ss` (Linux).

### Команды для разных ОС

| **ОС**      | **Команда**                                                                                                  | **Что показывает**                                                                                                                                          |
| :---------- | :----------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Windows** | `netstat -an` <br> `netstat -ano` (с PID) <br> `netstat -anb` (с именем процесса)                            | Все активные соединения и слушающие порты (`LISTENING`). `-o` добавляет PID, `-b` добавляет имя исполняемого файла.                                            |
| **Linux**   | `netstat -tuln` <br> `ss -tuln` <br> `netstat -anltp` (с PID) <br> `ss -tuap` (с PID)                        | **`-tuln`** — только слушающие TCP/UDP порты в числовом виде (как на твоем скриншоте). **`-anltp`** — все соединения с PID. `ss` — современная замена `netstat`. |
| **MacOS**   | `netstat -anl` <br> `netstat -anv` (с PID)                                                                    | Все соединения и слушающие порты. `-v` добавляет информацию о процессе.                                                                                       |
*Таб. 3. Утилиты для просмотра портов в разных ОС.*

> **Альтернатива для Windows:** В PowerShell можно использовать `Get-NetTcpConnection -State Listen`, а также графический инструмент **TCPView** от Microsoft Sysinternals.

![Реальный вывод netstat на Linux.png](/attachments/networking/06_ports/6.1-ports-overview/Вывод%20netstat%20на%20Windows.png)

*Рис. 5. Реальный вывод `netstat` на Linux. Видно, что порт `53` (DNS) слушает только локальный адрес `127.0.0.53`, а порты `111`, `22` и `631` — на всех IP (`0.0.0.0`).*

![Вывод ss на Linux.png](/attachments/networking/06_ports/6.1-ports-overview/Вывод%20ss%20на%20Linux.png)

*Рис. 6. Вывод `ss`. Видно, что для UDP-сокетов состояние `UNCONN` (нет соединения), а для TCP — `LISTEN` (ожидание входящих). Строка `0.0.0.0:22` — это SSH, слушающий все интерфейсы.*

![Вывод netstat на Windows.png](/attachments/networking/06_ports/6.1-ports-overview/Вывод%20netstat%20на%20Windows.png)

*Рис. 7. Вывод `netstat` на Windows. Видно `LISTENING` (слушает) и `ESTABLISHED` (активные соединения). Строка `0.0.0.0:135` — приложение слушает все IP на порту 135.*

### Разбор ключевых колонок вывода netstat

| **Колонка** | **Описание** |
| :--- | :--- |
| **Proto** | Протокол транспортного уровня (`tcp`, `udp`). |
| **Local Address** | Локальный IP-адрес и порт. Если `0.0.0.0` — приложение слушает все IP-адреса хоста. |
| **Foreign Address** | Удалённый IP-адрес и порт. |
| **State** | Состояние соединения (только для TCP). UDP не имеет состояний. |
| **PID** | Идентификатор процесса, открывшего порт. |
*Таб. 4. Описание колонок вывода команды netstat.*

## 4. Разбор сложных инженерных ситуаций и аномалий

### 4.1. Могут ли несколько приложений использовать один порт?

**Вопрос:** *Можно ли открыть один порт разными приложениями?*

**Технический ответ:** **Нет, в одно и то же время**. Одно приложение может открыть несколько портов, а разные приложения могут использовать один и тот же порт только последовательно. При попытке запустить второе приложение на уже занятом порту возникает ошибка `Address already in use`.

> **Важное уточнение:** TCP и UDP — это **разные протоколы**, хотя оба используют номера портов. Поэтому одно и то же число порта могут одновременно занимать одно TCP-приложение и одно UDP-приложение. 
> 
> **Пример:** Сервис DNS использует порт `53` сразу для двух протоколов: TCP (для передачи больших ответов) и UDP (для быстрых запросов). Это не конфликт, так как транспортные протоколы имеют независимые пространства портов.

### 4.2. Что означает `0.0.0.0` в колонке Local Address?

**Вопрос:** *Что означает `0.0.0.0` в колонке Local Address?*

**Технический ответ:** Значение `0.0.0.0` в колонке `Local Address` означает, что приложение **слушает все IP-адреса данного хоста**, но на **строго указанном порту**.  
Например, запись `0.0.0.0:22` означает, что SSH-сервер ожидает входящие подключения **на всех сетевых интерфейсах** машины (и с любых удалённых IP-адресов), но **только на порту 22**. Это отличается от `127.0.0.1:22` (принимает подключения только с локальной машины) или `192.168.1.5:22` (принимает подключения только с конкретного IP-адреса интерфейса).

> **Почему это важно:** Настройка `0.0.0.0` удобна для серверов с несколькими сетевыми интерфейсами, так как служба становится доступной сразу на всех интерфейсах без необходимости указывать каждый IP отдельно.

### 4.3. Почему у UDP отображаются состояния в netstat/ss?

**Вопрос:** *Почему у UDP иногда отображаются состояния (например, ESTABLISHED)?*

**Технический ответ:** Формально UDP не имеет состояний. Однако в утилите `ss` для UDP-сокетов может отображаться `UNCONN` (стандартное состояние) или `ESTABLISHED`. `ESTABLISHED` появляется, если в программе вызвана функция `connect()` для UDP-сокета. Это не означает установки реального соединения, а лишь то, что ядро привязало сокет к конкретному удалённому адресу.

### 4.4. Как порты переписываются в NAT?

**Вопрос:** *Как порты участвуют в трансляции адресов (NAT)?*

**Технический ответ:** NAT использует порты для различения соединений за одним внешним IP-адресом.
*   **SNAT (Source NAT):** Когда внутренний хост `192.168.1.100:54321` выходит в интернет, роутер меняет его на внешний IP и внешний порт, например, `203.0.113.5:40001`. Обратный ответ приходит на порт `40001`, и роутер знает, что это соединение принадлежит хосту `192.168.1.100:54321`.
*   **DNAT (Destination NAT):** Когда внешний пакет приходит на `203.0.113.5:8080`, роутер перенаправляет его на внутренний сервер `192.168.1.100:80`. Это используется для проброса портов (например, чтобы открыть веб-сервер из интернета).

> **Связь с другим конспектом:** Более детальный разбор трансляции адресов находится в [[3.8 NAT (Network Address Translation)]].

## 5. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости

- **Сканирование портов (Port Scanning):** Злоумышленники используют утилиты типа `nmap` для поиска открытых портов и уязвимых служб. Например, `nmap -sS -p- 192.168.1.1` выполняет SYN-сканирование всех `65535` портов целевого хоста.
- **Перехват портов (Port Hijacking):** Если приложение закрыло порт, злоумышленник может открыть его и перехватывать трафик.
- **DDoS-атаки на порты:** Перегрузка определённого порта (например, `80` или `443`) может вывести веб-сервер из строя.
- **Уязвимости привилегированных портов:** Если злоумышленник получит административные права, он сможет открыть привилегированные порты (`0-1023`) и маскировать свои службы под легитимные.

### 2. Меры защиты портов

Для ограничения доступа к портам используются сетевые экраны (Firewall). Правила фильтрации строятся на основе Five-Tuple (IP, порт, протокол).

```bash
# Разрешить входящие подключения только на порт 22 (SSH)
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# Запретить всё остальное
iptables -A INPUT -j DROP
```

> **Современная альтернатива:** В большинстве современных дистрибутивов Linux (Ubuntu, Debian) для настройки сетевого экрана проще использовать `ufw` (Uncomplicated Firewall), который является обёрткой над `iptables`:
>
> ```bash
> # Разрешить входящие подключения только на порт 22 (SSH)
> sudo ufw allow ssh
>
> # Разрешить входящие подключения на порт 443 (HTTPS)
> sudo ufw allow https
>
> # Включить фаервол (при этом все входящие, кроме разрешённых, будут заблокированы)
> sudo ufw enable
>
> # Показать текущие правила
> sudo ufw status verbose
> ```
>
> `ufw` значительно снижает когнитивную нагрузку: он автоматически управляет правилами `iptables` и позволяет быстро настраивать базовые политики без необходимости изучать сложный синтаксис.

> **Практический совет:** Закрывайте все неиспользуемые порты, ограничивайте доступ к привилегированным портам (`0-1023`) и обязательно используйте `fail2ban` для автоматической блокировки IP при попытках перебора паролей.

### 3. Инженерный FAQ

**Вопрос:** *Зачем вообще применять UDP, если TCP надёжнее?*
**Технический ответ:** UDP используется там, где **скорость** важнее надёжности: потоковое видео, онлайн-игры, VoIP, DNS-запросы. TCP добавляет задержки на установку соединения и повторную передачу данных.

**Вопрос:** *Что будет, если запущенных приложений будет больше 65 535?*
**Технический ответ:** Кому-то просто не хватит портов. На практике такое случается крайне редко, потому что одно приложение может использовать несколько портов, а общее количество сетевых процессов обычно не превышает нескольких тысяч.

## Заключение

Порты — это фундаментальный механизм транспортного уровня, обеспечивающий адресацию приложений на хосте. Понимание диапазонов портов, их привилегий и инструментов диагностики (`netstat`, `ss`) является обязательным для любого сетевого инженера и специалиста по информационной безопасности.
