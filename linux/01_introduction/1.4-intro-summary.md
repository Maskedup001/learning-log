## 2. Разбор контрольных вопросов (с пояснениями)

В данном разделе представлен разбор контрольных вопросов с обоснованием правильных ответов и анализом типичных ошибок

### 2.1. Какой номер порта используется по умолчанию для подключения по SSH?

**Вопрос:** *Какой номер порта используется по умолчанию для подключения по SSH протоколу?*

**Варианты ответов:**
- `443`
- **`22`** 
- `8080`
- `80`

**Правильный ответ:** `22`

**Разбор:**
- Порт `22` — стандартный порт для SSH, назначенный IANA (Internet Assigned Numbers Authority).
- **Почему не другие?**
  - `80` — HTTP (веб-трафик).
  - `443` — HTTPS (защищённый веб-трафик).
  - `8080` — альтернативный порт для веб-серверов.
- **Инженерный FAQ:** *Почему именно порт 22?*  
  Это исторический выбор, сделанный при создании протокола. Технических причин для выбора именно 22 не было — просто так сложилось, и де-факто этот порт стал стандартом.

---

### 2.2. Какой способ подключения к удаленному серверу считается более безопасным?

**Вопрос:** *Какой способ подключения к удаленному серверу считается более безопасным?*

**Варианты ответов:**
- Через FTP протокол
- Через веб-интерфейс без аутентификации
- **С использованием пары ключей (приватный и публичный)** 
- С помощью логина в виде email и сложного пароля

**Правильный ответ:** *С использованием пары ключей (приватный и публичный)*

**Разбор:**
- **FTP** — передаёт данные и пароль в открытом виде, не шифрует трафик.
- **Веб-интерфейс без аутентификации** — вообще не требует проверки личности.
- **Логин и сложный пароль** — лучше, чем ничего, но пароль всё ещё может быть подобран или перехвачен.
- **Пара ключей (приватный + публичный)** — самый безопасный метод, потому что:
  - Приватный ключ **никогда не передаётся по сети**.
  - Аутентификация происходит через криптографическое подтверждение владения ключом.
  - Ключи сложнее подобрать, чем пароль (особенно при использовании алгоритмов RSA или Ed25519).

### 2.3. Начиная с какой версии Windows появилась возможность выполнять подключение по SSH из терминала?

**Вопрос:** *Начиная с какой версии Windows в ней появилась возможность выполнять подключение по SSH протоколу прямо из терминала ОС?*

**Варианты ответов:**
- **Windows 10** 
- Windows 7
- Windows 11
- Windows 95

**Правильный ответ:** `Windows 10`

**Разбор:**
- Начиная с **Windows 10 (версия 1809, октябрь 2018)**, в систему был встроен SSH-клиент `OpenSSH`. Он устанавливается как дополнительный компонент и доступен прямо из `cmd` и `PowerShell`.
- В **Windows 11** он уже есть по умолчанию, но первая версия с официальной поддержкой — именно **Windows 10**.
- В **Windows 7** и старше для SSH нужно было устанавливать сторонние клиенты (PuTTY, MobaXterm).
- В **Windows 95** SSH не было даже в помине — в те годы использовались telnet и rsh.

**Комментарий из обсуждения:** Опытные пользователи отмечают, что в некоторых сборках Windows 7 SSH тоже можно было запустить из `cmd`, но это **не официальная поддержка**, а скорее уловки или сторонние утилиты.

### 2.4. Какой SSH-клиент требует конвертации ключа в собственный формат?

**Вопрос:** *Какой из перечисленных SSH-клиентов требует, чтобы приватный ключ был предварительно конвертирован из стандартного формата OpenSSH в собственный формат?*

**Варианты ответов:**
- Все SSH-клиенты работают с ключами в любом формате
- Встроенный SSH-клиент Windows 10/11
- MobaXterm
- **PuTTY** 

**Правильный ответ:** `PuTTY`

**Разбор:**
- **PuTTY** использует собственный формат ключей — `.ppk`. Ключи в формате OpenSSH (`.pem` или без расширения) необходимо конвертировать через утилиту **PuTTYgen**.
- **Встроенный SSH-клиент Windows** работает с ключами OpenSSH напрямую, без конвертации.
- **MobaXterm** также поддерживает ключи OpenSSH без дополнительной конвертации.
- **Все клиенты работают с любым форматом** — это неверно, потому что PuTTY является исключением.

**Практический совет:** После конвертации ключа через PuTTYgen **не удаляйте оригинальный приватный ключ** — он может понадобиться для других клиентов.

### 2.5. Корректный формат SSH-команды для подключения из Windows

**Вопрос:** *Дано: Имя Linux-пользователя: `itguy`, IP-адрес целевой Linux машины: `192.168.1.10`. Укажите корректный вариант строки подключения к удаленной Linux машине из Windows машины по протоколу SSH (с паролем).*

**Варианты ответов:**
- **`ssh itguy@192.168.1.10`** 
- `ssh 192.168.1.10@itguy`
- `ssh 192.168.1.10@hostguy`
- `ssh hostguy@192.168.1.10`

**Правильный ответ:** `ssh itguy@192.168.1.10`

**Разбор:**
- Правильный синтаксис команды SSH:  
  `ssh <имя_пользователя>@<IP-адрес>`
- Ошибки в других вариантах:
  - `ssh 192.168.1.10@itguy` — перепутан порядок: IP должен быть после `@`, а не до.
  - `ssh 192.168.1.10@hostguy` — используется имя Windows-пользователя (`hostguy`), но сервер — Linux (`itguy`).
  - `ssh hostguy@192.168.1.10` — также неверное имя пользователя.
- **Пример правильной команды:** `ssh itguy@192.168.1.10`

## 3. Разбор типичных ошибок и вопросов из обсуждений

### 3.1. Почему именно порт 22?
*Из комментариев: «а почему именно такой порт?»*

**Ответ:** Это исторический выбор. Порт `22` был назначен для SSH при создании протокола, но технических причин для выбора именно 22 не было. Сейчас это де-факто стандарт, и все SSH-клиенты и серверы ожидают порт `22` по умолчанию.

### 3.2. Путаница с версиями Windows и SSH
*Из комментариев: «7 винда спокойно подключается через ssh, без бубнов, прямо из cmd»*

**Ответ:** Это возможно только в том случае, если в систему вручную установлен OpenSSH-клиент. Официальная встроенная поддержка появилась только в Windows 10 (версия 1809). В Windows 7 по умолчанию SSH нет — нужна сторонняя программа.

### 3.3. Как быть, если ответ не очевиден?
*Из комментариев: «Пришлось загуглить ответ на вопрос»*

**Совет:** Если вы не уверены в ответе на экзамене или собеседовании, всегда можно опереться на логику:
- SSH — безопасный протокол → использует шифрование и ключи.
- Команды в Linux строятся по шаблону `команда@адрес`.
- Стандартные порты: 22, 80, 443, 8080 — запомните их.

- **Сравнение SSH-клиентов по работе с ключами:**

| Клиент                       | Формат ключа по умолчанию       | Требует конвертации? |
| :--------------------------- | :------------------------------ | :------------------- |
| **Встроенный SSH (Windows)** | OpenSSH (.pem / без расширения) | Нет                  |
| **MobaXterm**                | OpenSSH (.pem / без расширения) | Нет                  |
| **PuTTY**                    | .ppk (собственный формат)       | Да (через PuTTYgen)  |

- **Оптимизация запоминания:** Для экзамена достаточно запомнить 4 вещи:
  1. Порт SSH — `22`.
  2. Самый безопасный метод — ключи.
  3. Встроенный SSH в Windows — с версии 10.
  4. PuTTY требует `.ppk`-конвертацию.

## 5. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Использование пароля вместо ключей** — повышает риск Brute-force и перехвата.
- **Использование стандартного порта 22** — делает сервер лёгкой целью для автоматических сканеров.
- **Компрометация приватного ключа** — если ключ попадает к злоумышленнику, он получает полный доступ.
- **Защита:** Используйте ключи, меняйте стандартный порт, применяйте `fail2ban`.

### 2. Инженерный FAQ (На основе разбора дискуссий)

- **Вопрос:** *Почему SSH использует порт 22, а не какой-то другой?*  
  **Ответ:** Это исторический стандарт, выбранный создателями протокола. Никакой технической причины нет — просто так сложилось.

- **Вопрос:** *Можно ли подключиться по SSH из Windows 7?*  
  **Ответ:** Да, но только через сторонние клиенты (PuTTY, MobaXterm). Встроенный SSH появился только в Windows 10.

- **Вопрос:** *Почему PuTTY требует конвертации ключей?*  
  **Ответ:** PuTTY использует собственный формат `.ppk` для хранения ключей. Это связано с особенностями его архитектуры, но для пользователя это означает дополнительный шаг через PuTTYgen.

- **Вопрос:** *Что делать, если я не помню правильный ответ на экзамене?*  
  **Ответ:** Исключайте заведомо неверные варианты. Например, порты 80 и 443 связаны с веб-трафиком, а не с SSH. Имена пользователей в команде должны совпадать с именем на целевой машине, а не на вашей.
