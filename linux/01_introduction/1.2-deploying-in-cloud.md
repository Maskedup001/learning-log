# Тема 1.2: Разворачивание Linux в облаках и локальной лаборатории

В данной теме разбираются принципы удалённого управления Linux-серверами по протоколу SSH, создание виртуальной машины в Yandex Cloud с генерацией SSH-ключей, а также развёртывание бесплатной локальной серверной лаборатории на базе VirtualBox с двумя ВМ (клиент и сервер) для отработки SSH-подключений без затрат на облачные ресурсы. Рассматриваются популярные SSH-клиенты (MobaXterm, PuTTY), типичные ошибки и их решение, а также вопросы безопасности.

---

## 1. SSH и удалённое управление — Базовые свойства

- **Контекст/Уровень:** Системное администрирование / Сетевая безопасность (Прикладной уровень).
- **Основное назначение:** Обеспечение безопасного удалённого доступа к командной оболочке (Shell) сервера для выполнения административных задач, управления сервисами и разработки.
- **Принцип работы:** SSH (Secure Shell) — это протокол прикладного уровня, использующий криптографию для шифрования всего трафика между клиентом и сервером. Это защищает от перехвата данных (включая пароли) и MITM-атак. Подключение устанавливается через TCP-порт `22`.

### Ключевые термины

| **Термин** | **Определение** |
| :--- | :--- |
| **SSH** | Протокол безопасного удалённого управления. Все команды передаются в зашифрованном виде. |
| **VPS** | Виртуальный выделенный сервер (Virtual Private Server). Один из вариантов размещения Linux в облаке. |
| **SSH-клиент** | Программа для подключения к удалённому серверу по протоколу SSH (встроенный `cmd`/`PowerShell`, MobaXterm, PuTTY, SecureCRT). |
| **Публичный IP-адрес** | Уникальный адрес для доступа к виртуальной машине из интернета. |
| **Приватный ключ** | Секретный файл для аутентификации, хранится на клиентской машине. **Никогда не передаётся третьим лицам.** |
| **Публичный ключ** | Открытый файл, размещается на сервере и связывается с учётной записью пользователя. |

### Способы аутентификации
1. **По логину и паролю:** Менее безопасный, часто отключается в облачных провайдерах.
2. **По паре ключей (приватный и публичный):** Более безопасный и рекомендуемый способ.

## 2. Разворачивание сервера в Yandex Cloud (Альтернативный путь)

> **Примечание:** Этот раздел описывает платный путь. Для обучения рекомендуется использовать локальную лабораторию из Раздела 3, которая полностью бесплатна.

### 2.1. Создание виртуальной машины в Yandex Cloud
1. Перейти на сайт `https://yandex.cloud/` и создать учётную запись.
2. В консоли управления найти сервис **Compute Cloud**.
3. Нажать **«Создать виртуальную машину»** и выбрать режим **«Расширенная настройка»** (в простом режиме доступно меньше опций).
4. **Параметры настройки:**
   - **Дистрибутив:** Ubuntu (рекомендуется LTS-версия, например 24.04).
   - **Вычислительные ресурсы:** Для учебных целей достаточно **20% гарантированной доли vCPU** и **1 ГБ ОЗУ**.
   - **Способ доступа:** **Доступ по OS Login** — привязывается к аккаунту Yandex Cloud, более безопасный и удобный.
5. Нажать **«Создать виртуальную машину»**. Статус изменится с `provisioning` на `running`.

> **Почему 20% гарантированной доли vCPU?** Это минимальная гарантия производительности для учебных целей. При 20% vCPU ты платишь меньше, но не жди, что сервер будет работать быстро — это нормально для обучения. Для боевых задач обычно выбирают 50–100%.

### 2.2. Создание SSH-ключей в Yandex Cloud
При создании ВМ с доступом по OS Login необходимо сгенерировать пару SSH-ключей:
1. На странице свойств ВМ перейти в раздел с инструкцией по подключению.
2. Нажать **«Сгенерировать новый SSH-ключ»**.
3. Будет скачан ZIP-архив, содержащий:
   - Файл с расширением `.pub` — **публичный ключ** (размещается на сервере).
   - Файл без расширения — **приватный ключ** (хранится на клиентской машине).

### 2.3. Подключение через встроенный SSH-клиент (Windows cmd)
```bash
# Вариант 1 (с ключом -l)
ssh -l <username> -i "<путь_к_приватному_ключу>" <IP-адрес_ВМ>

# Вариант 2 (с синтаксисом пользователь@адрес)
ssh <username>@<IP-адрес> -i "<путь_к_ключу>"
```

> **Разбор параметров команды `ssh`:**
> - `ssh` — команда для подключения по протоколу SSH.
> - `-l <username>` — указывает имя пользователя на удалённой машине.
> - `<username>@<IP-адрес>` — альтернативный способ указать пользователя и адрес.
> - `-i "<путь_к_ключу>"` — указывает путь к файлу приватного ключа (путь рекомендуется заключать в кавычки для корректной обработки пробелов).

> **Важно:** При первом подключении SSH-клиент запросит подтверждение: `The authenticity of host ... can't be established. Are you sure you want to continue connecting (yes/no)?` Необходимо ввести `yes` и нажать Enter. После этого ключ сервера будет сохранён, и запрос больше не появится.

### 2.4. Настройка прав доступа к приватному ключу в Windows
При подключении может возникнуть ошибка: `Permissions for 'private-key' are too open`. Это защитный механизм SSH: приватный ключ не должен быть доступен другим пользователям системы.

**Решение:**
1. Найти файл приватного ключа в проводнике.
2. Нажать правой кнопкой мыши → **Свойства** → вкладка **Безопасность**.
3. Нажать **Дополнительно** → **Отключить наследование** → «Преобразовать унаследованные разрешения в явные».
4. Удалить всех пользователей, кроме своей учётной записи.
5. Нажать **ОК** и применить изменения.

> **Почему это работает?**  
> SSH — параноидальный протокол. Он считает, что если файл приватного ключа доступен *хотя бы одному* другому пользователю на компьютере, то ключ скомпрометирован. Команда «Отключить наследование» убирает все разрешения, которые «унаследованы» от папки, а удаление всех пользователей, кроме тебя, гарантирует, что никто другой не сможет даже прочитать этот файл. Это обязательное требование безопасности.

### 2.5. Удаление виртуальной машины (экономия средств)
После завершения работы с VPS **обязательно удалите виртуальную машину**, чтобы не тратить деньги на облачные ресурсы.

**Шаги:**
1. В консоли Yandex Cloud перейдите в раздел **Compute Cloud**.
2. Найдите вашу ВМ в списке.
3. Нажмите на значок меню (три точки) справа от машины → выберите **«Удалить»**.
4. Подтвердите удаление.
5. Статус изменится на `deleting`, затем ВМ исчезнет из списка.

> **Важно:** Остановка ВМ (`Stop`) не отменяет плату за диски и ресурсы. Только **удаление** полностью прекращает расходы.

## 3. Разворачивание локальной лаборатории (Рекомендуемый путь)

Этот раздел описывает создание полноценной серверной лаборатории внутри ноутбука, которая имитирует работу с удалённым VPS без затрат на облачные ресурсы.

### 3.1. Подготовка
- **Хостовая ОС:** Windows с 16+ ГБ ОЗУ.
- **VirtualBox:** Скачать с `https://www.virtualbox.org/`.
- **Образ Ubuntu 24.04 LTS Desktop:** Для клиента (с графикой).
- **Образ Ubuntu 24.04 LTS Server:** Для сервера (без графики).

### 3.2. Создание виртуальной машины «Клиент» (UbuntuLocal)
**Параметры:**
- Имя: `UbuntuLocal`. Тип: `Linux`, Версия: `Ubuntu (64-bit)`.
- ОЗУ: `4096 МБ`. Процессор: `2 ядра`.
- Жёсткий диск: `25 ГБ`, тип `VDI`, динамический.

**Установка и настройка:**
1. В настройках виртуалки перейти в **«Носители»** (Storage), выбрать образ `ubuntu-24.04-desktop-amd64.iso` и установить систему.
2. **Настройка сети:**
   - Выключить виртуалку. Перейти в **«Сеть»** (Network).
   - **Адаптер 1:** `Attached to` = **`Host-only Adapter`**. Name = `VirtualBox Host-Only Ethernet Adapter`.
   - Запустить виртуалку, открыть терминал (`Ctrl+Alt+T`), ввести `ip a` и записать IP (например, `192.168.56.101`).

### 3.3. Создание виртуальной машины «Сервер» (UbuntuServer)
**Параметры:**
- Имя: `UbuntuServer`. Тип: `Linux`, Версия: `Ubuntu (64-bit)`.
- ОЗУ: `1024 МБ`. Процессор: `1 ядро`.
- Жёсткий диск: `10 ГБ`, тип `VDI`, динамический.

**Установка и настройка:**
1. В настройках виртуалки перейти в **«Носители»**, выбрать образ `ubuntu-24.04-live-server-amd64.iso`.
2. На экране `SSH configuration` **обязательно** поставить галочку **`Install OpenSSH server`**.
3. Создать пользователя и пароль (например, `maskedup` / `admin123`).
4. **Настройка сети (адаптер 1 для SSH):**
   - **Адаптер 1:** `Attached to` = **`Host-only Adapter`**. Name = `VirtualBox Host-Only Ethernet Adapter`.
   - Запустить сервер, войти в систему и выполнить `ip a`. Записать IP (например, `192.168.56.102`). **Этот IP нужен для SSH**.
5. **Настройка интернета для сервера (адаптер 2):**
   - **Выключить сервер.** В настройках VirtualBox перейти в **«Сеть»** (Network).
   - Перейти на вкладку **`Адаптер 2`**. Поставить галочку `Включить сетевой адаптер`. `Attached to` = **`NAT`**.
   - **Запустить сервер** и зайти в него (ввести логин и пароль).
   - Узнать имя второго интерфейса. Для этого выполнить:
     ```bash
     ip a
     ```
     Обычно это `enp0s8` или `eth1`. Запомните это имя.
   - Открыть файл конфигурации сети:
     ```bash
     sudo nano /etc/netplan/50-cloud-init.yaml
     ```
   - **Важно!** В YAML-файлах отступы (пробелы) имеют значение. Файл должен выглядеть так (добавьте блок для вашего интерфейса, соблюдая отступы):
     ```yaml
     network:
       version: 2
       ethernets:
         enp0s3:
           dhcp4: true
         enp0s8:
           dhcp4: true
     ```
     *Если вашего интерфейса (например, `enp0s8`) нет в файле — добавьте его, как показано выше.*
   - Сохранить файл: нажать `Ctrl+X`, затем `Y`, затем `Enter`.
   - Применить изменения:
     ```bash
     sudo netplan apply
     ```
   - Проверить интернет:
     ```bash
     ping 8.8.8.8 -c 4
     ```

> **Почему мы редактируем этот файл? (Понимание YAML)**  
> Файл `/etc/netplan/50-cloud-init.yaml` — это «паспорт сети» твоего сервера. В нём прописано, какие сетевые карты есть у сервера и как они должны получать IP-адреса.  
>  
> **Проблема:** Когда ты создаёшь сервер в VirtualBox, он «видит» только адаптер 1 (Host-only). Но ты добавил адаптер 2 (NAT) для выхода в интернет. Без записи в этом файле сервер даже не знает о существовании второго адаптера и не может выйти в интернет.  
>  
> **Что делает YAML-конфигурация:**  
> ```yaml
> network:
>   version: 2                # Новая версия формата
>   ethernets:                # Настраиваем проводные адаптеры
>     enp0s3:                 # Адаптер 1 — для SSH (Host-only)
>       dhcp4: true           # Получить IP автоматически
>     enp0s8:                 # Адаптер 2 — для интернета (NAT)
>       dhcp4: true           # Получить IP автоматически
> ```
> **Простыми словами:** Мы говорим серверу: «У тебя есть две сетевые карты. Первая — для общения с твоим соседом (клиентом), вторая — для выхода в интернет. Включи обе и получи IP-адреса автоматически».

## 4. SSH-подключение с клиента к серверу

### 4.1. Подключение из терминала (UbuntuLocal)
На `UbuntuLocal` открыть терминал и выполнить:
```bash
ssh maskedup@192.168.56.102
```
(Вместо `192.168.56.102` использовать свой IP сервера).

### 4.2. Подключение через MobaXterm (Windows)
**MobaXterm** — графический SSH-клиент для Windows, который предоставляет удобный интерфейс управления сессиями, встроенный файловый менеджер и поддержку X11-Forwarding. Многие пользователи называют MobaXterm «IDE для командной строки» из-за удобного интерфейса, встроенного файлового менеджера и управления сессиями.

**Установка и настройка:**
1. Скачать `MobaXterm Home Edition (Installer)` с `https://mobaxterm.mobatek.net/download.html`.
2. Установить, следуя инструкциям установщика.
3. Запустить программу. В левом верхнем углу нажать кнопку **`Session`**.
4. Выбрать вкладку **`SSH`** и заполнить поля:

> **Альтернатива:** Если у вас нет прав администратора, скачайте **Portable-версию** (ZIP-архив) — она не требует установки, просто распакуйте и запускайте.

| Поле | Значение |
| :--- | :--- |
| **Remote host** | IP-адрес сервера (например, `192.168.56.102`). |
| **Specify username** | Имя пользователя (например, `maskedup`). |
| **Port** | `22` (стандартный порт SSH). |

5. Нажать **`OK`**. Сохранённая сессия появится в левой колонке.
6. **При первом подключении:** подтвердить ключ хоста (`Accept`).
7. **Сохранение пароля:** После успешного входа MobaXterm предложит сохранить пароль. Нажать **`Yes`**.
8. **Создание Master Password:** Придумать локальный пароль для защиты сохранённых сессий в MobaXterm. Это **не пароль от сервера**, а пароль для самой программы. Ввести его в оба поля, оставить выбор `only on new Windows account or new computer` и нажать **`OK`**.

### 4.3. Подключение через PuTTY (Windows)
**PuTTY** — классический SSH-клиент. Особенность: он использует собственный формат приватных ключей `.ppk`. Ключи, скачанные из Yandex Cloud, необходимо сконвертировать через `PuTTYgen`.

> **Примечание:** После конвертации через PuTTYgen не удаляйте оригинальный приватный ключ — он может понадобиться для других клиентов (например, MobaXterm или встроенного SSH).

### 4.4. Проверка подключения
После успешного входа на сервер выполните команды для проверки работоспособности:

```bash
lsb_release -a          # Узнать версию Ubuntu
ping 8.8.8.8 -c 4       # Проверить интернет
sudo apt update         # Обновить списки пакетов (введите пароль)
```

> **Примечание:** При выполнении `sudo apt update` система запросит пароль. Вводите его — звёздочки на экране не отображаются, это нормально.

### 4.5. Завершение сессии
Для выхода из удалённой сессии выполнить:
```bash
exit
```

## 5. Альтернативные сценарии и сравнение подходов

### 5.1. Сравнение способов подключения к удалённому серверу

| Способ | Плюсы | Минусы |
| :--- | :--- | :--- |
| **Встроенный SSH (cmd / PowerShell)** | Не требует установки, работает «из коробки» в Windows 10/11. | Требует настройки прав доступа к ключам, неудобен при работе с несколькими сессиями. |
| **MobaXterm** | Удобный графический интерфейс, сохранение сессий, встроенный файловый менеджер. | Требует установки, бесплатная версия имеет ограничения. |
| **PuTTY** | Классический, лёгкий, работает на старых версиях Windows. | Требует конвертации ключей в формат `.ppk`, устаревший интерфейс. |
| **SecureCRT** | Профессиональный функционал, поддержка многих протоколов. | Платная, избыточна для обучения. |

### 5.2. Когда что использовать

- **Встроенный SSH** — для разовых подключений и быстрых проверок.
- **MobaXterm** — для регулярной работы с несколькими серверами.
- **PuTTY** — для старых систем или если нужен только базовый функционал.
- **SecureCRT** — для профессиональной работы в корпоративной среде.

## 6. Влияние на смежные системы и компоненты

### 6.1. Зависимости
- **Сетевая инфраструктура:** Для SSH-подключений необходима корректная настройка сети (Bridged, NAT, Host-only). Неправильный выбор режима может сделать сервер недоступным.
- **Системные ресурсы:** Работа двух виртуальных машин одновременно требует достаточного объёма ОЗУ и CPU на хосте. Нехватка ресурсов приводит к зависаниям и ошибкам подключения.

### 6.2. Влияние на производительность
- **Нагрузка на CPU и RAM:** Виртуальные машины потребляют ресурсы в реальном времени. Запуск двух ВМ одновременно может снизить производительность хоста.
- **Нагрузка на диск:** Операции с файлами и обновления в гостевых системах создают дополнительную нагрузку на диск хоста.

### 6.3. Влияние на безопасность
- **Поверхность атаки:** Использование SSH-сервера в локальной сети создаёт потенциальную точку входа. Если сервер доступен из интернета (например, через Yandex Cloud), необходимы дополнительные меры защиты.
- **Управление ключами:** Приватные ключи должны храниться строго на клиентской машине. Их компрометация даёт полный доступ к серверу.

## 7. Разбор сложных инженерных ситуаций и аномалий

### 7.1. Ошибка `Permissions for 'private-key' are too open`
**Причина:** SSH требует, чтобы файл приватного ключа был доступен только текущему пользователю системы.  
**Решение:** Ограничить права доступа через свойства файла в Windows (см. раздел 2.4).

### 7.2. Ошибка `Connection timed out` при подключении
**Причина:** Сервер не запущен или сетевой адаптер настроен неправильно.  
**Решение:**
1. Убедиться, что виртуальная машина сервера запущена в VirtualBox.
2. Проверить IP-адрес сервера: внутри сервера выполнить `ip a`.
3. Убедиться, что клиент и сервер находятся в одной подсети (например, `192.168.56.0/24`).

### 7.3. Нет интернета на сервере
**Решение:** Убедиться, что настроен второй сетевой адаптер (NAT) и прописана конфигурация в `/etc/netplan/50-cloud-init.yaml` (см. раздел 3.3, шаг 5).

### 7.4. MobaXterm запрашивает пароль при каждом подключении
**Причина:** Не создан или забыт **Master Password** в MobaXterm.  
**Решение:** При первом сохранении пароля создать Master Password (см. раздел 4.2, шаг 8). Если забыли — удалить сохранённую сессию и создать заново.

## 8. Лимиты, оптимизация и масштабирование

- **Сравнение способов подключения:**

| Способ | Формат ключа | Особенности |
| :--- | :--- | :--- |
| Встроенный SSH (cmd) | Любой (без расширения, `.pem`) | Работает в Windows 10/11, настройка прав доступа обязательна. |
| MobaXterm | Любой (без расширения, `.pem`) | Удобный интерфейс, встроенный файловый менеджер, сохранение сессий. |
| PuTTY | `.ppk` (конвертируется через PuTTYgen) | Классический клиент, требует конвертации ключей. |
| SecureCRT | Любой | Платная профессиональная утилита с расширенными возможностями. |

- **Оптимизация ресурсов:** Для локальной лаборатории рекомендуется выделять серверу минимум 1 ГБ ОЗУ и 1 ядро CPU. Этого достаточно для базового администрирования и изучения SSH.
- **Масштабирование:** Локальная лаборатория легко масштабируется: можно добавлять новые виртуальные машины, поднимать сеть из нескольких серверов и отрабатывать взаимодействие между ними без затрат на облачные ресурсы.

## 9. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)
- **Атаки на SSH:** Подбор паролей (Brute-force), перехват сессии при использовании незашифрованных версий протокола, эксплуатация уязвимостей в старых версиях OpenSSH.
- **Защита:** Отключение входа по паролю (использование только ключей), смена стандартного порта `22`, настройка `fail2ban` для блокировки подозрительных IP-адресов.
- **Компрометация приватного ключа:** Если приватный ключ попадает в руки злоумышленника, он может получить полный доступ к серверу. **Никогда не передавайте приватный ключ третьим лицам.**

### 2. Инженерный FAQ (На основе разбора дискуссий)

- **Вопрос:** *Почему в курсе используется Yandex Cloud, а не локальная лаборатория?*  
  **Технический ответ:** Yandex Cloud (и другие облачные провайдеры) предоставляют реальные серверы с публичными IP-адресами, что максимально приближает обучение к реальным рабочим условиям. Однако локальная лаборатория на VirtualBox является бесплатной альтернативой и позволяет отработать те же навыки SSH и администрирования без затрат.

- **Вопрос:** *Зачем создавать ещё одну ВМ в Yandex Cloud, если уже есть локальная лаборатория?*  
  **Ответ:** Yandex Cloud даёт реальный публичный IP и доступ из интернета, что приближает к рабочим условиям. Локальная лаборатория — бесплатная альтернатива для отработки навыков.

- **Вопрос:** *Почему мы подключаемся из Windows, если установили Linux?*  
  **Ответ:** В реальной работе серверы — это удалённые машины, а клиентом может быть любая ОС (Windows, macOS, Linux). В этом уроке Windows выступает в роли клиента.

- **Вопрос:** *Есть ли дешёвые альтернативы Yandex Cloud?*  
  **Ответ:** Да: Timeweb (от 300 руб/мес), Hosting-russia (от 180 руб/мес), Beget (от 7 руб/сутки). Все они предоставляют VPS/VDS для тестов.

- **Вопрос:** *В чём разница между VPS и виртуальной машиной в VirtualBox?*  
  **Технический ответ:** VPS — это виртуальная машина, работающая на мощном оборудовании в дата-центре, и доступная из интернета. Виртуальная машина в VirtualBox работает на локальном компьютере и доступна только в локальной сети. С точки зрения администрирования и SSH, работа с ними идентична.

- **Вопрос:** *Что делать после завершения работы с VPS?*  
  **Технический ответ:** Виртуальную машину необходимо **удалить** (не просто остановить), чтобы не тратить средства на облачные ресурсы. В Yandex Cloud это делается через консоль управления: нажать на значок меню рядом с ВМ и выбрать «Удалить».

- **Вопрос:** *Что лучше — использовать сторонние SSH-клиенты или встроенный SSH в Windows?*  
  **Технический ответ:** Для разовых подключений достаточно встроенного `cmd` или `PowerShell`. Для регулярной работы (особенно с несколькими серверами) удобнее использовать MobaXterm, так как он сохраняет сессии, имеет встроенный файловый менеджер и упрощает перетаскивание файлов.

- **Вопрос:** *Что такое Master Password в MobaXterm и зачем он нужен?*  
  **Технический ответ:** Master Password — это локальный пароль для самой программы MobaXterm. Он шифрует все сохранённые сессии (включая пароли серверов). Это защищает ваши данные, если кто-то получит доступ к вашему компьютеру. Его нужно ввести один раз при запуске программы, чтобы получить доступ к сохранённым сессиям.

- **Вопрос:** *Какой SSH-клиент лучше для новичка?*  
  **Ответ:** MobaXterm — из-за удобного интерфейса и файлового менеджера. PuTTY — классика, но требует конвертации ключей. Встроенный SSH в Windows — для разовых подключений.

- **Вопрос:** *Что делать, если урок не засчитывается?*  
  **Ответ:** Проверьте, завершён ли урок до конца. Если нет — перезапустите или обратитесь к администратору платформы.

## Заключение

SSH является фундаментальным протоколом для безопасного управления серверами, и его освоение — обязательный шаг для каждого системного администратора. Развёртывание локальной лаборатории на VirtualBox позволяет отработать создание серверного окружения, настройку сети и подключение по SSH без затрат на облачные ресурсы, что делает её идеальной стартовой точкой для обучения. Для реальной работы с публичными IP-адресами и интернет-доступом можно использовать облачные VPS, однако важно помнить о своевременном удалении ресурсов для экономии средств.
