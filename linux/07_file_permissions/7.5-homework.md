## 2. Пошаговые задачи

### Часть 1: Экспресс-аудит и срочное исправление

1. Создайте файл чертежа и проверьте (выведите на экран) его текущие права.
2. Срочно ограничьте доступ! Сделайте так, чтобы:
   - Владелец (`ivan_tsar`) мог читать и редактировать файл.
   - Группа `developers` могла только читать.
   - Все остальные не имели доступа вообще.
3. Проверьте себя: попробуйте прочитать файл от имени тестировщика Серого Волка (`gray_wolf`). Должно получиться?

---

### Часть 2: Создание защищённой структуры проектов

Василиса Премудрая распорядилась создать специальные папки для проектов.

1. Создайте папки:
   - `/home/projects`
   - `/home/projects/development`
   - `/home/projects/shared`
2. Настройте права:
   - Для `development`: доступ (и максимальный) должны иметь только разработчики (группа `developers`).
   - Для `shared`: читать и писать могут все пользователи.
3. Смените владельца папки `development` на пользователя `ivan_tsar`, а группу — на `developers`.

---

### Часть 3: «Особые поручения» со спецэффектами

1. **Папка для временных файлов:** Создайте `/home/projects/temp`. Настройте специальные права так, чтобы любой пользователь мог создавать в ней файлы, но удалять — только свои собственные.
2. **Секретная команда для Волка:** Серый Волк жалуется, что не может запускать некоторые скрипты тестирования. Создайте файл `quick_test.sh` и настройте его так, чтобы он выполнялся как программа любым пользователем.
3. **Умная маска:** Установите маску прав по умолчанию так, чтобы новые файлы создавались с правами `644`, а папки — с правами `755`.

## 4. Разбор сложных ситуаций и типичных ошибок

### 4.1. Почему для папки `development` нужно именно `770`?

**Вопрос:** *Почему для папки `development` нужно ставить именно `770`, а не `700` или `777`?*

**Ответ:** Права `770` (`rwxrwx---`) означают:
- Владелец (`ivan_tsar`) — полный доступ (`rwx`).
- Группа (`developers`) — полный доступ (`rwx`).
- Остальные — нет доступа (`---`).

Это обеспечивает доступ только для разработчиков, но не для посторонних.

> **Важное замечание:** Для папок обязательно нужен `x` (исполнение), чтобы можно было зайти в папку (`cd`). Право `r` (чтение) позволяет только просматривать список файлов через `ls`, но без `x` вы не сможете получить доступ к содержимому папки. Без `x` даже `ls -l` не сработает корректно.

> **Важное уточнение:** Право `r` (чтение) на папку позволяет выполнить `ls` (показать имена файлов), но без `x` вы не сможете:
> - Выполнить `ls -l` (показать метаданные файлов).
> - Зайти в папку (`cd`).
> - Прочитать содержимое файлов внутри.
> 
> Поэтому для работы с папками всегда нужен полный доступ `rwx`.

> **Почему `ls -l` не работает без `x`?**  
> Право `x` (исполнение) на папку даёт доступ к метаданным файлов внутри. Без `x` система не может прочитать информацию о файлах (размер, права, владельца), поэтому `ls -l` выдаст ошибку. Для просмотра полной информации о файлах нужен полный доступ `rwx`.

---

### 4.2. Зачем нужен Sticky bit на папке `temp`?

**Вопрос:** *Что делает Sticky bit на папке `temp`?*

**Ответ:** Sticky bit (устанавливается через `chmod +t`) защищает файлы внутри директории от удаления пользователями, которые не являются их владельцами. Любой может создать файл, но удалить — только владелец или root.

---

### 4.3. Почему `umask 022` даёт `644` для файлов и `755` для папок?

**Вопрос:** *Как `umask 022` превращает максимальные права в нужные?*

**Ответ:** Это работает так:
- Для файлов: максимальные права `666` (`rw-rw-rw-`). `umask 022` запрещает запись для группы и остальных. Итог: `644` (`rw-r--r--`).
- Для папок: максимальные права `777` (`rwxrwxrwx`). `umask 022` запрещает запись для группы и остальных. Итог: `755` (`rwxr-xr-x`).

> **Дополнение:** Для файлов максимальные права всегда `666` (без `x`), поэтому при вычислении прав для файлов нужно учитывать, что `x`-бит не добавляется. Например:
> - Для директорий: `777 − 022 = 755` (`rwxr-xr-x`)
> - Для файлов: `666 − 022 = 644` (`rw-r--r--`)
> 
> **Нюанс:** Если при вычислении прав для файлов получается нечётное число (например, `7`), оно уменьшается на 1 (до `6`), потому что файлы не могут иметь право `x` по умолчанию.

> **Дополнительный пример с `umask`:**
> 
> | `umask` | Для папок (`777 - umask`) | Для файлов (`666 - umask`) |
> | :--- | :--- | :--- |
> | `022` | `755` (`rwxr-xr-x`) | `644` (`rw-r--r--`) |
> | `052` | `725` (`rwx-w-r-x`) | `624` (`rw-rw-r--`) |
> 
> **Нюанс для файлов:** Для файлов максимальные права всегда `666` (без `x`), поэтому при вычислении прав для файлов с `umask 052` получается `624`, а не `725`. Если при вычислении получается нечётное число (например, `7`), оно уменьшается на 1 (до `6`), потому что файлы не создаются с правом на выполнение.

### 4.4. Почему `su gray_wolf` не может прочитать файл?

**Вопрос:** *Почему Серый Волк не может прочитать `secret_blueprint.txt`?*

**Ответ:** Потому что файл имеет права `640` (`rw-r-----`):
- Владелец (`ivan_tsar`) — `rw-` (чтение и запись).
- Группа (`developers`) — `r--` (только чтение).
- Остальные — `---` (нет доступа).

Серый Волк (`gray_wolf`) не является владельцем и не состоит в группе `developers`, поэтому он не может прочитать файл.

### 4.6. Как правильно считать маску?

**Вопрос:** *Как вычислить `umask`, если нужны права `644` для файлов и `755` для папок?*

**Ответ:** Используйте формулу:
```
Маска = Максимальные права − Желаемые права
```
- Для файлов: `666 − 644 = 022`.
- Для папок: `777 − 755 = 022`.

Значит, `umask 022` даёт нужный результат.

**Дополнительно:** Для файлов максимальные права всегда `666` (без `x`), а для папок — `777` (с `x`). Это важно помнить при вычислении.

> **Как правильно считать маску (из комментария Ивана Борисова):**
> 
> **Формула:** `Маска = Максимальные права − Права по умолчанию`
> 
> **Максимальные права:**
> - Для файлов: `666` (`rw-rw-rw-`) — потому что файлы не создаются с правом на выполнение.
> - Для папок: `777` (`rwxrwxrwx`) — папкам нужно право на вход.
> 
> **Пример:** Если нужны права `644` для файлов:
> - `6 − 6 = 0`
> - `6 − 4 = 2`
> - `6 − 4 = 2`
> 
> **Маска = `022`**

### 4.7. Почему `chown` используется для смены и владельца, и группы?

**Вопрос:** *Зачем писать `chown ivan_tsar:developers /home/projects/development`, если можно сначала сменить группу через `chgrp`?*

**Ответ:** `chown ivan_tsar:developers` — это сокращённая запись, которая меняет и владельца, и группу одной командой. Это удобно и безопасно, потому что вы не можете случайно забыть сменить группу. Если вы сначала меняете группу через `chgrp developers`, а потом владельца через `chown ivan_tsar`, это тоже работает, но требует две команды.

**Порядок команд:**

```bash
sudo chown ivan_tsar:developers /home/projects/development
```

Или:

```bash
sudo chgrp developers /home/projects/development
sudo chown ivan_tsar /home/projects/development
```

- **Использование `chmod`:** Основной инструмент для изменения прав доступа.

## 6. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **SUID на скриптах:** Установка SUID на исполняемый скрипт (например, `.sh`) не даёт желаемого эффекта, так как скрипты запускаются интерпретатором. Однако это создаёт ложное впечатление безопасности и может быть использовано злоумышленником для манипуляций, если скрипт редактируем. Всегда проверяйте, что SUID установлен только на бинарные файлы и только при необходимости.

- **Ошибки в правах на директории:** Отсутствие права `x` на папку блокирует не только `cd`, но и доступ к метаданным файлов (`ls -l`). Это может привести к сбоям в работе приложений и скриптов, которые пытаются обращаться к файлам внутри такой директории.

- **Использование `chown` без `sudo`:** Команда `chown` изменяет владельца и требует прав root. Если её выполнить без `sudo`, система выдаст ошибку `Operation not permitted`, что может прервать выполнение скрипта или сценария. Всегда проверяйте наличие `sudo` перед административными операциями.

### 2. Инженерный FAQ (по безопасности)

- **Вопрос:** Как безопасно организовать общую папку для группы разработчиков?  
  **Ответ:** Используйте группу `developers` и права `770` для директории. Владелец — пользователь из группы, группа — `developers`. Это даст полный доступ членам группы и запретит доступ остальным. Для совместной работы внутри группы можно дополнительно установить SGID, чтобы новые файлы наследовали группу папки.

- **Вопрос:** Как правильно установить `umask` для всей системы, а не только для текущей сессии?  
  **Ответ:** Добавьте строку `umask 022` в файл `/etc/profile` (для всех пользователей) или в `~/.bashrc` (для конкретного пользователя). После перезагрузки или нового входа маска будет применяться автоматически.

- **Вопрос:** Что делать, если я случайно поставил права `777` на важный файл?  
  **Ответ:** Немедленно ограничьте права до минимально необходимых. Например, `chmod 640 file` (владелец — чтение/запись, группа — чтение, остальные — ничего). Также проверьте владельца и группу через `ls -l`.

- **Вопрос:** Как проверить, какие файлы в системе имеют установленный SUID-бит?  
  **Ответ:** Выполните `find / -perm -4000 2>/dev/null`. Это покажет все файлы с SUID. Регулярно просматривайте список на предмет неизвестных или подозрительных файлов.

- **Вопрос:** Можно ли установить разные `umask` для файлов и папок?  
  **Ответ:** Стандартно `umask` применяется одинаково ко всем создаваемым объектам. Однако существуют расширенные механизмы (например, default ACL), которые позволяют задать различные права по умолчанию для файлов и директорий, но они выходят за рамки базового курса. В простых случаях достаточно одной маски.
