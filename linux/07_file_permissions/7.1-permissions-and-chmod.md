# Тема 7.1: Вывод информации о правах доступа и команда `chmod`

В данной теме рассматриваются права доступа к файлам и директориям в Linux: структура вывода команды `ls -l`, значение символов `rwx`, а также команда `chmod` для изменения прав доступа. Разбираются два способа задания прав: буквенный (символьный) и цифровой (восьмеричный), а также рекурсивное изменение прав для директорий.

---

## 1. Вывод информации о правах доступа — Базовые свойства

- **Контекст/Уровень:** Системное администрирование / Управление файловой системой.
- **Основное назначение:** Получение информации о правах доступа к файлам и директориям.
- **Принцип работы:** Команда `ls -l` (или её псевдоним `ll`) выводит таблицу с подробной информацией о файлах и директориях, включая права доступа, владельца, группу и размер.

### 1.1. Структура вывода `ls -l`

Пример вывода:
```
-rw-r--r-- 1 itguy itguy 12345 Mar 26 10:00 important.txt
```

| Поле | Описание |
| :--- | :--- |
| 1 | Права доступа (10 символов) |
| 2 | Количество жёстких ссылок |
| 3 | Владелец файла (owner) |
| 4 | Группа-владелец (group) |
| 5 | Размер файла в байтах |
| 6–8 | Дата и время последней модификации |
| 9 | Имя файла или директории |
*Таб. 1. Поля вывода команды `ls -l`.*

> **Примечание о псевдониме `ll`:** `ll` — это не отдельная команда, а псевдоним (alias), который обычно определён в `~/.bashrc`. Он может быть настроен как `ls -alF` или `ls -la`. В разных дистрибутивах поведение `ll` может отличаться, так как псевдоним задаётся пользователем индивидуально.

## 2. Права доступа (первая колонка)

Первая колонка состоит из 10 символов.

### 2.1. Первый символ — тип файла

| Символ | Тип файла |
| :--- | :--- |
| `-` | Обычный файл |
| `d` | Директория (directory) |
| `l` | Символическая ссылка (link) |
| `c` | Символьное устройство (character device) |
| `b` | Блочное устройство (block device) |
| `s` | Сокет (socket) |
| `p` | Именованный канал (pipe) |
*Таб. 2. Типы файлов в Linux.*

### 2.2. Остальные 9 символов — три тройки `rwx`

| Позиции | Категория |
| :--- | :--- |
| 2–4 | Права владельца (user) |
| 5–7 | Права группы-владельца (group) |
| 8–10 | Права остальных пользователей (others) |
*Таб. 3. Категории пользователей в правах доступа.*

### 2.3. Значение букв `rwx`

| Буква | Название | Для файла | Для директории |
| :--- | :--- | :--- | :--- |
| `r` | read (чтение) | Просмотр содержимого файла | Просмотр списка файлов в директории (`ls`) |
| `w` | write (запись) | Изменение содержимого файла | Создание, удаление, переименование файлов внутри |
| `x` | execute (исполнение) | Запуск файла как программы/скрипта | Вход в директорию (`cd`) и доступ к атрибутам |
*Таб. 4. Значение символов `rwx`.*

> **Важное замечание о праве `x` на директорию:** Для доступа к файлам внутри директории необходимо иметь право `x` на саму директорию. Без него вы не сможете войти в директорию (`cd`), даже если у вас есть право `r`. Более того, право `x` на директорию требуется для доступа к атрибутам файлов внутри неё. Без права `x` вы не сможете получить доступ к объектам внутри директории, даже если знаете их полный путь.

**Пояснение на примере:**

| Права на директорию     | Что можно делать                                                                                                                                  |
| :---------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------ |
| `r` (только чтение)     | Просмотреть список файлов (`ls`), но нельзя войти (`cd`) и прочитать файлы                                                                        |
| `x` (только исполнение) | Можно войти (`cd`), но нельзя просмотреть список файлов (`ls`); однако если знать точное имя файла, его можно прочитать (при наличии `r` на файл) |
| `rwx` (полные права)    | Можно и просмотреть список, и войти, и читать/изменять файлы                                                                                      |
*Таб. 4.1. Поведение прав на директорию.*

## 3. Изменение прав доступа — `chmod`

Команда `chmod` (change mode) используется для изменения права доступа к файлам и директориям.

### 3.1. Синтаксис

```bash
chmod [опции] [права] [файл/директория]
```

---

## 4. Буквенный (символьный) синтаксис

### 4.1. Категории пользователей

| Символ | Категория |
| :--- | :--- |
| `u` | user — владелец файла |
| `g` | group — группа-владелец |
| `o` | others — все остальные |
| `a` | all — все категории (`u` + `g` + `o`) |
*Таб. 5. Категории пользователей для буквенного синтаксиса.*

### 4.2. Операции

| Оператор | Значение |
| :--- | :--- |
| `+` | Добавить право |
| `-` | Удалить право |
| `=` | Установить право (остальные сбрасываются) |
*Таб. 6. Операторы для буквенного синтаксиса.*

### 4.3. Примеры буквенного синтаксиса

```bash
# Добавить право на запись для остальных
chmod o+w important.txt

# Удалить права на чтение и запись для группы и остальных
chmod go-rw important.txt

# Добавить права для группы и остальных разными операциями
chmod g+w,o+r *

# Установить для владельца все права, для группы — чтение и запись, для остальных — только чтение
chmod u=rwx,g=rw,o=r i*

# Установить одинаковые права для всех категорий
chmod a=rw important.txt
```

> **Примечание о шаблонах:** `*` означает «все файлы в текущей директории», `i*` означает «все файлы, начинающиеся на `i`». Это работает точно так же, как в команде `ls`.

## 5. Цифровой (восьмеричный) синтаксис

### 5.1. Принцип перевода

Каждая тройка `rwx` представляется в виде трёх битов (1 — право есть, 0 — права нет), которые затем переводятся в восьмеричное число.

| Бинарное | Восьмеричное | Права |
| :--- | :--- | :--- |
| `000` | `0` | `---` |
| `001` | `1` | `--x` |
| `010` | `2` | `-w-` |
| `011` | `3` | `-wx` |
| `100` | `4` | `r--` |
| `101` | `5` | `r-x` |
| `110` | `6` | `rw-` |
| `111` | `7` | `rwx` |
*Таб. 7. Соответствие битовых масок и восьмеричных чисел.*

> **Практический совет:** Запоминать таблицу не обязательно. Достаточно помнить, что `r = 4`, `w = 2`, `x = 1`, и складывать их для получения нужного числа. Например:
> - `rwx` = 4+2+1 = `7`
> - `rw-` = 4+2+0 = `6`
> - `r--` = 4+0+0 = `4`

### 5.2. Синтаксис

```bash
chmod 764 important.txt
```

- Первая цифра (`7`) — права владельца: `rwx`
- Вторая цифра (`6`) — права группы: `rw-`
- Третья цифра (`4`) — права остальных: `r--`

### 5.3. Часто используемые комбинации

| Цифры | Права | Описание |
| :--- | :--- | :--- |
| `755` | `rwxr-xr-x` | Стандартные права для исполняемых файлов и директорий |
| `644` | `rw-r--r--` | Стандартные права для текстовых файлов |
| `600` | `rw-------` | Только владелец может читать и писать (приватные файлы) |
| `700` | `rwx------` | Только владелец имеет полный доступ |
| `777` | `rwxrwxrwx` | Полный доступ для всех (не рекомендуется) |
*Таб. 8. Часто используемые комбинации прав.*

> **Важное замечание о директориях и файлах:** Для директорий обычно используются права `755` или `750`, так как им обязательно нужно право `x` для входа. Для обычных файлов чаще применяются `644` или `664`. Если случайно задать директории права `644`, вы не сможете в неё войти, даже если у вас есть право `r`.

## 6. Изменение прав для директорий

### 6.1. Только директория

```bash
chmod 764 .          # изменить права на текущую директорию (точка)
chmod 755 /path/dir  # изменить права на указанную директорию
```

### 6.2. Рекурсивное изменение — `-R`

```bash
chmod -R 755 folder/
```

Ключ `-R` (recursive) применяет права ко всем файлам и поддиректориям внутри указанной директории.

> **Важно:** При рекурсивном изменении права применяются как к самой директории, так и ко всем вложенным объектам. Это может быть нежелательно, если вы хотите изменить права только на директорию, но не на её содержимое.

## 7. Практические примеры

### 7.1. Создание тестового файла и просмотр прав

```bash
touch important.txt
ls -l important.txt
# -rw-r--r-- 1 itguy itguy 0 Mar 26 10:00 important.txt
```

### 7.2. Добавление права на запись для остальных

```bash
chmod o+w important.txt
ls -l important.txt
# -rw-r--rw- 1 itguy itguy 0 Mar 26 10:00 important.txt
```

### 7.3. Удаление прав у группы и остальных

```bash
chmod go-rw important.txt
ls -l important.txt
# -rw------- 1 itguy itguy 0 Mar 26 10:00 important.txt
```

### 7.4. Установка прав цифровым способом

```bash
chmod 764 important.txt
ls -l important.txt
# -rwxrw-r-- 1 itguy itguy 0 Mar 26 10:00 important.txt
```

- Владелец: `7` = `rwx`  
- Группа: `6` = `rw-`  
- Остальные: `4` = `r--`

### 7.5. Установка прав для всех файлов в папке

```bash
chmod a=rw *           # все файлы в текущей папке: rw-rw-rw-
chmod 644 *            # все файлы: rw-r--r--
```

### 7.6. Рекурсивное изменение прав для директории

```bash
mkdir testdir
touch testdir/file1 testdir/file2
chmod -R 700 testdir/
ls -l testdir/
# оба файла получат права rwx------
```

## 8. Разбор сложных ситуаций и типичных вопросов

### 8.1. Почему `ll` может работать по-разному?

**Вопрос:** *В разных дистрибутивах команда `ll` даёт разный вывод. Почему?*

**Ответ:** `ll` — это не отдельная команда, а псевдоним (alias), который пользователь настраивает сам. Обычно он определён в `~/.bashrc` и может быть настроен как `ls -alF`, `ls -la` или даже как `systemctl`. В разных дистрибутивах и у разных пользователей он может отличаться.

### 8.2. Зачем директории нужно право `x`?

**Вопрос:** *Почему для директории нужно право `x`, а не только `r` и `w`?*

**Ответ:** Право `x` на директорию позволяет войти в неё (`cd`) и получить доступ к атрибутам файлов внутри. Без `x` вы не сможете зайти в директорию, даже если у вас есть `r`. Право `r` позволяет только просматривать список файлов, но не даёт доступа к их содержимому.

**Пример:**
- Если у директории есть `r`, но нет `x`: `ls` покажет список файлов, но `cd` выдаст ошибку `Permission denied`.
- Если есть `x`, но нет `r`: можно войти (`cd`), но нельзя посмотреть список (`ls`). Однако если знать точное имя файла, его можно прочитать (при наличии `r` на сам файл).

### 8.3. Какая разница между `chmod 664 -R` и `chmod 755 -R`?

**Вопрос:** *Почему после `chmod 664 -R .` я не могу зайти в папку?*

**Ответ:** Право `x` на директорию кодируется числом `1` (в восьмеричной системе). Число `6` (`rw-`) не включает `x`, поэтому директория теряет возможность входа. Для директорий используйте `755` (`rwxr-xr-x`) или `750` (`rwxr-x---`).

### 8.4. Буквенный vs цифровой синтаксис: что лучше?

**Вопрос:** *Какой способ задания прав лучше — буквенный или цифровой?*

**Ответ:** Оба способа имеют свои преимущества:
- **Буквенный** — более гибкий и интуитивно понятный. Позволяет добавлять или удалять конкретные права, не изменяя остальные.
- **Цифровой** — более компактный и быстрый, особенно при использовании часто встречающихся комбинаций (например, `755`, `644`).

Выбор зависит от личных предпочтений и конкретной задачи.

## 9. Лимиты, оптимизация и масштабирование

- **Права доступа:** В Linux каждый файл и директория имеют права для владельца, группы и остальных. Это основа безопасности системы.
- **Рекурсивное изменение:** Использование `-R` требует осторожности, так как изменения применяются ко всем вложенным объектам.
- **Право `x` для директорий:** Обязательно для доступа к содержимому директории. Без него даже `ls` не сможет получить атрибуты файлов.

## 10. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Неправильные права:** Слишком широкие права (например, `777`) могут дать доступ к файлам неавторизованным пользователям.
- **Ошибка в правах на директорию:** Отсутствие `x` на директорию блокирует доступ к её содержимому, что может привести к сбоям в работе приложений.
- **Рекурсивное изменение:** Неосмотрительное использование `chmod -R` может случайно изменить права на системные файлы, что приведёт к нестабильности системы.

### 2. Инженерный FAQ

- **Вопрос:** *Как посмотреть права в цифровом формате?*  
  **Ответ:** Команда `stat -c "%a %n" file` показывает права в восьмеричном формате.

- **Вопрос:** *Можно ли задать права только на директорию, не меняя файлы внутри?*  
  **Ответ:** Да, для этого нужно выполнить `chmod` без ключа `-R`. Права изменятся только на саму директорию.

- **Вопрос:** *Что означают права `066` и `111`?*  
  **Ответ:** Это нестандартные комбинации, которые технически допустимы, но редко используются на практике. Linux позволяет задавать любые права, потому что система доверяет администратору и не ограничивает его в выборе.

## 11. Итоговая шпаргалка по командам

| Тема | Команды / Понятия |
| :--- | :--- |
| Просмотр прав | `ls -l`, `ll` |
| Структура прав | Тип файла + три тройки `rwx` |
| Значение `rwx` | Чтение, запись, исполнение (для файлов и директорий) |
| Буквенный синтаксис `chmod` | `u`, `g`, `o`, `a`; `+`, `-`, `=`; `r`, `w`, `x` |
| Цифровой синтаксис `chmod` | Цифры 0–7 (восьмеричная система) |
| Рекурсивное изменение | `chmod -R` |
*Таб. 9. Итоговая шпаргалка по правам доступа и командам chmod.*

### Ключевые понятия:

- **Владелец (user)** — пользователь, создавший файл.
- **Группа (group)** — группа, связанная с файлом.
- **Остальные (others)** — все остальные пользователи системы.
- `rwx` — чтение, запись, исполнение.
- Для доступа к содержимому директории необходимо право `x` на неё.
- Цифровой способ основан на битовом представлении прав: `r=4`, `w=2`, `x=1`, сумма даёт цифру от 0 до 7.

## Заключение

В этой теме были рассмотрены права доступа к файлам и директориям в Linux: структура вывода `ls -l`, значение символов `rwx` и команда `chmod` для изменения прав. Понимание различий между правами на файлы и директории, а также умение использовать буквенный и цифровой синтаксисы являются базовыми навыками для управления доступом в Linux.
