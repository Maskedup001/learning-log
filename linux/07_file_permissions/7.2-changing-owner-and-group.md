# Тема 7.2: Смена владельцев и групп

В данной теме рассматриваются команды для изменения владельца и группы-владельца файлов и директорий: `chown` (change owner) и `chgrp` (change group). Разбираются синтаксис, варианты использования, рекурсивное применение, а также сравнение этих команд и практические примеры.

---

## 1. Смена владельца и группы — `chown`

Команда `chown` (change owner) используется для изменения владельца и/или группы-владельца файлов и директорий. Это **административная команда**, требующая прав root (выполняется с `sudo`).

- **Контекст/Уровень:** Системное администрирование / Управление файловой системой.
- **Основное назначение:** Изменение владельца и/или группы-владельца файлов и директорий.
- **Принцип работы:** `chown` (change owner) изменяет записи в метаданных файла (inode). Это административная команда, требующая прав root (выполняется с `sudo`).

### 1.1. Базовый синтаксис

```bash
sudo chown [опции] [владелец][:группа] файл
```

### 1.2. Варианты использования

| Синтаксис | Действие |
| :--- | :--- |
| `chown username file` | Изменить только владельца. |
| `chown :groupname file` | Изменить только группу-владельца. |
| `chown username:groupname file` | Изменить одновременно владельца и группу. |
| `chown username: file` | Изменить владельца, группа устанавливается как основная группа пользователя. |
*Таб. 1. Варианты использования команды `chown`.*

### 1.3. Примеры

**Смена только владельца:**
```bash
sudo chown outgoinghr anotherfile
```
После выполнения владельцем файла `anotherfile` станет пользователь `outgoinghr`.

**Смена только группы:**
```bash
sudo chown :remoteworkers important.txt
```
Группа-владелец файла `important.txt` меняется на `remoteworkers`.

**Смена владельца и группы одновременно:**
```bash
sudo chown salesguy:remoteworkers onemorefile
```
Владелец — `salesguy`, группа-владелец — `remoteworkers`.

**Смена группы у всех файлов в текущей папке:**
```bash
sudo chown :itguy *
```
Символ `*` (звёздочка) обозначает все файлы в текущей директории.

---

## 2. Рекурсивная смена владельца — `-R`

Ключ `-R` (recursive) применяет изменения ко всем файлам и поддиректориям внутри указанной директории.

### 2.1. Синтаксис

```bash
sudo chown -R username:groupname directory/
```

### 2.2. Пример

```bash
sudo chown -R outgoinghr:remoteworkers ./
```

Меняет владельца и группу для текущей директории (`.`) и **всех** вложенных в неё файлов и папок.

### 2.3. Важное предостережение

Если изменить владельца текущей директории на другого пользователя, можно потерять возможность просматривать её содержимое без `sudo`. Однако root всегда имеет доступ к любым файлам независимо от прав.

**Пример проблемы:**
```bash
sudo chown outgoinghr:remoteworkers .     # владелец текущей папки изменён
ls .                                      # ошибка: Permission denied
sudo ls .                                 # работает (с правами root)
```

**Для восстановления доступа** можно вернуть права владельцу или выставить права `777`:
```bash
sudo chmod 777 .                         # временное решение (не рекомендуется)
sudo chown itguy:itguy .                 # вернуть владельца
```

> **Важное замечание о праве `r` на директорию:** Даже если у пользователя есть право `r` (чтение) на директорию, он не может в неё войти без права `x` (исполнение). Право `r` позволяет только просматривать список файлов (`ls`), но не даёт доступа к содержимому директории или входа в неё (`cd`). Именно поэтому после смены владельца пользователь не может зайти в директорию, пока не будут настроены соответствующие права.

> **Почему `777` — это плохо:** Права `777` (`rwxrwxrwx`) дают полный доступ любому пользователю в системе. Это означает, что любой может удалить, перезаписать или выполнить ваш файл. На продакшен-серверах это категорически недопустимо. Даже на тестовой машине стоит избегать `777`, так как ошибка может привести к неприятным последствиям.

## 3. Смена только группы — `chgrp`

Команда `chgrp` (change group) предназначена исключительно для смены группы-владельца. Это также административная команда.

### 3.1. Базовый синтаксис

```bash
sudo chgrp [опции] groupname file
```

### 3.2. Примеры

**Смена группы для одного файла:**
```bash
sudo chgrp remoteworkers somedoc.txt
```

**Смена группы для текущей директории:**
```bash
sudo chgrp officeworkers .
```

**Рекурсивная смена группы для директории и всех вложенных объектов:**
```bash
sudo chgrp -R officeworkers ./
```

---

## 4. Сравнение `chown` и `chgrp`

| Команда | Назначение | Особенности |
| :--- | :--- | :--- |
| `chown` | Смена владельца и/или группы | Может менять и то, и другое одной командой. |
| `chgrp` | Смена только группы | Специализированная команда, не меняет владельца. |
*Таб. 2. Сравнение `chown` и `chgrp`.*

> **Исторический контекст:** Исторически команды `chown` и `chgrp` были разделены. В первых версиях Unix не было групп, и `chown` меняла только владельца. Позже, когда появились группы, для их изменения создали отдельную команду `chgrp`. Со временем `chown` научилась работать и с группами, но `chgrp` осталась для совместимости и специализированных задач.

**Важное отличие:** Обе команды требуют прав root (`sudo`). Однако `chgrp` может выполняться владельцем файла, если он состоит в группе, которой хочет передать права на файл.

## 5. Практические примеры

### 5.1. Подготовка тестовой среды

```bash
# Создать группу (если не существует)
sudo groupadd remoteworkers

# Добавить пользователей в группу
sudo usermod -a -G remoteworkers itguy
sudo usermod -a -G remoteworkers outgoinghr

# Проверить
grep remoteworkers /etc/group
# remoteworkers:x:1006:itguy,outgoinghr
```

### 5.2. Смена владельца файла

```bash
sudo chown outgoinghr important.txt
ls -l important.txt
# -rw-r--r-- 1 outgoinghr itguy 0 Mar 26 10:00 important.txt
```

### 5.3. Смена группы файла

```bash
sudo chown :remoteworkers important.txt
ls -l important.txt
# -rw-r--r-- 1 outgoinghr remoteworkers 0 Mar 26 10:00 important.txt
```

### 5.4. Смена владельца и группы одновременно

```bash
sudo chown salesguy:remoteworkers onemorefile
```

### 5.5. Смена группы у всех файлов в папке

```bash
sudo chgrp itguy *
```

### 5.6. Рекурсивная смена группы для директории

```bash
sudo chgrp -R officeworkers ./
ls -l    # все файлы внутри получат группу officeworkers
```

## 6. Разбор сложных ситуаций и типичных вопросов

### 6.1. Чем `chown` отличается от `chgrp`?

**Вопрос:** *Команды `chown` и `chgrp` ничем не отличаются?*

**Ответ:** Нет, они отличаются по назначению:
- `chown` может менять и владельца, и группу (раздельно или вместе).
- `chgrp` меняет только группу.

Кроме того, `chgrp` может выполняться владельцем файла, если он состоит в группе, которой хочет передать права на файл, в то время как `chown` всегда требует `sudo`.

### 6.2. Почему после смены владельца директории я не могу в неё зайти?

**Вопрос:** *Я сменил владельца директории на другого пользователя, но теперь не могу в неё зайти. Почему?*

**Ответ:** Даже если у вас есть право `r` на директорию, вам нужно право `x` для входа (`cd`) и доступа к атрибутам файлов. Право `r` позволяет только просматривать список файлов (`ls`), но не даёт доступа к их содержимому. Для восстановления доступа либо верните владельца обратно, либо настройте права `rwx` (например, `chmod 755 .`).

### 6.3. Почему `chown` может менять и владельца, и группу, если исторически это были разные команды?

**Вопрос:** *Зачем нужна `chgrp`, если `chown` умеет менять группу?*

**Ответ:** Исторически `chown` и `chgrp` были разными командами, потому что в ранних версиях Unix не было групп. Когда группы появились, для их изменения создали `chgrp`. Со временем `chown` расширили, и она научилась менять и группы, но `chgrp` осталась для совместимости. В современных системах `chgrp` используется реже, но она всё ещё полезна, когда нужно изменить только группу, не трогая владельца.

### 6.4. Исторический контекст: почему существуют и `chown`, и `chgrp`

**Вопрос:** *Зачем нужна команда `chgrp`, если `chown` уже умеет менять группу?*

**Ответ:** Это хороший вопрос, который показывает, как эволюционировал Linux (и Unix в целом).

**1. Начало: в Unix не было групп (1969–1971)**
В самой первой редакции Unix понятия «групп пользователей» не существовало. Система была маленькой, экспериментальной, и все доверяли друг другу. У каждого файла был только один создатель — владелец. Чтобы передать файл другому, Кен Томпсон создал команду `chown` (change owner). Она была максимально простой: брала имя нового пользователя и перезаписывала ID владельца в метаданных файла (inode).

**2. Появление групп и `chgrp` (1973–1975)**
Когда Unix стала использоваться в корпорациях, появилась необходимость разделять доступ между разными отделами. Так появилась концепция групп. Теперь у каждого файла было два ярлыка безопасности:
- конкретный пользователь-владелец;
- группа (например, `developers`, `accounting`).

Для управления этим вторым ярлыком создали отдельную команду — `chgrp` (change group). Разработчики Unix следовали философии: «одна программа делает одну задачу». Поэтому `chown` меняла только владельца, а `chgrp` — только группу.

**3. Слияние: почему `chown` теперь умеет менять и группу (конец 1980-х)**
Системные администраторы устали запускать две команды подряд:

```bash
chown ivan file.txt
chgrp managers file.txt
```

В Unix-сообществе началось движение за упрощение. В итоге `chown` научили распознавать двоеточие. Теперь команда `chown ivan:managers file.txt` меняла и владельца, и группу одной строкой.

**Так почему же `chgrp` всё ещё существует?**  
`chgrp` осталась для обратной совместимости, а также для случаев, когда нужно изменить только группу, не трогая владельца. В современной работе она используется реже, но она не является полностью устаревшей.

### 6.5. Что произойдёт, если сменить владельца файла, который запущен?

**Вопрос:** *Я сменил владельца запущенной программы. Что будет?*

**Ответ:** Ничего страшного не произойдёт. Права доступа проверяются только при открытии файла. Если программа уже запущена, она продолжит работать, даже если владелец изменился.

### 6.6. Можно ли одновременно сменить владельца у нескольких файлов?

**Вопрос:** *Как сменить владельца у нескольких файлов за одну команду?*

**Ответ:** Да, это можно сделать через пробел:

```bash
sudo chown username file1 file2 file3
```

### 6.7. Альтернативные способы проверки владельца и группы

**Вопрос:** *Как быстро проверить владельца и группу файла без `ls -l`?*

**Ответ:** Используйте команду `stat`. Она выводит подробную информацию о файле, включая владельца и группу.

```bash
stat -c "%U %G" important.txt
```

**Пример вывода:**
```
outgoinghr remoteworkers
```

**Другие полезные способы:**
- `ls -n` — показывает UID и GID вместо имён.
- `find . -user username` — найти все файлы, принадлежащие пользователю.
- `find . -group groupname` — найти все файлы, принадлежащие группе.

## 7. Лимиты, оптимизация и масштабирование

- **Обе команды требуют `sudo`:** Смена владельца и группы — административные операции, требующие прав root.
- **Рекурсивное изменение (`-R`):** Применяется ко всем вложенным объектам. Требует осторожности, так как может изменить права на большое количество файлов.
- **Право `x` на директорию:** Для доступа к содержимому директории обязательно наличие права `x` на неё.

## 8. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Потеря доступа:** Неправильная смена владельца директории может привести к потере доступа к ней для обычных пользователей.
- **Случайная смена прав:** Рекурсивное изменение (`-R`) без проверки может изменить права на системные файлы, что приведёт к нестабильности системы.
- **Смена владельца без `sudo`:** Обычные пользователи не могут менять владельца файлов — это ограничивает несанкционированный доступ.

### 2. Инженерный FAQ

- **Вопрос:** *Можно ли сменить владельца без `sudo`?*  
  **Ответ:** Нет, `chown` всегда требует прав root. Если вы не являетесь root, используйте `sudo`.

- **Вопрос:** *Что делать, если я случайно сменил владельца корневой директории?*  
  **Ответ:** Немедленно верните владельца обратно с помощью `sudo chown root:root /`. Если вы потеряли доступ, используйте live USB или recovery mode для восстановления.

- **Вопрос:** *Можно ли сменить группу через `chown`?*  
  **Ответ:** Да, через синтаксис `chown :groupname file`.

- **Вопрос:** *Может ли кто-то сменить владельца без `sudo`?*  
  **Ответ:** Да — если вы уже root. Но это тавтология. Обычный пользователь — нет.

## 9. Итоговая шпаргалка по командам

| Команда | Назначение | Ключи |
| :--- | :--- | :--- |
| `sudo chown username file` | Сменить владельца | `-R` (рекурсивно) |
| `sudo chown :groupname file` | Сменить группу | `-R` |
| `sudo chown username:groupname file` | Сменить владельца и группу | `-R` |
| `sudo chgrp groupname file` | Сменить только группу | `-R` |
*Таб. 3. Итоговая шпаргалка по командам.*

### Ключевые понятия:

- Обе команды требуют прав root (`sudo`).
- Ключ `-R` (recursive) применяет изменения ко всем вложенным файлам и папкам.
- При смене владельца текущей директории можно потерять доступ к ней (но root всегда имеет доступ).
- `chown` универсальнее, `chgrp` специализируется только на группах.

## Заключение

В этой теме были рассмотрены команды для смены владельца и группы-владельца файлов и директорий: `chown` и `chgrp`. Обе команды требуют прав root и могут применяться рекурсивно. Важно понимать различия между ними и помнить, что смена владельца директории может привести к потере доступа, если не настроены соответствующие права.
