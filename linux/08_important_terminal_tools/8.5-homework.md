# Тема 8.5: Домашнее задание — Архивные хроники Трёх Топоров

В данной теме представлено практическое домашнее задание по работе со ссылками, потоками ввода-вывода и конвейерами в Linux. Задание разбито на три части: создание жёстких и символических ссылок, анализ системы с помощью потоков и конвейеров, а также анализ текста и создание резервной копии.

---

## 1. Условие задания

Вам предстоит написать несколько команд в терминале для выполнения заданий. Затем вы сможете проверить результаты и сравнить свои команды с ответами.

**Примечание:** Ваш ответ может отличаться от приведённого в качестве эталона и при этом также являться верным. Это нормальная ситуация в программировании, когда одну задачу можно решить разными способами.

### Архивные хроники Трёх Топоров

Василиса Премудрая обнаружила, что файлы в компании хранятся хаотично! Нужно навести порядок в архивных записях и настроить систему мониторинга.

---

## 2. Пошаговые задачи

### Часть 1: Магия ссылок

1. Создайте важный файл с паролями от серверов:

   ```bash
   echo "Пароль от главного сервера: МолодильноеЯблоко123" > secret_passwords.txt
   ```

2. Создайте жёсткую ссылку на этот файл в папке `/home/projects/backups/` (папку нужно создать).
3. Создайте символическую ссылку на этот файл на рабочем столе Ивана Царевича (в его домашней папке).
4. Проверьте iNodes всех трёх объектов — убедитесь, что у файла и жёсткой ссылки одинаковые номера!

---

### Часть 2: Потоки и пользователи

1. Серый Волк наконец-то написал свои тестовые скрипты, но забыл, куда сохранил их! Найдите все `.sh` файлы в системе и сохраните список в `all_scripts.txt`, а все ошибки доступа — в `access_errors.log`.
2. Создайте файл отчёта о работе системы, записав в него:
   - Дату и время создания отчёта.
   - Список всех пользователей системы.
   - Информацию о текущем пользователе (логин, id и список его групп).
3. Кажется, Кощей пытался взломать систему! Проверьте, кто сейчас в системе, и сохраните информацию о вошедших пользователях в файл `logged_in_users.txt`.

---

### Часть 3: Конвейер расследований

1. Иван Царевич случайно удалил важные стихи, которые сочинял для Василисы! Нужно восстановить текст и проанализировать его.
   - Скачайте шекспировские стихи для вдохновения (если файл потерялся с прошлых уроков):
     ```bash
     pandoc -t plain https://shakespeare.mit.edu/romeo_juliet/full.html > romeo_and_juliet_poem.txt
     ```
2. Проанализируйте текст и узнайте:
   - Сколько раз встречается слово `"love"` в поэме?
   - Сколько раз упоминаются семьи `"Montague"` и `"Capulet"`?
   - Какие первые 5 строк упоминают Ромео?
   - Результаты достаточно выводить в окно рабочего терминала.
3. Создайте резервную копию настроек:
   - Создайте папку `backups` и проверьте её существование за одну команду.
   - Если папка существует — скопируйте туда файл с паролями `secret_passwords.txt`.
   - Если нет — создайте папку и выведите сообщение `"Создана новая папка для бэкапов"`.

## 3. Решения

### 3.1. Авторское решение

```bash
# ===== ЧАСТЬ 1: ССЫЛКИ =====

# Создаем файл с паролями
echo "Пароль от главного сервера: МолодильноеЯблоко123" > secret_passwords.txt

# Создаем папку для жесткой ссылки (использовали sudo, т.к. нужны права root)
sudo mkdir -p /home/projects/backups/
sudo chown -R maskedup:maskedup /home/projects/backups/

# Создаем жесткую ссылку в папке backups
sudo ln /home/maskedup/linux_course/secret_passwords.txt /home/projects/backups/hard_copy_secret_passwords

# Создаем символическую ссылку на рабочем столе Ивана Царевича
sudo ln -s /home/maskedup/linux_course/secret_passwords.txt /home/ivan_tsar/Desktop/secret_passwords_symlink.txt

# Проверяем iNodes всех трех объектов
sudo ls -li /home/maskedup/linux_course/secret_passwords.txt /home/projects/backups/hard_copy_secret_passwords /home/ivan_tsar/Desktop/secret_passwords_symlink.txt

# РЕЗУЛЬТАТ:
# 144817 -rw-r--r-- 2 maskedup maskedup 89 Aug 23 23:12 /home/maskedup/linux_course/secret_passwords.txt
# 144817 -rw-r--r-- 2 maskedup maskedup 89 Aug 23 23:12 /home/projects/backups/hard_copy_secret_passwords
# 144196 lrwxrwxrwx 1 ivan_tsar ivan_tsar 48 Aug 23 23:55 /home/ivan_tsar/Desktop/secret_passwords_symlink.txt -> /home/maskedup/linux_course/secret_passwords.txt

# У файла и жесткой ссылки одинаковый iNode (144817), у символической — другой (144196).

# ===== ЧАСТЬ 2: ПОТОКИ И ПОЛЬЗОВАТЕЛИ =====

# 1. Поиск всех .sh файлов
sudo find / -name "*.sh" > all_scripts.txt 2> access_errors.log

# 2. Создание отчета о системе
echo "Дата и время отчета: $(date)" > system_report.txt
echo -e "\nСписок всех пользователей:" >> system_report.txt
cat /etc/passwd | cut -d: -f1 >> system_report.txt
echo -e "\nИнформация о текущем пользователе:" >> system_report.txt
echo "Логин: $(whoami)" >> system_report.txt
echo "ID: $(id)" >> system_report.txt
echo "Группы: $(groups)" >> system_report.txt

# 3. Проверка, кто в системе
who > logged_in_users.txt

# ===== ЧАСТЬ 3: КОНВЕЙЕР РАССЛЕДОВАНИЙ =====

# Скачиваем поэму
pandoc -t plain https://shakespeare.mit.edu/romeo_juliet/full.html > romeo_and_juliet_poem.txt

# Сколько раз встречается слово "love"
grep -o -i "love" romeo_and_juliet_poem.txt | wc -l
# РЕЗУЛЬТАТ: 175

# Сколько раз упоминаются семьи Montague и Capulet
grep -o -i "montague" romeo_and_juliet_poem.txt | wc -l
# РЕЗУЛЬТАТ: 48

grep -o -i "capulet" romeo_and_juliet_poem.txt | wc -l
# РЕЗУЛЬТАТ: 152

# Первые 5 строк, упоминающие Ромео
grep -i "romeo" romeo_and_juliet_poem.txt | head -n 5
# РЕЗУЛЬТАТ:
# Romeo and Juliet
# Shakespeare homepage | Romeo and Juliet | Entire play
# O, where is Romeo? saw you him to-day?
# Enter ROMEO

# Создание резервной копии
mkdir backups 2>/dev/null && echo "Создана новая папка для бэкапов" && cp secret_passwords.txt backups/ || cp secret_passwords.txt backups/ || echo "Папка уже существует"

# Проверка резервной копии
ls -l backups/
cat backups/secret_passwords.txt
```

> **Важное уточнение:** Команда `sudo chown -R maskedup:maskedup /home/projects/backups/` нужна, чтобы **изменить владельца** папки и всех файлов в ней на пользователя `maskedup`. Без этого шага, если папка создана через `sudo`, её владельцем будет `root`, и пользователь `maskedup` не сможет в неё писать.

### 3.2. Авторское решение (эталон)

```bash
# ===== Часть 1: Магия ссылок =====

# Создаём файл с паролями
echo "Пароль от главного сервера: МолодильноеЯблоко123" > secret_passwords.txt

# Создаём папку для жёсткой ссылки
mkdir -p /home/projects/backups
ln secret_passwords.txt /home/projects/backups/passwords_backup

# Создаём символическую ссылку на рабочем столе Ивана
ln -s $(pwd)/secret_passwords.txt /home/ivan_tsar/secret_passwords_link

# Проверяем iNodes всех объектов
ls -li secret_passwords.txt /home/projects/backups/passwords_backup /home/ivan_tsar/secret_passwords_link

# ===== Часть 2: Потоки и пользователи =====

# Поиск всех .sh файлов с разделением вывода и ошибок
find / -type f -name "*.sh" 1>all_scripts.txt 2>access_errors.log

# Создаём файл отчёта
echo "=== Отчёт о пользователях системы ===" > users_report.txt
date >> users_report.txt
echo -e "\n=== Все пользователи системы ===" >> users_report.txt
cat /etc/passwd | cut -d: -f1 >> users_report.txt
echo -e "\n=== Текущий пользователь ===" >> users_report.txt
echo "Логин: $(whoami)" >> users_report.txt
echo "ID: $(id -u)" >> users_report.txt
echo "Группы: $(groups)" >> users_report.txt

# Проверка вошедших пользователей
who > logged_in_users.txt

# ===== Часть 3: Конвейер расследований =====

# Скачиваем поэму
pandoc -t plain https://shakespeare.mit.edu/romeo_juliet/full.html > romeo_and_juliet_poem.txt

# Анализ текста
echo "Анализ поэмы Шекспира:"
grep -o -i "love" romeo_and_juliet_poem.txt | wc -l
grep -o -i "montague" romeo_and_juliet_poem.txt | wc -l
grep -o -i "capulet" romeo_and_juliet_poem.txt | wc -l

echo "Первые 5 строк о Ромео:"
grep -i "romeo" romeo_and_juliet_poem.txt | head -5

# Создание резервной копии с проверкой
ls -d /home/projects/backups && cp secret_passwords.txt /home/projects/backups/ || (mkdir -p /home/projects/backups && echo "Создана новая папка для бэкапов")
```

> **Важное уточнение:** `$(pwd)` — это **командная подстановка**, которая возвращает текущий рабочий каталог. Это гарантирует, что символическая ссылка будет указывать на **абсолютный путь** к файлу, а не на относительный. Если использовать просто `secret_passwords.txt`, ссылка будет указывать на файл **относительно** домашней директории Ивана, что может привести к ошибке.

### 3.4. Решение с `awk`

```bash
# Часть 1
mkdir -p projects/backups
echo "Пароль от главного сервера: МолодильноеЯблоко123" > secret_passwords.txt
ln secret_passwords.txt projects/backups/secret_pass
sudo ln -s secret_passwords.txt /home/ivan_tsar/secret_pass
ls -i secret_passwords.txt
ls -i projects/backups/secret_pass

# Часть 2
date > report
echo -e "\n" >> report
cat /etc/passwd | awk -F":" '$3 > 999 {print $1}' >> report
echo -e "\n" >> report
id >> report
who > logged_in_users.txt

# Часть 3
pandoc -t plain https://shakespeare.mit.edu/romeo_juliet/full.html > romeo_and_juliet_poem.txt
grep --color=always -io "love" romeo_and_juliet_poem.txt | wc -l
grep --color=always -ioE "Montague|Capulet" romeo_and_juliet_poem.txt | wc -l
cat romeo_and_juliet_poem.txt -n | grep -i "romeo" | head -5 | awk '{print $1}'
mkdir backups && echo "Успешно" || "не успешно"
cp secret_passwords.txt backups || mkdir backups && echo "Создана новая папка для бэкапов"
```

> **Важное уточнение:** `awk -F":"` — задаёт разделитель полей (двоеточие). `$3` — третье поле (UID пользователя). `$3 > 999` — фильтрует только **системных пользователей** (UID > 999), отбрасывая системные службы. `{print $1}` — выводит только первое поле (имя пользователя).

### 3.5. Решение с `getent` и `if`

```bash
# Часть 1
echo "Пароль от главного сервера: МолодильноеЯблоко123" > secret_passwords.txt
mkdir -p /home/projects/backups
ln secret_passwords.txt /home/projects/backups/secret_passwords.txt
ln -s $(pwd)/secret_passwords.txt ~/Desktop/secret_passwords.txt
ls -li secret_passwords.txt /home/projects/backups/secret_passwords.txt ~/Desktop/secret_passwords.txt

# Часть 2
find / -type f -name "*.sh" > all_scripts.txt 2> access_errors.log
{
  date
  echo "=== Все пользователи системы ==="
  getent passwd | cut -d: -f1
  echo "=== Текущий пользователь ==="
  echo "Логин: $(whoami)"
  echo "UID: $(id -u)"
  echo "GID: $(id -g)"
  echo "Группы: $(id -Gn | tr ' ' ', ')"
} > system_report.txt

who > logged_in_users.txt

# Часть 3
pandoc -t plain https://shakespeare.mit.edu/romeo_juliet/full.html > romeo_and_juliet_poem.txt 2>/dev/null || echo "Файл уже был скачан или pandoc недоступен"
grep -o -i -w "love" romeo_and_juliet_poem.txt | wc -l
grep -i -c "Montague" romeo_and_juliet_poem.txt
grep -i -c "Capulet" romeo_and_juliet_poem.txt
grep -i -n "Romeo" romeo_and_juliet_poem.txt | head -5 | cut -d: -f1,2-

mkdir -p backups && cp secret_passwords.txt backups/ || (mkdir backups && echo "Создана новая папка для бэкапов")
```

> **Важное уточнение:** `getent passwd` — команда, которая получает записи из базы данных пользователей (аналогично `cat /etc/passwd`, но работает с любыми источниками аутентификации, включая LDAP и NIS). `cut -d: -f1` — извлекает первое поле (имя пользователя).

### 3.7. Решение с `if` и `else` для резервной копии

```bash
# Часть 1
sudo mkdir -p /home/projects/backups/
echo "Пароль от главного сервера: МолодильноеЯблоко123" > secret_passwords.txt

echo "=== АНАЛИЗ ПОЭМЫ 'РОМЕО И ДЖУЛЬЕТТА' ==="

if [ -d backups ]; then
    cp secret_passwords.txt backups/
    echo "Файл secret_passwords.txt скопирован в папку backups"

    cp secret_passwords.txt backups/

(mkdir ./backups 2>/dev/null && echo "Создана новая папка для бэкапов") || (cp secret_passwords.txt ./backups/ && echo "Файл скопирован")
```

> **Важное уточнение:** В этом решении используется `sudo usermod -d /home/ivan_tsar ivan_tsar` для изменения домашней директории пользователя `ivan_tsar`. Это **спорное решение**, так как меняет настройки пользователя. В обычной практике достаточно создать папку `Desktop` и символическую ссылку в ней, без изменения домашней директории. Но как вариант — решение имеет право на существование.

> **Почему это решение может быть полезно:** Команда `sudo usermod -d` изменяет домашнюю директорию пользователя. Если у `ivan_tsar` не было домашней папки или она была настроена иначе, это решение позволяет гарантировать, что ссылка попадёт в нужное место. Однако **злоупотреблять** такими командами не стоит — они меняют системные настройки.

> **Дополнительно про `grep -io "Montague\|Capulet"`:** В этом решении используется `grep` с ключом `-i` (игнорировать регистр) и `-o` (выводить только совпадения), а также `\|` для поиска **двух** слов одновременно. Это сокращает количество команд: вместо двух `grep` можно использовать один.

## 4. Разбор сложных ситуаций и типичных ошибок

### 4.1. Почему `ln -t` создаёт ссылку без возможности задать имя?

**Вопрос:** *Почему при использовании `ln -t /home/ivan_tsar secret_passwords.txt` ссылка получается с тем же именем, что и исходный файл?*

**Ответ:** Ключ `-t` (target directory) указывает **только директорию**, куда будет помещена ссылка, но **не позволяет задать имя ссылки**. Чтобы задать имя, нужно указывать полный путь к ссылке:
```bash
ln -s $(pwd)/secret_passwords.txt /home/ivan_tsar/secret_passwords_link
```

> **Дополнительно:** Если вы используете `ln -s -v -t /home/ivan_tsar secret_passwords.txt`, система сообщит, что ссылка создана, но она **может указывать сама на себя**, если имя таргета совпадает с именем ссылки. Это приведёт к ошибке `Too many levels of symbolic links`.

### 4.2. Почему Иван Царевич не может прочитать символическую ссылку?

**Вопрос:** *Иван Царевич не может прочитать `secret_passwords.txt` через символическую ссылку в своей домашней папке. Почему?*

**Ответ:** Символическая ссылка хранит **путь** к целевому файлу. Если у Ивана Царевича нет прав на чтение **домашней директории** пользователя, в которой лежит исходный файл, он не сможет прочитать его через ссылку. Для решения проблемы используйте `setfacl` для выдачи прав:
```bash
setfacl -m u:ivan_tsar:--x /home/vboxuser
setfacl -m u:ivan_tsar:r-- /home/vboxuser/secret_passwords.txt
```

> **Важное уточнение:** `setfacl` — команда для управления **расширенными правами доступа (ACL)**.  
> - `--x` — даёт право **переходить** в директорию (execute), но не просматривать её содержимое.  
> - `r--` — даёт право **читать** файл.  
>  
> Без этих прав Иван Царевич не сможет прочитать файл через символическую ссылку, даже если сама ссылка существует.

### 4.3. Почему `cut` не изучался в курсе?

**Вопрос:** *Откуда взялись команды `$` и `cut`? В предыдущих уроках их не было.*

**Ответ:** Это резонное замечание. `cut` — утилита для извлечения столбцов из текста. В курсе она не изучалась, поэтому автор курса **убрал её из примера решения** и заменил на более простые команды. Однако `cut` полезен для извлечения имён пользователей из `/etc/passwd` (через разделитель `:`).

### 4.4. Что делать, если `pandoc` не установлен?

**Вопрос:** *У меня нет `pandoc`. Что делать?*

**Ответ:** Установите `pandoc`:
```bash
sudo apt update && sudo apt install -y pandoc
```

### 4.5. Почему `mkdir -p backups && cp ... || (mkdir backups && echo ...)` может работать неправильно?

**Вопрос:** *Почему без скобок цепочка `mkdir -p backups && cp ... || echo "Создана новая папка"` может вывести неправильное сообщение?*

**Ответ:** Операторы `&&` и `||` имеют **одинаковый приоритет** и выполняются **слева направо**. Без скобок:
1. `mkdir -p backups` — создаёт папку (если её нет).
2. `&& cp ...` — копирует файл (если папка создалась).
3. `|| echo "Создана новая папка"` — выводит сообщение, **если** какая-то команда слева завершилась с ошибкой.

Но если папка **уже существует**, `mkdir -p` завершится успешно, `cp` скопирует файл, и `||` **не выполнится**. Однако если папка **не существует** и `mkdir -p` создал её, `cp` скопирует файл, и `||` тоже **не выполнится**. В этом случае сообщение **не появится**.

**Правильный вариант с скобками:**
```bash
(mkdir -p backups && echo "Создана новая папка для бэкапов") || (cp secret_passwords.txt backups/ && echo "Файл скопирован")
```

> **Дополнительный пример:**  
> Без скобок: `mkdir -p backups && cp secret_passwords.txt backups/ || echo "Создана новая папка"`  
> Если папка `backups` уже существует, `mkdir -p` завершится успешно, `cp` скопирует файл, и `echo` **не выполнится**.  
> А если папки нет, `mkdir -p` создаст её, `cp` скопирует файл, и `echo` тоже **не выполнится**.  
>  
> **Правильный вариант:**  
> ```bash
> if [ -d backups ]; then
>     cp secret_passwords.txt backups/
> else
>     mkdir -p backups
>     echo "Создана новая папка для бэкапов"
>     cp secret_passwords.txt backups/
> fi
> ```

## 5. Лимиты, оптимизация и масштабирование

- **Жёсткие ссылки:** Нельзя создавать на директории и на файлы в других файловых системах.
- **Мягкие ссылки:** Могут указывать на файлы на других файловых системах и директории.
- **Конвейеры:** Позволяют обрабатывать данные потоково, не загружая весь файл в память.
- **`find` с перенаправлением:** Для сохранения результатов в файл используйте `>`, для объединения ошибок и результатов — `2>&1`.

## 6. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Символические ссылки как вектор обхода ограничений:** Злоумышленник может создать символическую ссылку на чувствительный файл (например, `/etc/shadow`) в месте, где у него есть права на запись. Если другой пользователь или процесс обратится к этой ссылке, он может получить доступ к данным, на которые у него нет прямых прав. Важно проверять ссылки в общедоступных директориях и использовать `find -type l` для их поиска.
    
- **Хранение паролей в открытом виде:** Создание файла с паролями (например, `secret_passwords.txt`) в незащищённом месте делает его доступным для любого, кто может прочитать директорию. Даже если права на файл ограничены, родительская директория должна иметь соответствующие права, чтобы избежать случайного раскрытия данных.
    
- **Неправильные права на резервные копии:** Создание бэкапов с правами `777` или без ограничения доступа (например, `cp file /tmp/`) может привести к утечке конфиденциальных данных. Резервные копии должны храниться в защищённых директориях с ограниченным доступом.
    
- **Утечка информации через логи:** Если перенаправление ошибок (`2> error.log`) настроено неправильно, ошибки могут содержать чувствительные данные (например, пути к файлам, имена пользователей). Важно проверять содержимое логов перед их хранением.
    
- **Анализ логов и обнаружение атак:** Использование `grep` и `wc` для анализа логов — это не только инструмент диагностики, но и способ обнаружения подозрительной активности (например, неудачные попытки входа через SSH). Однако если логи не защищены, злоумышленник может их изменить или удалить, скрывая следы.
    

### 2. Инженерный FAQ (по безопасности)

- **Вопрос:** Как защитить файл с паролями от несанкционированного доступа?  
  **Ответ:** Используйте права `600` (только владелец) и разместите файл в директории с правами `700`. Также можно использовать ACL для дополнительного ограничения доступа (например, `setfacl`).
    
- **Вопрос:** Что делать, если символическая ссылка указывает на файл в другой директории, но пользователь не может её прочитать?  
  **Ответ:** Проверьте права на директорию, где находится целевой файл. Если у пользователя нет права `x` на промежуточные директории, он не сможет получить доступ к файлу через ссылку. Для решения проблемы можно использовать `setfacl` или изменить права на директорию (но это может быть небезопасно).
    
- **Вопрос:** Как предотвратить создание симлинков, которые указывают сами на себя?  
  **Ответ:** Используйте абсолютные пути при создании ссылок (`ln -s /полный/путь/файл ссылка`). Внимательно проверяйте, что ссылка создана в правильном месте и указывает на существующий файл. Если использовать относительный путь без учёта текущей директории, ссылка может указать на саму себя.
    
- **Вопрос:** Как обеспечить безопасность резервных копий?  
  **Ответ:** Создавайте бэкапы в директориях с ограниченным доступом (например, `/mnt/archive` с правами `750`). Используйте `sudo` для копирования, чтобы файлы принадлежали `root`, и проверяйте права на созданные копии после операции.
    
- **Вопрос:** Можно ли использовать `find` для обнаружения подозрительных файлов?  
  **Ответ:** Да, `find` может помочь найти файлы с установленными SUID-битами (`find / -perm -4000`) или символические ссылки в неожиданных местах (`find / -type l`). Регулярный аудит таких файлов помогает выявлять потенциальные угрозы.
