# Тема 8.1: Ссылки и iNodes

В данной теме рассматриваются фундаментальные понятия файловой системы Linux: inodes (структуры метаданных), жёсткие и мягкие (символические) ссылки. Разбираются создание, характеристики, отличия и практические примеры использования ссылок, а также влияние на файловую систему и дисковое пространство.

---

## 1. Inodes — фундаментальное понятие файловой системы

**Inode** (index node) — это структура данных в файловой системе Linux, которая хранит метаинформацию о файле или директории, но **не содержит имя файла и его содержимое**.

- **Контекст/Уровень:** Системное администрирование / Файловая система.
- **Основное назначение:** Хранение метаинформации о файлах и директориях без содержимого и имени.
- **Принцип работы:** Inode (index node) — структура данных в файловой системе Linux, которая хранит метаданные файла. Каждый файл или директория имеет свой inode, который идентифицируется уникальным номером. Имя файла хранится отдельно в каталоге, а не в inode.

### 1.1. Что хранится в inode

- Тип файла (обычный, директория, ссылка и т.д.).
- Права доступа (`rwx`).
- UID владельца и GID группы.
- Размер файла.
- Временные метки (создание, модификация, доступ).
- Счётчик жёстких ссылок.
- Указатели на блоки данных на диске.

### 1.2. Просмотр inode номеров

```bash
ls -li                # показать inode номера (ключ -i)
```

**Пример вывода:**
```
123456 -rw-r--r-- 1 itguy itguy 1024 Mar 26 10:00 main.config.file
123456 -rw-r--r-- 1 itguy itguy 1024 Mar 26 10:00 hardlink2config
789012 lrwxrwxrwx 1 itguy itguy   15 Mar 26 10:00 softlink2config -> main.config.file
```

### 1.3. Inodes и команда `df -i`

```bash
df -i /              # просмотр использования inodes на корневом разделе
```

**Вывод показывает:**
- `IUsed` — количество использованных inodes.
- `IFree` — количество свободных inodes.
- `IUse%` — процент использованных inodes.

> **Важно:** Файловая система может заполниться не только по месту, но и по количеству inodes. В этом случае создать новый файл будет невозможно, даже если свободное место есть. Однако в файловых системах нового поколения (например, Btrfs) inodes не фиксированы и распределяются динамически, поэтому `df -i` может показывать `0` — это нормально.

## 2. Жёсткие ссылки (hard links)

**Жёсткая ссылка** — это **дополнительное имя файла**, указывающее на тот же inode, что и исходный файл.

- **Контекст/Уровень:** Системное администрирование / Файловая система.
- **Основное назначение:** Создание дополнительных имён для файла, указывающих на тот же inode.
- **Принцип работы:**  Жёсткая ссылка и исходный файл равнозначны — они указывают на один и тот же inode, поэтому изменения в одном файле автоматически отражаются в другом.

### 2.1. Создание жёсткой ссылки

```bash
ln source_file hardlink_name
```

### 2.2. Характеристики жёстких ссылок

| Свойство                      | Описание                                                                                  |
| :---------------------------- | :---------------------------------------------------------------------------------------- |
| **Один inode**                | Исходный файл и жёсткая ссылка имеют **одинаковый** номер inode.                          |
| **Счётчик ссылок**            | Каждая новая жёсткая ссылка увеличивает счётчик ссылок в inode.                           |
| **Независимость от имени**    | После переименования исходного файла жёсткая ссылка продолжает работать.                  |
| **Независимость от удаления** | После удаления исходного файла жёсткая ссылка сохраняет данные (пока счётчик ссылок > 0). |
| **Ограничения**               | Нельзя создать на разные файловые системы (разные разделы).                               |
*Таб. 1. Характеристики жёстких ссылок.*

### 2.3. Пример

```bash
echo "main config data" > main.config.file
ln main.config.file hardlink2config
ls -li
```

**Вывод:**
```
# 123456 -rw-r--r-- 2 itguy itguy 20 ... main.config.file
# 123456 -rw-r--r-- 2 itguy itguy 20 ... hardlink2config
```

Обратите внимание на вторую колонку (`2`) — это счётчик жёстких ссылок.

## 3. Мягкие (символические) ссылки — soft links

**Символическая ссылка** — это **отдельный файл**, который содержит **путь** к целевому файлу.

- **Контекст/Уровень:** Системное администрирование / Файловая система.
- **Основное назначение:** Создание ярлыков, указывающих на путь к целевому файлу.
- **Принцип работы:** При обращении к ссылке система следует по указанному пути и обращается к целевому файлу. В отличие от жёсткой ссылки, мягкая ссылка **не хранит содержимое файла**, а только **указатель** на его местоположение. Поэтому если целевой файл будет переименован или удалён, ссылка перестанет работать.

### 3.1. Создание мягкой ссылки

```bash
ln -s source_file softlink_name
```

> **Важное замечание:** Ключ `-s` в команде `ln` расшифровывается как **symbolic**, а не как "soft". В Linux мягкие ссылки называются **символическими**, хотя их суть от этого не меняется.

### 3.2. Характеристики мягких ссылок

| Свойство                    | Описание                                               |
| :-------------------------- | :----------------------------------------------------- |
| **Разный inode**            | Ссылка и целевой файл имеют **разные** номера inode.   |
| **Хранит путь**             | Содержит строку с путём к целевому файлу.              |
| **Зависимость от имени**    | При переименовании целевого файла ссылка **ломается**. |
| **Зависимость от удаления** | При удалении целевого файла ссылка **ломается**.       |
| **Гибкость**                | Может указывать на файлы на других файловых системах.  |
*Таб. 2. Характеристики мягких ссылок.*

### 3.3. Отображение в `ls -l`

```
lrwxrwxrwx 1 itguy itguy 15 Mar 26 10:00 softlink2config -> main.config.file
```

- Первый символ `l` — тип файла (link).
- Права `rwxrwxrwx` — права самой ссылки (фактические права определяются целевым файлом).
- Стрелка `->` показывает, на какой файл ссылается.

### 3.4. Сломанная ссылка (dangling link)

Если целевой файл удалён или переименован, ссылка становится нерабочей и подсвечивается красным цветом:

```
lrwxrwxrwx 1 itguy itguy 15 Mar 26 10:00 softlink2config -> main.config.file (broken)
```

## 4. Сравнение жёстких и мягких ссылок

| Характеристика | Жёсткая ссылка (hard link) | Мягкая ссылка (soft link) |
| :--- | :--- | :--- |
| **Создание** | `ln source target` | `ln -s source target` |
| **Inode** | Одинаковый с исходным | Разный с исходным |
| **После удаления исходного** | Данные сохраняются | Ссылка ломается |
| **После переименования исходного** | Работает | Ломается |
| **Может указывать на директорию** | Нет | Да |
| **Может работать между файловыми системами** | Нет | Да |
| **Размер** | Размер исходного файла | Длина пути (несколько байт) |
| **Отображение в `ls -l`** | Обычный файл | `l` в начале, `->` |
*Таб. 3. Сравнение жёстких и мягких ссылок.*

## 5. Копия vs ссылки

- **Копия файла** — это **полностью независимый файл** с собственным inode и содержимым.
- **Жёсткая ссылка** — дополнительное имя файла, указывающее на тот же inode.
- **Мягкая ссылка** — отдельный файл, содержащий путь к целевому файлу.

### 5.1. Создание копии

```bash
cp main.config.file copyof.config
```

### 5.2. Поведение при изменении исходного файла

```bash
echo "new line" >> main.config.file   # добавить строку
ls -li
```

**Результат:**
- `main.config.file` — размер увеличился.
- `hardlink2config` — размер увеличился (тот же inode).
- `softlink2config` — размер не изменился (ссылка), но при чтении покажет новые данные.
- `copyof.config` — размер остался прежним.

| Объект | Реакция на изменение исходного файла |
| :--- | :--- |
| Жёсткая ссылка | Изменяется (общий inode). |
| Мягкая ссылка | Изменяется (читает исходный файл). |
| Копия | Не изменяется (независимый файл). |
*Таб. 4. Поведение объектов при изменении исходного файла.*

## 6. Управление ссылками

### 6.1. Просмотр счётчика ссылок

```bash
ls -l
# -rw-r--r-- 2 itguy itguy ...   (вторая колонка — количество жёстких ссылок)
```

### 6.2. Поиск всех жёстких ссылок на файл

```bash
find / -inum 123456 2>/dev/null   # поиск по номеру inode
```

### 6.3. Удаление ссылок

```bash
rm hardlink2config       # удаляет жёсткую ссылку, уменьшает счётчик
rm softlink2config       # удаляет символическую ссылку (целевой файл не трогает)
```

## 7. Практические примеры

### 7.1. Создание файла и ссылок

```bash
# Создать файл с содержимым
echo "Important configuration" > main.config

# Создать жёсткую ссылку
ln main.config hardlink

# Создать мягкую ссылку
ln -s main.config softlink

# Создать копию
cp main.config copy

# Просмотреть inodes
ls -li
```

### 7.2. Эксперимент с переименованием

```bash
mv main.config renamed.config
cat hardlink          # работает
cat softlink          # ошибка: No such file or directory
cat renamed.config    # работает
```

### 7.3. Эксперимент с удалением

```bash
rm renamed.config
cat hardlink          # работает (данные сохранены)
cat softlink          # ошибка: broken link
```

### 7.4. Создание жёсткой ссылки на директорию (нельзя)

```bash
ln /home /home_link
# ln: /home: hard link not allowed for directory
```

> **Почему нельзя создать жёсткую ссылку на директорию?**  
> Потому что это может привести к созданию **циклических ссылок** (например, `/home` → `/home/link` → `/home`). Это нарушит целостность файловой системы (т.e. может создать бесконечную рекурсию при обходе). В Linux это **запрещено на уровне ядра**.

### 7.5. Создание мягкой ссылки на директорию

```bash
ln -s /home home_link
ls -l home_link
# lrwxrwxrwx ... home_link -> /home
```

## 8. Разбор сложных ситуаций и типичных вопросов

### 8.1. Почему `-s` расшифровывается как "symbolic", а не "soft"?

**Вопрос:** *В команде `ln -s` ключ `-s` расшифровывается как "soft" или как "symbolic"?*

**Ответ:** Ключ `-s` расшифровывается как **symbolic**. В Linux мягкие ссылки называются **символическими** (symbolic links), хотя их суть от этого не меняется. Термин "мягкая ссылка" (soft link) является неофициальным, но широко используется в русскоязычной документации.

> **Проверка в man:**  
> Если выполнить `man ln`, можно увидеть:  
> `-s, --symbolic    make symbolic links instead of hard links`  
> Это подтверждает, что `-s` означает **symbolic**, а не "soft".

### 8.2. Практический пример: DNS-сервер

**Вопрос:** *Как связаны ссылки и DNS-сервер?*

**Ответ:** В реальной практике ссылки часто используются для управления конфигурационными файлами. Например, файл `/etc/resolv.conf` изначально является символической ссылкой на файл в другой директории, который перезаписывается при перезагрузке системы. Чтобы изменить настройки DNS, нужно удалить ссылку и создать самостоятельный файл с нужным содержимым.

### 8.3. Зачем нужны жёсткие ссылки?

**Вопрос:** *Для чего нужны жёсткие ссылки?*

**Ответ:** Жёсткие ссылки позволяют создать несколько имён для одного файла на одном разделе. Это полезно для:
- Резервного копирования без дублирования данных.
- Организации файлов в разных каталогах без копирования.
- Экономии дискового пространства (например, видеофайл, который нужен в двух местах, занимает место только один раз).

> **Пример:** Если у вас есть видеофайл на 5 ГБ, который нужен и в `~/Videos`, и в `~/Documents/presentation`, вы можете сделать жёсткую ссылку вместо копии:
> ```bash
> ln /home/user/Videos/demo.mp4 /home/user/Documents/presentation/demo.mp4
> ```
> В итоге место занимает один файл, но доступен по двум путям.

### 8.4. Зачем нужны мягкие ссылки?

**Вопрос:** *Для чего нужны мягкие ссылки?*

**Ответ:** Мягкие ссылки — это ярлыки, указывающие на путь к файлу. Они используются для:
- Создания ярлыков для длинных путей.
- Организации версий (например, `python` → `python3.9`).
- Управления конфигурациями.
- Указания на файлы на других файловых системах.

> **Пример из практики (BitrixVM):**  
> В BitrixVM многие конфигурационные файлы (например, `/etc/nginx/nginx.conf`) являются **символическими ссылками** на файлы в других директориях. Это позволяет легко обновлять конфигурации, не перезаписывая основные файлы.

### 8.5. Что происходит при удалении последней жёсткой ссылки?

**Вопрос:** *Файл существует, пока на него ссылается хотя бы одна жёсткая ссылка. Что происходит при удалении последней?*

**Ответ:** При удалении последней жёсткой ссылки счётчик ссылок (`i_nlink`) становится равным нулю. Файл считается удалённым, но данные на диске **не стираются немедленно** — они помечаются как свободные и могут быть перезаписаны. Поэтому существуют утилиты для восстановления данных, а также утилиты для "безопасного удаления", которые перезаписывают данные перед удалением.

> **Дополнительно:** После удаления последней жёсткой ссылки данные на диске не стираются немедленно — они помечаются как свободные и могут быть перезаписаны. Поэтому существуют утилиты для восстановления данных. Однако если данные были перезаписаны, восстановить их уже нельзя.

### 8.6. Что происходит, если восстановить удалённый файл?

**Вопрос:** *Если я удалил оригинал, а потом создал файл с тем же именем, будет ли ссылка работать?*

**Ответ:** Зависит от типа ссылки:
- **Мягкая ссылка** — начнёт работать, потому что она ссылается на **имя файла**. Если создать новый файл с тем же именем, ссылка укажет на него.
- **Жёсткая ссылка** — **не будет ссылаться** на новый файл, потому что она указывает на **inode**, а не на имя. Новый файл получит новый inode, и жёсткая ссылка останется ссылкой на старый (удалённый) файл.

## 9. Лимиты, оптимизация и масштабирование

- **Жёсткие ссылки:** Нельзя создавать на директории и на файлы в других файловых системах.
- **Мягкие ссылки:** Могут указывать на файлы на других файловых системах и директории.
- **Копии:** Занимают дополнительное дисковое пространство, в отличие от ссылок.
- **Количество ссылок:** Максимальное количество жёстких ссылок на один файл ограничено значением `i_nlink` (обычно 65 535, но может отличаться в зависимости от файловой системы). Это техническое ограничение файловой системы.

## 10. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Ссылки и безопасность:** Символические ссылки могут использоваться для обхода ограничений доступа. Например, если злоумышленник создаёт ссылку на чувствительный файл, он может получить доступ к нему, даже если у него нет прямых прав. Важно проверять ссылки перед использованием.
- **Inodes и заполнение диска:** Если inodes закончатся, система не сможет создавать новые файлы, даже если есть свободное место. Это может быть использовано для атак типа "отказ в обслуживании".

### 2. Инженерный FAQ

- **Вопрос:** *Можно ли создать жёсткую ссылку на директорию?*  
  **Ответ:** Нет, нельзя. Создание жёсткой ссылки на директорию запрещено из соображений безопасности.

- **Вопрос:** *Что такое "сломанная" ссылка?*  
  **Ответ:** Сломанная ссылка (dangling link) — это символическая ссылка, целевой файл которой был удалён или переименован.

- **Вопрос:** *Как найти все жёсткие ссылки на файл?*  
  **Ответ:** Используйте команду `find / -inum 123456 2>/dev/null`, где `123456` — номер inode.

- **Вопрос:** *Что делать, если `whatis ln` выдаёт `nothing appropriate`?*  
  **Ответ:** Обновите базу данных man-страниц: `sudo mandb`.

### Ключевые выводы:

- Жёсткие ссылки и исходный файл имеют **один inode** и счётчик ссылок.
- После удаления исходного файла жёсткая ссылка продолжает работать (пока счётчик > 0).
- Мягкие ссылки зависят от имени целевого файла и ломаются при его переименовании или удалении.
- Копия — полностью независимый файл с собственным inode и содержимым.
- Жёсткие ссылки нельзя создавать на директории и на файлы в других файловых системах.
