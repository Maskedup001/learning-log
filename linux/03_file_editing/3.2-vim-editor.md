# Тема 3.2: Vim. Редактор по умолчанию

В данной теме рассматривается текстовый редактор Vim (Vi Improved) — стандартный редактор терминала в большинстве дистрибутивов Linux. Разбираются ключевые особенности, режимы работы, основные команды для навигации и редактирования текста, а также вопросы, связанные с практическим применением и безопасностью. В конце приведены практические рекомендации, разбор типичных ошибок и ответы на часто задаваемые вопросы.

---

## 1. Vim — Базовые свойства

* **Контекст/Уровень:** Системное администрирование / Работа с текстовыми файлами в терминале.
* **Основное назначение:** Редактирование текстовых файлов в терминале без использования графического интерфейса.
* **Принцип работы:** Vim (Vi Improved) — текстовый редактор, работающий в терминале. Является редактором по умолчанию в большинстве дистрибутивов Linux. Команды `vi` и `vim` часто являются псевдонимами друг для друга и вызывают один и тот же редактор.

### 1.1. Ключевые особенности

- **Предустановлен практически во всех Linux-системах** — работает даже в минимальных установках и на серверах.
- **Неинтуитивный для новичков, но чрезвычайно мощный** — после освоения Vim позволяет редактировать текст быстрее, чем в любом графическом редакторе.
- **Работает на огромном количестве устройств** — от серверов до встраиваемых систем и Android (через терминал).
- **Поддерживает плагины** — подсветка синтаксиса, интеграция с Git, автодополнение и многое другое.

### 1.2. Запуск редактора

```bash
vim filename.txt    # открыть файл в Vim
vi filename.txt     # часто то же самое (псевдоним)
```

> **Важное примечание:** В некоторых дистрибутивах (например, Ubuntu 24.04) Vim может не быть предустановлен. В таком случае установите его:

```bash
sudo apt install vim
```

## 2. Режимы работы Vim

Главная особенность Vim — наличие нескольких режимов работы. В графических редакторах вы просто печатаете текст. В Vim **режимы разделяют ввод текста и управление текстом**, что позволяет выполнять сложные операции без использования мыши.

### 2.1. Описание режимов

| Режим | Как попасть | Назначение |
| :--- | :--- | :--- |
| **Нормальный (Normal)** | По умолчанию при открытии; `Esc` из любого другого режима | Навигация, выполнение команд, переход в другие режимы |
| **Режим вставки (Insert)** | `i` (insert) | Непосредственный ввод и редактирование текста |
| **Режим команд (Command)** | `:` (двоеточие) | Выполнение команд: сохранение, выход, настройки |
| **Визуальный режим (Visual)** | `v` | Выделение текста для копирования, вырезания, удаления |
*Таб. 1. Режимы работы Vim*

**Варианты визуального режима:**

| Команда    | Действие                                |
| :--------- | :-------------------------------------- |
| `v`        | Визуальный режим (символьное выделение) |
| `V`        | Визуальный режим (построчное выделение) |
| `Ctrl + v` | Визуальный режим (блочное выделение)    |
*Таб. 2. Варианты визуального режима*

> **Почему в Vim нет мыши?** Vim был разработан в 1991 году для устройств, где мыши либо не было, либо она была неудобна. Вместо этого Vim предлагает клавиатурные команды для всех операций.

## 3. Выход из Vim (самое важное!)

Это первая команда, которую должен запомнить каждый новичок. Если вы не знаете, что делать — нажмите `Esc` несколько раз, затем введите `:q!` и нажмите `Enter`.

| Команда        | Действие                                                              |
| :------------- | :-------------------------------------------------------------------- |
| `:q`           | Выйти (quit) — работает только при отсутствии несохранённых изменений |
| `:q!`          | Выйти без сохранения изменений (force quit)                           |
| `:w`           | Сохранить (write) — остаться в редакторе                              |
| `:wq` или `:x` | Сохранить и выйти                                                     |
| `Shift + ZQ`   | Выйти без сохранения (альтернатива `:q!`)                             |
| `Shift + ZZ`   | Сохранить и выйти (альтернатива `:wq`)                                |
*Таб. 3. Команды выхода из Vim*

**Все команды вводятся в режиме команд после нажатия `:`.**

> **Примечание о `Shift + ZQ`:** Многие пользователи считают эту комбинацию более удобной, так как она не требует ввода двоеточия.

## 4. Редактирование текста

### 4.1. Типовой рабочий процесс

1. Открыть файл: `vim filename.txt` (попадаем в нормальный режим).
2. Перейти в режим вставки: нажать `i`.
   - `i` — вставить перед курсором
   - `a` — вставить после курсора
   - `I` — вставить в начало строки
   - `A` — вставить в конец строки
   - `o` — вставить пустую строку ниже и войти в режим вставки
   - `O` — вставить пустую строку выше и войти в режим вставки
1. Ввести или отредактировать текст.
2. Вернуться в нормальный режим: нажать `Esc`.
3. Сохранить: `:w`.
4. Выйти: `:q`.

**Или одной командой:** `:wq`.

### 4.2. Отмена изменений

| Команда (в нормальном режиме) | Действие |
| :--- | :--- |
| `u` | Отменить последнее действие (undo) |
| `3u` | Отменить последние 3 действия |
| `Ctrl + r` | Повторить отменённое действие (redo) |
*Таб. 4. Команды отмены изменений*

## 5. Команды управления текстом (нормальный режим)

### 5.1. Удаление

| Команда | Действие |
| :--- | :--- |
| `dd` | Удалить текущую строку |
| `5dd` | Удалить 5 строк (текущую и 4 следующих) |
| `dw` | Удалить слово от курсора |
| `2dw` | Удалить 2 слова |
| `x` | Удалить символ под курсором |
| `X` | Удалить символ перед курсором |
| `d$` | Удалить от курсора до конца строки |
| `d0` | Удалить от курсора до начала строки |
*Таб. 5. Команды удаления*

### 5.2. Копирование и вставка

| Команда | Действие                                       |
| :------ | :--------------------------------------------- |
| `p`     | Вставить содержимое буфера после курсора (put) |
| `P`     | Вставить содержимое буфера до курсора          |
| `yy`    | Скопировать (yank) текущую строку              |
| `y$`    | Скопировать от курсора до конца строки         |
| `yw`    | Скопировать слово от курсора                   |
*Таб. 6. Команды копирования и вставки*

> **Важно о буфере обмена:** `p` вставляет из **внутреннего буфера** Vim. Если вы вырезали текст в другом окне и скопировали его в системный буфер, он не попадёт во внутренний буфер Vim. Для копирования в системный буфер используются другие команды.

## 6. Навигация в нормальном режиме

Vim позволяет перемещаться по тексту без использования мыши и стрелок. Хотя стрелки тоже работают, их использование считается «не-вимовским» стилем.

### 6.1. Основные команды навигации

| Команда | Действие |
| :--- | :--- |
| `h` | Влево |
| `j` | Вниз |
| `k` | Вверх |
| `l` | Вправо |
| `w` | Вперёд на слово |
| `b` | Назад на слово |
| `0` | В начало строки |
| `$` | В конец строки |
| `gg` | Перейти в начало файла |
| `G` | Перейти в конец файла |
*Таб. 7. Основные команды навигации*

> **Почему именно `h j k l`?** Vim был разработан для устройств, у которых не было стрелок или они были неудобны. Клавиши `h j k l` находятся в центре клавиатуры и позволяют перемещаться, не отрывая рук от основной позиции. Это ключевая идея Vim — максимальная эффективность без лишних движений.

### 6.2. Навигация с числовыми аргументами

| Команда | Действие |
| :--- | :--- |
| `2w` | Переместиться на 2 слова вперёд |
| `10h` | Переместиться на 10 символов влево |
| `3j` | Переместиться на 3 строки вниз |
| `5k` | Переместиться на 5 строк вверх |
*Таб. 8. Навигация с числовыми аргументами*

### 6.3. Навигация по экрану и файлу

| Команда | Действие |
| :--- | :--- |
| `Ctrl + d` | Прокрутить вниз на половину экрана |
| `Ctrl + u` | Прокрутить вверх на половину экрана |
| `Ctrl + e` | Прокрутить вниз на одну строку |
| `Ctrl + y` | Прокрутить вверх на одну строку |
| `f[char]` | Переместиться вперёд к указанному символу |
| `F[char]` | Переместиться назад к указанному символу |
| `t[char]` | Переместиться вперёд к позиции перед указанным символом |
| `T[char]` | Переместиться назад к позиции перед указанным символом |
| `;` | Повторить последний поиск символа вперёд |
| `,` | Повторить последний поиск символа назад |

| `{` | Переместиться назад на параграф (до предыдущей пустой строки) |
*Таб. 9. Навигация по экрану и файлу*

## 7. Поиск текста

### 7.1. Поиск вперёд

1. В нормальном режиме нажать `/`
2. Ввести искомый текст (например, `Romeo`)
3. Нажать `Enter`

**Навигация по результатам:**

| Команда | Действие                               |
| :------ | :------------------------------------- |
| `n`     | Перейти к следующему совпадению (next) |
| `N`     | Перейти к предыдущему совпадению       |
*Таб. 10. Навигация по результатам поиска*

### 7.2. Поиск назад

Используйте `?` вместо `/` для поиска в обратном направлении.

**Пример:** `?Romeo` найдёт `Romeo` выше по тексту.

> **Примечание о выделении:** После поиска результаты остаются подсвеченными. Чтобы убрать подсветку, используйте команду `:nohlsearch` (или сокращённо `:noh`). Также можно использовать `Ctrl + L` для обновления экрана — это убирает временную подсветку.

## 8. Почему Vim так важен

Несмотря на высокий порог входа, Vim остаётся критически важным инструментом по нескольким причинам:

- **Предустановлен везде** — в минимальных установках Linux, на серверах, во встраиваемых системах, в Android (через терминал).
- **Не требует графического интерфейса** — работает через SSH на любом соединении.
- **Эффективность** — при освоении позволяет выполнять сложные операции с текстом без использования мыши.
- **Стандарт** — часто является единственным редактором, доступным в окружениях восстановления системы (rescue mode, single user mode).

## 9. Альтернативные сценарии и сравнение подходов

### 9.1. Сравнение текстовых редакторов для терминала

| Редактор | Плюсы | Минусы |
| :--- | :--- | :--- |
| **Nano** | Простой, интуитивный, есть подсказки в интерфейсе | Ограниченный функционал, не подходит для сложных задач |
| **Vim** | Мощный, предустановлен везде, поддерживает плагины | Высокий порог входа, неинтуитивный для новичков |
| **Emacs** | Чрезвычайно мощный, настраиваемый до бесконечности | Сложный, требует изучения Lisp |
| **micro** | Современный, горячие клавиши как в графических редакторах | Не предустановлен, требует установки |
| **neovim** | Форк Vim с улучшенной архитектурой и плагинами | Требует установки |
*Таб. 11. Сравнение текстовых редакторов для терминала*

### 9.2. Когда что использовать

- **Nano** — для быстрых правок, когда нужно просто отредактировать файл.
- **Vim** — для серьёзной работы, когда требуется скорость и мощный функционал.
- **Emacs** — для тех, кому нужен не просто редактор, а целая экосистема.
- **micro** — для тех, кто хочет привычные сочетания клавиш.
- **neovim** — для тех, кто хочет современный Vim с лучшей поддержкой плагинов.

## 10. Влияние на смежные системы и компоненты

### 10.1. Зависимости
- **Система:** Vim предустановлен практически везде, поэтому его наличие не требует дополнительных действий.
- **Плагины:** Для полноценной работы требуется установка плагинов через менеджеры (`vim-plug`, `Vundle`), что может влиять на производительность.

### 10.2. Влияние на производительность
- **Нагрузка на ресурсы:** Vim потребляет минимальное количество ресурсов, так как работает в терминале и не загружает файл целиком.
- **Эффективность:** При освоении Vim позволяет выполнять операции быстрее, чем в графических редакторах.

### 10.3. Влияние на безопасность
- **Редактирование системных файлов:** Использование `sudo vim` для редактирования системных файлов требует осторожности. Ошибки в конфигурации могут привести к неработоспособности системы.
- **Плагины:** Установка плагинов из ненадёжных источников может привести к компрометации системы.

### 10.4. Интеграция с другими инструментами
- **tmux:** Многие опытные пользователи запускают Vim внутри терминального мультиплексора `tmux`. Это позволяет сохранять сессии, разделять экран на панели и не терять состояние при обрыве SSH.

## 11. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Редактирование системных файлов:** Использование `sudo vim` требует осторожности. Ошибки в конфигурации могут привести к неработоспособности системы.
- **Плагины из ненадёжных источников:** Установка плагинов без проверки может привести к компрометации системы.

### 2. Инженерный FAQ (На основе разбора дискуссий)

- **Вопрос:** *Как выйти из Vim, если ничего не работает?*  
  **Ответ:** Нажмите `Esc` несколько раз, затем введите `:q!` и нажмите `Enter`. Это безопасный выход без сохранения изменений.

- **Вопрос:** *В чём разница между `vi` и `vim`?*  
  **Ответ:** `vim` — это улучшенная версия `vi` (Vi Improved). В большинстве дистрибутивов команды `vi` и `vim` являются псевдонимами и вызывают один и тот же редактор. Если установлен полноценный `vim`, ввод `vi` запускает его же.

- **Вопрос:** *Как освоить Vim с нуля?*  
  **Ответ:** Наберите в терминале `vimtutor`. Это встроенный интерактивный учебник, который проведёт вас по основам работы с Vim. Также существует браузерная игра [VimMaster](https://renzorlive.github.io/vimmaster/) для отработки навыков.

- **Вопрос:** *Почему `h j k l`, а не стрелки?*  
  **Ответ:** Vim разрабатывался для устройств, у которых не было стрелок. Клавиши `h j k l` находятся в центре клавиатуры, что позволяет не отрывать руки от основной позиции набора.

- **Вопрос:** *Почему Vim так сложен, если есть Nano?*  
  **Ответ:** Nano — это простой и удобный редактор для быстрых правок. Vim — это мощный инструмент, который при освоении даёт огромную скорость и гибкость. Nano не заменяет Vim, а дополняет его.

- **Вопрос:** *Что такое `vimtutor` и где его взять?*  
  **Ответ:** `vimtutor` — это встроенный интерактивный учебник, который доступен в терминале. Просто наберите `vimtutor` и следуйте инструкциям.

- **Вопрос:** *Что такое `neovim` и зачем он нужен?*  
  **Ответ:** `neovim` — это форк Vim с улучшенной архитектурой, поддержкой современных плагинов и более активным сообществом. Он не предустановлен по умолчанию, но является популярной альтернативой.

- **Вопрос:** *Существуют ли альтернативы `Esc` для выхода из режима вставки?*  
  **Ответ:** Да, `Ctrl + [` работает так же, как `Esc`. Это может быть удобнее, если `Esc` находится далеко от основной позиции рук.

- **Вопрос:** *На каком языке доступен `vimtutor`?*  
  **Ответ:** `vimtutor` доступен на многих языках, включая русский. В большинстве дистрибутивов он автоматически определяется по языку системы. Если нужно запустить на русском, можно использовать команду `vimtutor ru` (в некоторых системах) или выбрать русский язык внутри учебника.

- **Вопрос:** *Можно ли использовать `Ctrl + c` вместо `Esc`?*  
  **Ответ:** Да, `Ctrl + c` в большинстве случаев работает как `Esc`, но в некоторых плагинах может вести себя иначе. Более надёжная альтернатива — `Ctrl + [`.

## 12. Лимиты, оптимизация и масштабирование

- **Высокий порог входа:** Vim требует времени на освоение, но это окупается скоростью и эффективностью.
- **Предустановлен везде:** Это делает Vim идеальным выбором для работы на серверах и встраиваемых системах.
- **Плагины расширяют возможности:** Менеджеры плагинов (`vim-plug`, `Vundle`) позволяют настроить Vim под любые задачи.
- **Альтернативы:** Nano подходит для простых задач, Neovim — для тех, кому нужен более современный и быстрый инструмент.
