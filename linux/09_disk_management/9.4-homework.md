# Тема 9.4: Домашнее задание — Диагностика и управление дисковым пространством

В данной теме представлено практическое домашнее задание по диагностике дискового пространства, подключению нового диска и настройке автоматического монтирования. Задание разбито на три части: диагностика катастрофы, подключение спасательного диска и наведение порядка. В конце приведены примеры решений и разбор типичных ошибок.

Вам предстоит написать несколько команд в терминале для выполнения заданий. Затем вы сможете проверить результаты и сравнить свои команды с ответами.

**Примечание:** Ваш ответ может отличаться от приведённого в качестве эталона и при этом также являться верным. Это нормальная ситуация в программировании, когда одну задачу можно решить разными способами.

## 2. Пошаговые задачи

### Часть 1: Диагностика катастрофы

Система "задыхается" от нехватки места! Нужно выяснить масштабы бедствия.

1. **Проведите инвентаризацию дисков:**
   - Узнайте, какие диски есть в системе.
   - Проверьте использование места на файловых системах.
   - Найдите, какие типы файловых систем используются.

2. **Выявите "пожирателей пространства":**
   - Узнайте, сколько места занимает домашняя директория текущего пользователя.
   - Проверьте размер всех файлов с расширением `.log` в домашних директориях.
   - Найдите 5 самых больших файлов в системе.
   - Сохраните отчёт в файл `disk_report.txt`.

### Часть 2: Подключение спасательного диска

Иван Царевич принёс новый диск! Нужно его подготовить.

1. Найдите новый диск в системе (предположим, это `/dev/sdb`).
2. Изучите структуру диска и создайте новый раздел.
3. Отформатируйте раздел в файловую систему `ext4`.
4. Создайте точку монтирования `/mnt/archive` для нового хранилища.
5. Смонтируйте новый диск и дайте права на запись.

### Часть 3: Наведение порядка

Чтобы избежать повторения катастрофы, нужно настроить автоматическое монтирование.

1. Создайте резервную копию файла `fstab`.
2. Настройте автоматическое монтирование нового диска при загрузке.
3. Проверьте настройки — размонтируйте и смонтируйте по fstab.
4. Перенесите архивные файлы на новый диск.

### Бонус: Срочная помощь Волку

Серый Волк паникует — его тестовые логи занимают много места!

1. Найдите все файлы с расширением `.log` в его домашней директории.
2. Создайте на новом диске папку `wolf_logs` и переместите туда логи.

### Что нужно предоставить в результате

Полную последовательность команд терминала, решающую все задачи.

**Пример начала:**

```bash
# Часть 1
lsblk
df -hT
...
```

Удачи в спасении компании от цифрового коллапса!

## 3. Примеры решений

### 3.1. Авторское решение

```bash
# ===== Часть 1: Диагностика катастрофы =====

# 1. Инвентаризация дисков
echo "=== ИНВЕНТАРИЗАЦИЯ ДИСКОВ ===" > disk_report.txt
lsblk >> disk_report.txt
echo -e "\n=== ИСПОЛЬЗОВАНИЕ МЕСТА ===" >> disk_report.txt
df -hT >> disk_report.txt
echo -e "\n=== ФАЙЛОВЫЕ СИСТЕМЫ EXT4 ===" >> disk_report.txt
df -hT -t ext4 >> disk_report.txt

# 2. Поиск "пожирателей пространства"
echo -e "\n=== ДОМАШНЯЯ ДИРЕКТОРИЯ ===" >> disk_report.txt
du -sh ~ >> disk_report.txt

echo -e "\n=== РАЗМЕР .log ФАЙЛОВ В /home ===" >> disk_report.txt
du -ch /home/*.log 2>/dev/null | grep total >> disk_report.txt

echo -e "\n=== 5 САМЫХ БОЛЬШИХ ФАЙЛОВ ===" >> disk_report.txt
du -ah / 2>/dev/null | sort -hr | head -5 >> disk_report.txt

# Выводим отчет на экран
cat disk_report.txt

# ===== Часть 2: Подключение спасательного диска =====

# 1. Поиск нового диска
echo "=== ПОИСК НОВОГО ДИСКА ==="
lsblk
ls /dev/sd*

# 2. Изучение структуры диска и создание раздела
echo "=== СОЗДАНИЕ РАЗДЕЛА НА /dev/sdb ==="
sudo fdisk -l /dev/sdb
sudo fdisk /dev/sdb << EOF
n
p
1


w
EOF

# 3. Форматирование раздела
echo "=== ФОРМАТИРОВАНИЕ РАЗДЕЛА ==="
sudo mkfs.ext4 /dev/sdb1

# 4. Создание точки монтирования
echo "=== СОЗДАНИЕ ТОЧКИ МОНТИРОВАНИЯ ==="
sudo mkdir /mnt/archive

# 5. Монтирование диска и настройка прав
echo "=== МОНТИРОВАНИЕ ДИСКА ==="
sudo mount /dev/sdb1 /mnt/archive
sudo chmod 755 /mnt/archive

# Проверка
lsblk -f
df -hT | grep archive

# ===== Часть 3: Наведение порядка =====

# 1. Резервная копия fstab
echo "=== СОЗДАНИЕ БЭКАПА FSTAB ==="
sudo cp /etc/fstab /etc/fstab.bak
ls /etc/fstab*

# 2. Настройка автоматического монтирования
echo "=== НАСТРОЙКА АВТОМОНТИРОВАНИЯ ==="

# Показываем UUID для информации
echo "UUID диска:"
lsblk -f /dev/sdb1 | grep sdb1 | awk '{print $3}'

# Добавляем запись в fstab напрямую
lsblk -f /dev/sdb1 | grep sdb1 | awk '{print "UUID="$3" /mnt/archive ext4 defaults 0 2"}' | sudo tee -a /etc/fstab

# 3. Проверка настроек
echo "=== ПРОВЕРКА АВТОМОНТИРОВАНИЯ ==="
sudo umount /mnt/archive
sudo mount -a
df -hT | grep archive

# 4. Перенос архивных файлов
echo "=== ПЕРЕНОС АРХИВНЫХ ФАЙЛОВ ==="
sudo mkdir /mnt/archive/old_projects
# Переносим файлы (перемещаем, а не копируем)
sudo mv /home/projects/* /mnt/archive/old_projects/ 2>/dev/null || echo "Файлы перенесены или отсутствуют"

# Проверка переноса
ls -la /mnt/archive/old_projects/

# ===== Бонус: Срочная помощь Волку =====

# Поиск логов Волка
echo "=== ПОИСК ЛОГОВ ВОЛКА ==="
find /home/gray_wolf -name "*.log" -type f > wolf_logs_list.txt
echo "Найдены файлы:"
cat wolf_logs_list.txt

# Создание папки и перемещение логов
echo "=== ПЕРЕМЕЩЕНИЕ ЛОГОВ ==="
sudo mkdir /mnt/archive/wolf_logs

# Перемещаем только то, что есть в корне домашней директории
sudo mv /home/gray_wolf/*.log /mnt/archive/wolf_logs/ 2>/dev/null
echo "Логи Волка перемещены в архив"

# Проверка
echo "Логи перемещены в:"
ls -la /mnt/archive/wolf_logs/

# Финальная проверка места
echo "=== ФИНАЛЬНАЯ ПРОВЕРКА МЕСТА ==="
df -hT | grep -E "(Filesystem|archive)"
# или вариант проще:
df -hT | grep archive
```

sudo gdisk /dev/sdb
# Интерактивные команды:

# 4. Создание точки монтирования
sudo mkdir -p /mnt/archive

sudo cp /etc/fstab /etc/fstab.bak

## 4. Разбор сложных ситуаций и типичных ошибок

### 4.1. Почему `du -ch /home/*.log` не находит файлы?

**Вопрос:** *Команда `du -ch /home/*.log` выдаёт ошибку `No such file or directory`. Почему?*

**Ответ:** Файлы `.log` могут находиться в поддиректориях, а не в корне `/home`. Команда `du -ch /home/*.log` ищет только в корне `/home`, поэтому не находит файлы в поддиректориях.

**Решение:** Использовать `find` для рекурсивного поиска:

```bash
find /home -type f -name "*.log" -exec du -h {} + | sort -hr
```

---

### 4.2. Почему для папки `development` нужно именно `770`?

**Вопрос:** *Почему для папки `development` нужно ставить `770`, а не `700` или `777`?*

**Ответ:** Права `770` (`rwxrwx---`) означают:
- Владелец (`ivan_tsar`) — полный доступ (`rwx`).
- Группа (`developers`) — полный доступ (`rwx`).
- Остальные — нет доступа (`---`).

Это обеспечивает доступ только для разработчиков, но не для посторонних.

> **Важное замечание:** Для папок обязательно нужен `x` (исполнение), чтобы можно было зайти в папку (`cd`). Право `r` (чтение) позволяет только просматривать список файлов через `ls`, но без `x` вы не сможете получить доступ к содержимому папки.

---

### 4.3. Почему после перезагрузки диск пропадает из `df -h`?

**Вопрос:** *После перезагрузки диск `/dev/sdb1` пропадает из `df -h`. Почему?*

**Ответ:** Ручное монтирование не сохраняется после перезагрузки. Для автоматического монтирования необходимо добавить запись в `/etc/fstab`.

**Решение:** Добавить строку с UUID в `/etc/fstab` и проверить через `sudo mount -a`.

---

### 4.4. Что делать, если `mount -a` выдаёт ошибку про systemd?

**Вопрос:** *При выполнении `sudo mount -a` появляется ошибка: `mount: (hint) your fstab has been modified, but systemd still uses the old version; use 'systemctl daemon-reload' to reload.`*

**Ответ:** Выполнить `systemctl daemon-reload` и повторить `sudo mount -a`:

```bash
systemctl daemon-reload
sudo mount -a
```

---

### 4.5. Почему `find /home/gray_wolf -name "*.log" -type f` находит файлы в поддиректориях?

**Вопрос:** *Команда `find /home/gray_wolf -name "*.log" -type f` находит файлы в поддиректориях. Это нормально?*

**Ответ:** Да, `find` по умолчанию ищет рекурсивно во всех поддиректориях. Если нужно найти только в корне домашней директории, используйте `-maxdepth 1`:

```bash
find /home/gray_wolf -maxdepth 1 -name "*.log" -type f
```

## 5. Лимиты, оптимизация и масштабирование

- **`du -ah /`** — команда может выполняться очень долго на больших дисках. Для ускорения можно ограничить глубину поиска: `du -ah --max-depth=3 /`.
- **`find / -type f`** — поиск по всей файловой системе может занять значительное время. Рекомендуется исключать системные каталоги: `find / -path /proc -prune -o -path /sys -prune -o -type f -print`.
- **`rsync`** — для больших объёмов данных рекомендуется использовать `rsync` вместо `mv`, так как он поддерживает докачку и проверку целостности.
- **`fdisk` vs `gdisk`** — для дисков больше 2 ТБ обязательно использовать GPT (`gdisk`).

## 6. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Неправильное редактирование `/etc/fstab`:** Ошибка (неверный UUID, лишний пробел, неверный путь) может привести к отказу загрузки системы. Это критический вектор отказа в обслуживании (DoS). Всегда используйте `sudo mount -a` для проверки и опцию `nofail` для критичных дисков.
    
- **Использование `sudo` без необходимости:** Выполнение команд с правами root повышает риск случайного повреждения данных. Злоумышленник, получивший терминал, может выполнить любую команду. Следует ограничивать доступ к sudo и работать с минимально необходимыми правами.
    
- **Слишком широкие права на точку монтирования:** Установка `chmod 777` на смонтированный диск позволяет любому пользователю изменять или удалять данные. Если диск содержит чувствительную информацию, это может привести к утечке. Используйте принцип минимальных привилегий (`770`, `750`).
    
- **Прямой доступ к устройству:** Команда `cat /dev/sdb` открывает сырой диск, что может привести к повреждению данных или раскрытию фрагментов чувствительной информации (пароли, ключи). Избегайте этого без крайней необходимости.
    
- **Оставление неиспользуемых ресурсов (Yandex Cloud):** Если после работы не удалить виртуальные машины и хранилище, можно получить счёт за неиспользованные ресурсы. Всегда соблюдайте последовательность удаления.
    
### 2. Инженерный FAQ (по безопасности)

- **Вопрос:** Как защитить `/etc/fstab` от случайных ошибок?  
  **Ответ:** Всегда делайте резервную копию (`sudo cp /etc/fstab /etc/fstab.bak`), проверяйте записи через `sudo mount -a` и используйте опцию `nofail` для необязательных дисков. Также полезно проверять UUID через `blkid` перед добавлением строки.
    
- **Вопрос:** Что делать, если после изменения fstab система не загружается?  
  **Ответ:** Загрузитесь в режим восстановления (recovery mode) или используйте live USB, закомментируйте проблемную строку в `/etc/fstab`, перезагрузитесь и исправьте ошибку.
    
- **Вопрос:** Как безопасно дать доступ к диску другим пользователям?  
  **Ответ:** Используйте группы и права `770` или `750`. Например, `sudo chown user:group /mnt/archive && sudo chmod 770 /mnt/archive`. Это даст доступ только членам группы.
    
- **Вопрос:** Как избежать повреждения данных при работе с `fdisk`/`gdisk`?  
  **Ответ:** Всегда создавайте резервные копии важных данных, перед изменением таблицы разделов проверяйте вывод `lsblk` и `sudo fdisk -l`, действуйте по шагам и не прерывайте процесс.
    
- **Вопрос:** Как удалить облачные ресурсы, чтобы не платить?  
  **Ответ:** Выполните строго: отключите хранилище от ВМ, удалите хранилище, удалите ВМ, удалите облако и платёжный аккаунт. Проверьте, что ничего не осталось в консоли.
