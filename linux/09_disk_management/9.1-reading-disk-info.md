# Тема 9.1: Чтение информации

В данной теме рассматриваются команды для получения информации о дисках и файловых системах в Linux: директория `/dev`, команды `df`, `du`, `mount`, `fdisk`, `gdisk` и `lsblk`. Разбираются обозначения дисков и разделов, различия между MBR и GPT, а также практические примеры определения основного диска.

---

## 1. Устройства в Linux — директория `/dev` — Базовые свойства

- **Контекст/Уровень:** Системное администрирование / Файловая система.
- **Основное назначение:** Предоставление доступа к физическим и виртуальным устройствам через файловую систему.
- **Принцип работы:** В Linux всё является файлом, включая устройства. Директория `/dev` (devices) содержит специальные файлы, представляющие физические и виртуальные устройства системы.

### 1.1. Обозначения дисков

| Обозначение | Тип устройства |
| :--- | :--- |
| `sdX` | SCSI, SATA, USB-диски (современные интерфейсы) |
| `hdX` | IDE-диски (устаревшие, редко встречаются) |
| `nvmeXnY` | NVMe SSD (современные высокоскоростные SSD) |

*Таб. 1. Обозначения дисков.*

**Пример:** `sda` — первый физический диск, `sdb` — второй и т.д.

> **Важное замечание:** При использовании SSD наименование дисков в системе может начинаться с `nvme*`. Например, `nvme0n1` — это первый NVMe SSD, а `nvme0n1p1` — его первый раздел. У пользователя с SSD в системе может не быть `sda` вообще — он будет только на флешке.

### 1.2. Разделы диска

К обозначению диска добавляется номер раздела:

- `sda1` — первый раздел на диске `sda`
- `sda2` — второй раздел
- `sda3` — третий раздел

### 1.3. Просмотр дисковых устройств

```bash
ls /dev/sd*          # показать все sd-устройства
ls /dev/nvme*        # показать все NVMe-устройства
```

## 2. Команда `df` — информация о свободном месте

`df` (disk free) отображает информацию об использовании дискового пространства всех смонтированных файловых систем.

### 2.1. Базовое использование

```bash
df -h                # human-readable (ГБ, МБ, КБ)
df -hT               # добавить тип файловой системы
df -hT /             # информация только о корневом разделе
```

### 2.2. Фильтрация по типу файловой системы

```bash
df -hT -t ext4       # показать только разделы с ext4
```

### 2.3. Информация об inodes

```bash
df -i                # использование inodes
df -ih               # с human-readable
```

> **Важно:** Раздел может быть заполнен не только по месту, но и по количеству inodes.

---

## 3. Команда `du` — использование дискового пространства

`du` (disk usage) показывает, сколько места занимают файлы и директории.

### 3.1. Полезные ключи

| Ключ | Описание |
| :--- | :--- |
| `-h` | human-readable |
| `-s` | summary — только итог |
| `-d N` | max depth — глубина вложенности |
| `-c` | total — показать общий итог в конце |

*Таб. 2. Ключи команды `du`.*

### 3.2. Примеры

```bash
du -sh ~             # размер домашней директории
du -h --max-depth=1  # размер файлов и папок первого уровня
du -ch *.txt         # размер всех .txt файлов с итогом
```

> **Важное замечание:** Ключа `-i` для команды `du` **не существует**. Команда `mount -h` — это то же самое, что и `mount --help` (вызов справки), а не команда для просмотра дисков.

---

## 4. Команда `mount` — информация о смонтированных файловых системах

Без аргументов `mount` выводит список всех смонтированных файловых систем.

```bash
mount                # вывести все точки монтирования
```

Вывод содержит много информации, часто используется в сочетании с `grep` для фильтрации:

```bash
mount | grep ext4    # показать только разделы с ext4
```

## 5. Команды `fdisk` и `gdisk` — работа с таблицей разделов

Эти команды предназначены для просмотра и изменения таблицы разделов диска. Они требуют прав `root`.

### 5.1. Различия между MBR и GPT

| Характеристика | MBR (Master Boot Record) | GPT (GUID Partition Table) |
| :--- | :--- | :--- |
| Макс. размер диска | 2 ТБ | 9,4 ЗБ (зеттабайт) |
| Макс. количество разделов | 4 основных | 128 (по умолчанию) |
| Команда | `fdisk` | `gdisk` (более современная) |
| Надёжность | Одна копия | Несколько копий, контрольные суммы |

*Таб. 3. Сравнение MBR и GPT.*

### 5.2. Просмотр информации о диске с помощью `fdisk`

```bash
sudo fdisk -l /dev/sda
```

Вывод содержит:
- Размер диска (в GiB)
- Размер сектора
- Тип таблицы разделов (GPT / MBR)
- Список разделов с размерами и типами

**Пример вывода `fdisk -l /dev/sda`:**

```bash
Disk /dev/sda: 25 GiB, 26843545600 bytes, 52428800 sectors
Disk model: VBOX HARDDISK
Units: sectors of 1 * 512 = 512 bytes
Sector size (logical/physical): 512/512 bytes
I/O size (minimum/optimal): 512/512 bytes
Disk label type: gpt
Disk identifier: BDE43016-D788-4D89-A611-49CCE602CBC7

Device      Start      End  Sectors  Size Type
/dev/sda1    2048     4095     2048    1M BIOS boot
/dev/sda2    4096  1054719  1050624  513M EFI System
/dev/sda3 1054720 52426751 51372032 24.5G Linux filesystem
```

> **Подробный разбор вывода `fdisk -l /dev/sda`:**
>
> **Строка `Disk /dev/sda: 25 GiB, 26843545600 bytes, 52428800 sectors`**  
> Указывает общий размер диска: 25 ГиБ (Gibibyte) в двоичных единицах, 26 843 545 600 байт и 52 428 800 секторов.  
> Один сектор = 512 байт (стандарт для большинства дисков).
>
> **Строка `Disk model: VBOX HARDDISK`**  
> Модель диска — виртуальный диск VirtualBox.
>
> **Строка `Units: sectors of 1 * 512 = 512 bytes`**  
> Единица измерения — сектор (512 байт).
>
> **Строка `Sector size (logical/physical): 512/512 bytes`**  
> Логический и физический размер сектора — 512 байт.
>
> **Строка `I/O size (minimum/optimal): 512/512 bytes`**  
> Минимальный и оптимальный размер операций ввода-вывода.
>
> **Строка `Disk label type: gpt`**  
> Тип таблицы разделов — GPT (GUID Partition Table), современный формат.
>
> **Строка `Disk identifier: BDE43016-D788-4D89-A611-49CCE602CBC7`**  
> Уникальный идентификатор диска в формате GUID (Globally Unique Identifier). Используется для однозначной идентификации диска в системе.
>
> **Таблица разделов:**
> - `/dev/sda1` — раздел BIOS boot (1M). Не монтируется, используется для загрузки системы на GPT-дисках.
> - `/dev/sda2` — раздел EFI System (513M). Точка монтирования `/boot/efi` (или аналогичная), содержит загрузчики EFI.
> - `/dev/sda3` — раздел Linux filesystem (24.5G). Основной раздел с корневой файловой системой (`/`).
>
> **Особенности `fdisk`:**
> - Не отображает уникальные GUID-идентификаторы разделов.
> - Типы разделов выражаются приблизительно («Linux filesystem», «EFI System»).
> - Вывод компактный — удобен для быстрого просмотра.

> **Примечание:** Обозначение GiB (Gibibyte) — это 1024 МБ, в отличие от GB (Gigabyte) = 1000 МБ. Это важно для понимания размеров дисков.

> **Дополнительно:** В Debian без `sudo` команды `fdisk` и `gdisk` не откроются. Некоторые администраторы предпочитают `cfdisk` — утилиту с более удобным интерактивным интерфейсом.

> **Дополнительно:** Про разницу между KiB, MiB, GiB и KB, MB, GB полезно почитать на Wikipedia — это помогает понимать размеры дисков.

### 5.3. Просмотр с помощью `gdisk`

```bash
sudo gdisk -l /dev/sda
```

Аналогичен `fdisk`, но ориентирован на GPT.

**Пример вывода `gdisk -l /dev/sda`:**

```bash
GPT fdisk (gdisk) version 1.0.8
Partition table scan:
  MBR: protective
  BSD: not present
  APM: not present
  GPT: present
  
Found valid GPT with protective MBR; using GPT.
Disk /dev/sda: 52428800 sectors, 25.0 GiB
Model: VBOX HARDDISK
Sector size (logical/physical): 512/512 bytes
Disk identifier (GUID): BDE43016-D788-4D89-A611-49CCE602CBC7
Partition table holds up to 128 entries
First usable sector: 34, last usable sector: 52428766
Total free space: 4029 sectors (2.0 MiB)

Number  Start (sector)   End (sector)  Size       Code  Name
1       2048             4095          1024.0 KiB  EF02  BIOS boot
2       4096             1054719       513.0 MiB   EF00  EFI System Partition
3       1054720          52426751      24.5 GiB    8300  Linux filesystem
```

> **Подробный разбор вывода `gdisk -l /dev/sda`:**
>
> **Строка `GPT fdisk (gdisk) version 1.0.8`**  
> Название и версия утилиты.
>
> **Блок `Partition table scan:`**  
> Проверка наличия различных типов таблиц разделов:
> - `MBR: protective` — защитная MBR (присутствует на GPT-дисках, чтобы старые системы не пытались читать диск как MBR).
> - `BSD: not present` — таблица BSD отсутствует.
> - `APM: not present` — таблица Apple Partition Map отсутствует.
> - `GPT: present` — таблица GPT присутствует.
>
> **Строка `Found valid GPT with protective MBR; using GPT.`**  
> Подтверждение: диск содержит корректную GPT с защитной MBR, поэтому используется GPT.
>
> **Строка `Disk /dev/sda: 52428800 sectors, 25.0 GiB`**  
> Общий размер диска: 52 428 800 секторов и 25.0 ГиБ.
>
> **Строка `Model: VBOX HARDDISK`**  
> Модель диска — виртуальный диск VirtualBox.
>
> **Строка `Sector size (logical/physical): 512/512 bytes`**  
> Логический и физический размер сектора — 512 байт.
>
> **Строка `Disk identifier (GUID): BDE43016-D788-4D89-A611-49CCE602CBC7`**  
> Уникальный GUID диска.
>
> **Строка `Partition table holds up to 128 entries`**  
> Максимальное количество записей в таблице разделов — 128 (стандарт для GPT).
>
> **Строки `First usable sector: 34, last usable sector: 52428766`**  
> Границы полезного пространства: первый доступный сектор — 34, последний — 52 428 766. Сектора 0–33 зарезервированы для защитной MBR и GPT-заголовка.
>
> **Строка `Total free space: 4029 sectors (2.0 MiB)`**  
> Свободное незанятое пространство — 4029 секторов (2.0 МиБ).
>
> **Таблица разделов:**
> - `Number 1` — раздел BIOS boot (1024.0 KiB, код `EF02`). Не монтируется, используется для загрузки.
> - `Number 2` — раздел EFI System Partition (513.0 MiB, код `EF00`). Содержит загрузчики EFI.
> - `Number 3` — раздел Linux filesystem (24.5 GiB, код `8300`). Основной раздел с корневой файловой системой.
>
> **Особенности `gdisk`:**
> - Отображает уникальные GUID-идентификаторы разделов.
> - Показывает точные коды типов разделов (`EF02`, `EF00`, `8300`).
> - Показывает точные имена разделов («EFI System Partition»).
> - Разделы нумеруются и указываются с точными границами в секторах.
> - Вывод детальный — удобен для глубокого анализа GPT-дисков.

### 5.4. Сравнение `fdisk` и `gdisk`

| Критерий | `fdisk` | `gdisk` |
| :--- | :--- | :--- |
| **Тип таблицы** | Работает и с MBR, и с GPT | Работает **только с GPT** |
| **Формат** | Компактный, быстрый просмотр | Детальный, технический |
| **GUID** | Не показывает | Показывает (идентификаторы и коды) |
| **Типы разделов** | Приблизительные («Linux filesystem») | Точные коды (`8300`, `EF00`, `EF02`) |
| **Имена разделов** | Не показывает | Показывает точные названия |

*Таб. 4. Сравнение `fdisk` и `gdisk`.*

> **Почему результаты почти одинаковые?**  
> Это объясняется тем, что диск уже размечен как **GPT**. Если бы диск был размечен как **MBR** (устаревший формат), то `gdisk` выдал бы ошибку «Not a GPT disk», а `fdisk` показал бы **MBR**.

## 6. Команда `lsblk` — список блочных устройств

`lsblk` (list block devices) — наиболее наглядный способ просмотра информации о дисках и их разделах.

### 6.1. Базовое использование

```bash
lsblk
```

**Пример вывода:**

```
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINT
sda      8:0    0   20G  0 disk
├─sda1   8:1    0  512M  0 part /boot
├─sda2   8:2    0    1G  0 part [SWAP]
└─sda3   8:3    0 18.5G  0 part /
```

| Колонка | Описание |
| :--- | :--- |
| `NAME` | Имя устройства |
| `SIZE` | Размер |
| `TYPE` | `disk` (физический диск), `part` (раздел) |
| `MOUNTPOINT` | Точка монтирования (если смонтировано) |

*Таб. 5. Колонки вывода `lsblk`.*

> **Дополнительный пример:** Для NVMe SSD вывод может выглядеть так:
> ```bash
> nvme0n1     259:0    0 238,5G  0 disk  
> ├─nvme0n1p1 259:1    0   100M  0 part /boot/efi
> ├─nvme0n1p2 259:2    0    16M  0 part  
> ├─nvme0n1p3 259:3    0  68,4G  0 part  
> ├─nvme0n1p4 259:4    0  34,5G  0 part /
> ├─nvme0n1p5 259:5    0   7,8G  0 part [SWAP]
> ├─nvme0n1p6 259:6    0  34,4G  0 part /Data
> ├─nvme0n1p7 259:7    0  78,1G  0 part  
> └─nvme0n1p8 259:8    0   1,5G  0 part
> ```

### 6.2. Полезные ключи

```bash
lsblk -f             # показать файловые системы
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT   # выбрать нужные колонки
lsblk -l             # список без древовидной структуры
```

## 7. Определение основного диска

Основной диск (корневая файловая система) определяется по точке монтирования `/`:

```bash
df -h /              # показывает, какой раздел смонтирован в /
lsblk -f | grep /    # найти раздел с точкой монтирования /
```

В выводе `df -h` и `lsblk` корневой раздел будет иметь `MOUNTPOINT = /`.

> **Важное уточнение:** `tmpfs` — это временное файловое хранилище в оперативной памяти, а `ext4` — это раздел на жёстком диске. Они **не являются синонимами**. `tmpfs` используется для временных данных (например, `/tmp`), а `ext4` — для постоянного хранения данных.

## 8. Сравнение команд для работы с дисками

| Команда (с опциями) | Назначение | Требует root | Особенности |
| :--- | :--- | :--- | :--- |
| `lsblk` | Список блочных устройств | Нет | Наглядное древовидное отображение |
| `df -h` | Свободное место на смонтированных разделах | Нет | Показывает использование дискового пространства |
| `du -sh` | Размер директорий | Нет | Для оценки занятого места папками |
| `mount` | Список смонтированных файловых систем | Нет | Много информации, удобно фильтровать через `grep` |
| `sudo fdisk -l` | Таблица разделов диска | Да | Подробная информация о разделах |
| `sudo gdisk -l` | Таблица разделов (GPT) | Да | Современная альтернатива `fdisk` |
| `cat /dev/sda` | Прямой доступ к устройству | Да | Опасно! Не использовать без необходимости |

## 10. Контрольные вопросы

### Вопрос 1. Где в файловой системе Linux можно найти файлы, представляющие физические диски и их разделы?

- В папке `/dev/`
- В папке `/bin/`
- В папке `/mnt/`
- В папке `/etc/`

**Пояснение:** Директория `/dev` содержит специальные файлы, представляющие физические и виртуальные устройства системы.

### Вопрос 2. Что обозначают имена `sda`, `sda1`, `sda2` в каталоге `/dev`?

- `sda` — это раздел диска, а `sda1`, `sda2` — это физические диски
- `sda` — это физический диск, а `sda1`, `sda2` — это его разделы
- Все эти имена обозначают разные физические диски
- Это специальные файлы для оперативной памяти (tmpfs)

**Пояснение:** `sda` — физический диск, `sda1`, `sda2` — его разделы.

### Вопрос 3. Какой командой можно быстро узнать общее, использованное и свободное место на всех смонтированных дисках в удобочитаемом виде (в гигабайтах, мегабайтах)?

- `du -i`
- `lsblk`
- `df -h`
- `mount -h`

**Пояснение:** `df -h` показывает общее, использованное и свободное место на всех смонтированных дисках в удобочитаемом виде.

> **Важное уточнение:** Ключа `-i` для команды `du` не существует. Команда `mount -h` — это вызов справки, а не просмотр дисков.

### Вопрос 4. С помощью какого ключа команды `df` можно отфильтровать вывод и показать информацию только для дисков с определённым типом файловой системы, например, `ext4`?

- `df -h ext4`
- `df -t ext4`
- `df -m ext4`
- `df --filter ext4`

**Пояснение:** Ключ `-t` фильтрует вывод по типу файловой системы.

### Вопрос 5. Чем принципиально отличаются строки с типом файловой системы `ext4` от строк с типом `tmpfs` в выводе команды `df`?

- `tmpfs` — это раздел на жёстком диске, а `ext4` — это раздел на SSD диске
- Ничем не отличаются, это синонимы
- `ext4` — это раздел для загрузки, а `tmpfs` — это корневой раздел
- `ext4` — это раздел на жёстком диске, а `tmpfs` — это временное файловое хранилище в оперативной памяти

**Пояснение:** `ext4` — это раздел на жёстком диске, а `tmpfs` — временное файловое хранилище в оперативной памяти.

### Вопрос 6. Какой командой можно получить информацию о блочных устройствах (дисках и разделах) в виде древовидной структуры?

- `mount`
- `df -h`
- `fdisk -l`
- `lsblk`

**Пояснение:** `lsblk` показывает информацию о блочных устройствах в виде древовидной структуры.

### Вопрос 7. Вы запустили команду `sudo fdisk -l /dev/sda`. В строке "Disklabel type" вы видите значение `gpt`. Что это означает?

- Диск размечен с помощью современной схемы GPT (GUID Partition Table)
- Диск использует файловую систему EXT4
- Диск размечен с помощью устаревшей схемы MBR (Master Boot Record)
- Диск не размечен и не содержит разделов
- Диск создан с помощью Chat GPT

**Пояснение:** Значение `gpt` в строке "Disklabel type" означает, что диск размечен с помощью современной схемы GPT (GUID Partition Table).

## 11. Разбор сложных инженерных ситуаций, граничных кейсов и аномалий

### 11.1. Определение основного диска

Основной диск (корневая файловая система) определяется по точке монтирования `/`:

```bash
df -h /              # показывает, какой раздел смонтирован в /
lsblk -f | grep /    # найти раздел с точкой монтирования /
```

В выводе `df -h` и `lsblk` корневой раздел будет иметь `MOUNTPOINT = /`.

> **Важное уточнение:** `tmpfs` — это временное файловое хранилище в оперативной памяти, а `ext4` — это раздел на жёстком диске. Они **не являются синонимами**. `tmpfs` используется для временных данных (например, `/tmp`), а `ext4` — для постоянного хранения данных.

---

### 11.2. Почему на SSD диск может называться `nvme0n1`, а не `sda`?

**Вопрос:** _Почему при использовании SSD наименование дисков в системе может начинаться с `nvme*`, а не с `sda`?_

**Ответ:** Это зависит от интерфейса подключения:

- **SATA/USB/SCSI** — диски обозначаются как `sda`, `sdb` и т.д.
- **NVMe** — диски обозначаются как `nvme0n1`, `nvme0n1p1` и т.д.

Например, у пользователя с SSD в системе может не быть `sda` вообще — он будет только на флешке.

---

### 11.3. Что такое GiB и GB?

**Вопрос:** _В чём разница между GiB и GB?_

**Ответ:**

- **GB (Gigabyte)** — метрическая единица, 1 GB = 1000 МБ.
- **GiB (Gibibyte)** — двоичная единица, 1 GiB = 1024 МБ.

Это важно для понимания размеров дисков. Например, диск на 25 GiB будет иметь размер 26 843 545 600 байт, а не 25 000 000 000.

---

### 11.4. Почему `du -i` не работает?

**Вопрос:** _Почему команда `du -i` не существует?_

**Ответ:** Ключа `-i` для команды `du` не существует. `du` предназначена для оценки размера директорий, а `df -i` — для просмотра использования inodes. Это разные команды.

> **Важное уточнение:** Ключ `-i` существует только у `df` (`df -i`). У `du` есть ключ `-s` (summary) для вывода только итогового размера.

---

### 11.5. Что делает `mount -h`?

**Вопрос:** _Команда `mount -h` — это просмотр дисков?_

**Ответ:** Нет. `mount -h` — это то же самое, что и `mount --help` (вызов справки). Для просмотра смонтированных файловых систем используйте `mount` без аргументов.

## 12. Лимиты, оптимизация и масштабирование

- **`df` vs `du`:** `df` показывает свободное место на смонтированных разделах, `du` — размер директорий. Для диагностики лучше использовать `df`.
- **`fdisk` vs `gdisk`:** `fdisk` работает с MBR, `gdisk` — с GPT. Для современных дисков (больше 2 ТБ) лучше использовать `gdisk`.
- **`lsblk` vs `mount`:** `lsblk` даёт наглядное древовидное отображение, `mount` — много информации, но удобно фильтровать через `grep`.
- **`cfdisk`:** Утилита с интерактивным интерфейсом, удобнее для новичков.

## 14. Влияние на смежные системы и компоненты

### 14.1. Зависимости

- **Диагностика:** Команды `df`, `du`, `lsblk` используются для диагностики проблем с дисковым пространством. Например, если `df -h` показывает 100% заполнение, это может указывать на необходимость очистки или расширения раздела.
- **Автоматизация:** Команды `df`, `du` часто используются в скриптах мониторинга для оповещения о заполнении дисков.

### 14.2. Влияние на производительность

- **Частое выполнение `du`** на больших директориях может увеличить нагрузку на диск и замедлить работу системы.
- **`fdisk` и `gdisk`** — это утилиты, которые при неправильном использовании могут повредить таблицу разделов, что приведёт к **полной потере данных**.
- **`lsblk`** — лёгкая команда, не создаёт значительной нагрузки на систему.

### 14.3. Влияние на безопасность

- **Прямой доступ к устройству** (`cat /dev/sda`) — опасная операция, так как можно случайно повредить данные. Дополнительно: при просмотре сырых данных можно наткнуться на фрагменты паролей или ключей, что создаёт риск утечки конфиденциальной информации.
- **Неправильное использование `fdisk`/`gdisk`** может повредить таблицу разделов и привести к потере данных. Всегда создавайте резервные копии перед работой.
- **Несанкционированный доступ:** команды `fdisk` и `gdisk` требуют прав `root`, что ограничивает круг лиц, способных их выполнять.

## 15. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Прямой доступ к устройству:** `cat /dev/sda` — опасная операция, так как можно случайно повредить данные или столкнуться с фрагментами паролей и ключей шифрования. Важно помнить, что сам факт просмотра не опасен, но если данные выводятся на экран или пишутся в лог сессии, это уже утечка.
- **Неправильное использование `fdisk`/`gdisk`:** может привести к повреждению таблицы разделов и потере данных. Всегда используйте резервные копии.
- **Несанкционированный доступ:** команды `fdisk` и `gdisk` требуют прав `root`, поэтому доступ к ним ограничен, что снижает риск случайного изменения.
- **Логирование:** если вы работаете с `sudo`, действия логируются, что помогает отследить несанкционированные изменения.

### 2. Инженерный FAQ

**Вопрос:** _Почему опасно просматривать сырые, бинарные данные (`cat /dev/sda`)?_

**Ответ:** Это опасно по нескольким причинам:
1. Риск случайно что-то изменить.
2. Можно наткнуться на фрагменты паролей, ключей шифрования.
3. Если диск активно читается/записывается операционной системой, данные могут быть повреждены.

> **Важное уточнение:** «Фрагменты паролей и ключей» — это не опасность для системы, а проблема утечки конфиденциальных данных. Сам факт просмотра не опасен, опасно если кто-то смотрит на экран или пишется лог сессии. **Дополнительно:** Если диск активно читается/записывается операционной системой, данные могут быть повреждены.

**Вопрос:** _Чем отличаются `ext4` и `tmpfs`?_

**Ответ:** `ext4` — это раздел на жёстком диске, а `tmpfs` — временное файловое хранилище в оперативной памяти. Они **не являются синонимами** и используются для разных целей.

**Вопрос:** _Что такое GiB и GB?_

**Ответ:** GiB (Gibibyte) — это 1024 МБ (двоичная единица), а GB (Gigabyte) — это 1000 МБ (метрическая единица). Это важно для понимания размеров дисков.

**Вопрос:** _Что такое `cfdisk` и чем он лучше `fdisk`?_

**Ответ:** `cfdisk` — утилита с интерактивным интерфейсом для работы с таблицей разделов. Многим администраторам она нравится больше, чем `fdisk`, из-за более удобного интерфейса. `cfdisk` позволяет работать с диском через меню, что снижает риск ошибочных действий.

**Вопрос:** _Почему в Debian без `sudo` команды `fdisk` и `gdisk` не открываются?_

**Ответ:** Это связано с тем, что доступ к таблице разделов требует прав `root`. В Debian по умолчанию `sudo` не установлен, поэтому для выполнения этих команд необходимо использовать `su -` или установить `sudo` (`apt install sudo`).
