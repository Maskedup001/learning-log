# Тема 9.2: Монтирование диска

В данной теме рассматривается полный цикл подключения нового диска в Linux: от добавления виртуального диска в VirtualBox до создания раздела, файловой системы, монтирования и настройки автоматического монтирования через `/etc/fstab`. Разбираются команды `gdisk`, `mkfs`, `mount`, `umount`, а также вопросы безопасности и восстановления системы при ошибках конфигурации.

---

## 1. Подготовка нового диска в VirtualBox — Базовые свойства

- **Контекст/Уровень:** Виртуализация / Виртуальные машины / Хранилище.
- **Основное назначение:** Добавление дополнительного дискового пространства для виртуальной машины.
- **Принцип работы:** Для добавления нового диска необходимо остановить виртуальную машину, затем в настройках перейти в раздел **Носители** (Storage) и нажать кнопку добавления жёсткого диска. Выбрать **Создать**, тип диска **VDI**, размер — **20 ГБ**. После этого запустить машину.

### 1.1. Обнаружение нового диска

После запуска проверяем наличие диска:

```bash
lsblk
```

Появляется устройство `sdb` размером 20 ГБ. Также его можно увидеть в `/dev`:

```bash
ls /dev/sd*
```

> **Важное замечание:** Тип диска VDI является проприетарным форматом VirtualBox. Он плохо переносится в VMware — при конвертации VDI в VMDK могут возникнуть проблемы с запуском графических систем. Для лучшей совместимости рекомендуется использовать формат **VMDK**.

---

## 2. Создание раздела — `gdisk`

Для работы с диском необходимо создать раздел. Используем `gdisk` (современная альтернатива `fdisk` для GPT):

```bash
sudo gdisk /dev/sdb
```

### 2.1. Интерактивные команды

| Команда | Описание |
| :--- | :--- |
| `?` | Справка |
| `n` | Создать новый раздел |
| `w` | Записать изменения и выйти |
| `q` | Выйти без сохранения |
*Таб. 1. Интерактивные команды `gdisk`.*

### 2.2. Пошаговое создание раздела

1. **Номер раздела:** `1` (Enter)
2. **Первый сектор:** Enter (значение по умолчанию)
3. **Последний сектор:** Enter (на весь диск)
4. **Тип раздела:** `8300` (Linux filesystem) — Enter
5. **Запись:** `w`
6. **Подтверждение:** `Y`

После этого в выводе `lsblk` появляется раздел `sdb1`.

> **Важное замечание:** Если вы случайно ввели неправильные значения, можно выйти без сохранения, нажав `q`. Изменения не будут применены.

---

## 3. Создание файловой системы — `mkfs`

На созданном разделе необходимо создать файловую систему:

```bash
sudo mkfs.ext4 /dev/sdb1
```

> **Важное уточнение:** `mkfs` — это **обёртка (wrapper)** над специализированными утилитами для создания файловых систем. Когда вы запускаете команду `mkfs`, она **не выполняет всю работу самостоятельно**, а вызывает соответствующую утилиту для конкретного типа файловой системы. Например:
> - `mkfs -t ext4 /dev/sdb1` фактически вызывает утилиту `mke2fs` (которая является реализацией `mkfs.ext4`).
> - `mkfs.xfs` запускает соответствующую программу для XFS.
>
> Таким образом, `mkfs` служит **удобным интерфейсом**, который принимает общие параметры (тип файловой системы, опции) и передаёт их специализированной утилите. Чтобы увидеть список доступных специализированных утилит, можно набрать `mkfs` и затем дважды нажать клавишу `Tab` — система покажет варианты (например, `mkfs.ext4`, `mkfs.xfs`, `mkfs.btrfs`).
>
> **Операция `mkfs` уничтожает все данные** на разделе. Перед выполнением убедитесь, что вы указали правильный раздел.

## 4. Монтирование раздела

### 4.1. Создание точки монтирования

Точка монтирования создаётся в папке `/mnt`:

```bash
sudo mkdir /mnt/newdrive
```

> **Важное уточнение:** Точки монтирования для новых дисков обычно создаются в каталоге `/mnt/`. Это стандартный каталог для временного монтирования файловых систем.

### 4.2. Ручное монтирование

```bash
sudo mount /dev/sdb1 /mnt/newdrive
```

После этого команда `df -h` отобразит новый раздел.

### 4.3. Настройка прав доступа

По умолчанию новый раздел доступен только `root`. Чтобы обычные пользователи могли записывать файлы, необходимо изменить права:

```bash
sudo chmod o+w /mnt/newdrive
```

Теперь все пользователи могут писать на новый диск.

> **Важное замечание:** Команда `chmod o+w` добавляет право записи для остальных пользователей (`others`). Альтернативные варианты:
> - `sudo chmod u+s` — устанавливает SUID-бит для владельца.
> - `sudo chmod o+w` — даёт право записи всем остальным пользователям.
>
> **Дополнительно:** Если на диске хранятся чувствительные данные, лучше использовать более строгие права, например:
> - `sudo chmod 755 /mnt/newdrive` — чтение для всех, запись только для владельца.
> - `sudo chmod 750 /mnt/newdrive` — доступ только для владельца и группы.

## 5. Итоговый цикл подключения нового диска

| Шаг | Команда / Действие |
| :--- | :--- |
| 1 | Добавить диск в VirtualBox (выключенная ВМ) |
| 2 | `lsblk` — убедиться, что диск (`sdb`) обнаружен |
| 3 | `sudo gdisk /dev/sdb` — создать раздел (`n`, `w`) |
| 4 | `sudo mkfs.ext4 /dev/sdb1` — создать файловую систему |
| 5 | `sudo mkdir /mnt/newdrive` — создать точку монтирования |
| 6 | `sudo mount /dev/sdb1 /mnt/newdrive` — примонтировать |
| 7 | `sudo chmod o+w /mnt/newdrive` — дать права на запись |
*Таб. 2. Полный цикл подключения нового диска.*

> **Важное уточнение:** После перезагрузки монтирование нужно будет выполнить заново (если не прописано в `/etc/fstab`).

---

## 6. Проблема: диск не сохраняется после перезагрузки

После ручного монтирования диск доступен только до перезагрузки системы. При перезагрузке (`reboot`) раздел размонтируется, и его нужно монтировать заново:

```bash
sudo mount /dev/sdb1 /mnt/newdrive
```

Файлы на диске при этом сохраняются, но точка монтирования восстанавливается только после повторного выполнения команды.

> **Важное уточнение:** Диск автоматически размонтируется при перезагрузке системы — это нормальное поведение. Файловая система при этом **не повреждается**, а команда `df` не кэширует данные.

---

## 7. Автоматическое монтирование — файл `/etc/fstab`

Чтобы диск монтировался автоматически при загрузке системы, необходимо добавить запись о нём в файл `/etc/fstab`.

### 7.1. Создание резервной копии

Перед редактированием рекомендуется сделать копию файла:

```bash
sudo cp /etc/fstab /etc/fstab.backup
```

### 7.2. Получение UUID раздела

Для надёжной идентификации раздела используется его **UUID** (Universally Unique Identifier):

```bash
lsblk -f
```

В выводе виден UUID для каждого раздела (например, для `sdb1`).

> **Важное замечание:** Альтернативная команда для просмотра UUID — `blkid`. Она компактнее для просмотра UUID, но `lsblk -f` даёт лучшее понимание структуры дисков. Стоит знать обе команды и выбирать под конкретную задачу:
> - `blkid` — удобнее для скриптов.
> - `lsblk -f` — удобнее для работы руками.

### 7.3. Редактирование `/etc/fstab`

```bash
sudo nano /etc/fstab
```

**Формат одной строки:**

```
UUID=<значение>  <точка_монтирования>  <тип_ФС>  <опции>  <dump>  <pass>
```

**Пример добавленной строки:**

```
UUID=12345678-1234-1234-1234-123456789abc /mnt/newdrive ext4 defaults,nofail 0 2
```

### 7.4. Разбор полей `/etc/fstab`

| Поле | Значение | Описание |
| :--- | :--- | :--- |
| 1 | `UUID=...` | Идентификатор раздела |
| 2 | `/mnt/newdrive` | Точка монтирования |
| 3 | `ext4` | Тип файловой системы |
| 4 | `defaults,nofail` | Опции: `nofail` позволяет системе загружаться даже при ошибках монтирования |
| 5 | `0` | Dump (резервное копирование) — отключено |
| 6 | `2` | Порядок проверки `fsck` (1 — root, 2 — остальные разделы) |
*Таб. 3. Разбор полей `/etc/fstab`.*

> **Важное уточнение:** `fstab` (File System Table) — это конфигурационный файл в операционных системах Unix и Linux, который используется для определения, какие файловые системы следует автоматически монтировать при запуске системы. Основные функции:
> - **Автоматическое монтирование** — указывает, какие файловые системы будут монтироваться при старте системы.
> - **Упрощение администрирования** — все параметры указаны в одном месте.
> - **Настройки безопасности** — может предоставлять уровень доступа к различным файловым системам.

## 8. Проверка конфигурации

После добавления записи необходимо проверить корректность:

### 8.1. Размонтировать диск (если он был примонтирован)

```bash
sudo umount /mnt/newdrive
```

Проверить: `df -h` — диск должен отсутствовать.

### 8.2. Смонтировать всё по fstab

```bash
sudo mount -a
```

Ключ `-a` (all) монтирует все файловые системы, указанные в `/etc/fstab`.

### 8.3. Проверить результат

```bash
df -h
```

Диск должен появиться в списке.

> **Важное замечание:** Если команда `mount -a` не выводит ошибок, а диск не появился, возможно, в записи есть ошибка (например, неверный UUID или путь).

---

## 9. Симуляция ошибки и восстановление

Если в `/etc/fstab` допущена ошибка (например, удалён один символ в UUID), система всё равно может загрузиться (благодаря опции `nofail`), но диск не примонтируется.

### 9.1. Порядок исправления

1. Отредактировать `/etc/fstab`, исправив ошибку.
2. Выполнить `sudo mount -a` для проверки.
3. Убедиться, что диск появился в `df -h`.

### 9.2. Типичная ошибка при выполнении `sudo mount -a`

```bash
mount: (hint) your fstab has been modified, but systemd still uses the old version; use 'systemctl daemon-reload' to reload.
```

**Решение:** Ввести в терминал:

```bash
systemctl daemon-reload
```

И затем опять выполнить:

```bash
sudo mount -a
```

## 10. Контрольные вопросы

### Вопрос 1. Какими командами можно создать раздел на новом диске в Linux? (выберите все правильные варианты)

- `mkfs`
- `lsblk`
- `mount`
- `gdisk`
- `umount`
- `df`
- `fdisk`

**Пояснение:** Раздел на новом диске создаётся командами `gdisk` (для GPT) или `fdisk` (для MBR). Команда `mkfs` создаёт файловую систему, а `mount` монтирует раздел.

### Вопрос 2. Где обычно создают точки монтирования для новых дисков?

- В системных логах
- В кэше приложений
- В каталоге `/mnt/`
- В домашней папке пользователя

**Пояснение:** Точки монтирования для новых дисков обычно создаются в каталоге `/mnt/` — это стандартное место для временного монтирования файловых систем.

### Вопрос 3. Какую команду используют для просмотра блочных устройств после добавления нового диска?

- `mkfs --list`
- `mount -l`
- `gdisk -L`
- `lsblk`

**Пояснение:** `lsblk` — команда для просмотра блочных устройств (дисков и разделов) в виде древовидной структуры.

### Вопрос 4. Почему после перезагрузки системы новый раздел диска перестает отображаться в `df -h`?

- Файловая система повреждается
- Команда `df` кэширует данные
- Диск автоматически размонтируется
- Диск физически отключается

**Пояснение:** После перезагрузки системы раздел автоматически размонтируется. Это нормальное поведение — файловая система не повреждается, а `df` не кэширует данные.

### Вопрос 5. В каком файле нужно прописать автоматическое монтирование диска при загрузке?

- `/etc/fstab`
- `/var/log/mount.log`
- `~/.bashrc`
- `/dev/disk.conf`

**Пояснение:** Файл `/etc/fstab` содержит конфигурацию автоматического монтирования файловых систем при загрузке системы.

### Вопрос 6. Для какой из перечисленных команд справедливы следующие утверждения?

- Применяется после ручного редактирования `/etc/fstab`, чтобы применить изменения без перезагрузки.
- Автоматически выполняется при загрузке системы для монтирования всех файловых систем, указанных в файле `/etc/fstab` (с опцией `auto`).

- `sudo mount -a`
- `sudo mount --all`
- `sudo automount`
- `sudo fstab mount`

**Пояснение:** `sudo mount -a` монтирует все файловые системы, указанные в `/etc/fstab`. Ключ `-a` (all) применяет изменения без перезагрузки.

### Вопрос 7. Какую команду используют для размонтирования диска?

- `detach`
- `mount -u`
- `umount`
- `unmount`

**Пояснение:** Команда `umount` (не `unmount`) используется для размонтирования файловой системы.

## 11. Разбор сложных инженерных ситуаций, граничных кейсов и аномалий

### 11.1. Проблема: система не загружается из-за ошибки в `/etc/fstab`

**Вопрос:** _Если в `/etc/fstab` допущена ошибка без опции `nofail`, система может не загрузиться. Что делать?_

**Ответ:** Если система не загружается, необходимо войти в режим восстановления (recovery mode) или загрузиться с LiveCD, затем:
1. Закомментировать проблемную строку в `/etc/fstab`.
2. Исправить ошибку.
3. Перезагрузиться.

> **Важное уточнение:** Проблема с этим монтированием в том, что если что-то случится с диском, система не будет грузиться. Люди, которые не понимают, что написано на чёрном экране, начинают паниковать. Именно поэтому опция `nofail` так важна — она позволяет системе загружаться даже при ошибках монтирования.

> **Важное уточнение:** Пользователи должны понимать, как исправить ошибки в `/etc/fstab`, чтобы их ОС снова загрузилась. Если система не загружается, необходимо:
> 1. Загрузиться в режиме восстановления (recovery mode) или с LiveCD.
> 2. Открыть `/etc/fstab` и закомментировать проблемную строку (добавить `#` в начало).
> 3. Перезагрузиться.
> 4. После успешной загрузки исправить ошибку и удалить `#`.

### 11.2. Проблема: `systemctl daemon-reload` после изменения `/etc/fstab`

**Вопрос:** _Что делать, если при выполнении `sudo mount -a` появляется ошибка о том, что systemd использует старую версию fstab?_

**Ответ:** Необходимо выполнить:

```bash
systemctl daemon-reload
```

Затем повторить:

```bash
sudo mount -a
```

### 11.3. Сравнение `blkid` и `lsblk -f` для получения UUID

| Команда | Что показывает | Когда использовать |
| :--- | :--- | :--- |
| `blkid` | Компактный вывод UUID | Для скриптов и автоматизации |
| `lsblk -f` | Древовидное отображение с UUID | Для работы руками и понимания структуры |
*Таб. 4. Сравнение `blkid` и `lsblk -f`.*

> **Важное уточнение:** `blkid` — удобная команда для просмотра UUID. Обе команды полезны, стоит знать обе и выбирать под конкретную задачу.

### 11.4. Проблема: расширение корневого раздела

**Вопрос:** _Как расширить корневой раздел (/) на виртуальной машине?_

**Ответ:** Для расширения корневого раздела необходимо:
1. Добавить дополнительное пространство в VirtualBox (увеличить размер диска).
2. Использовать `gdisk` для изменения размеров разделов.
3. Применить изменения через `resize2fs` для файловой системы `ext4`.

> **Важное уточнение:** Эта операция требует особой осторожности — ошибка может привести к потере данных. Рекомендуется делать резервную копию перед началом.

## 12. Лимиты, оптимизация и масштабирование

- **VDI vs VMDK:** Формат VDI плохо переносится в VMware. Для лучшей совместимости рекомендуется использовать VMDK.
- **`mount -a` vs `reboot`:** `mount -a` позволяет применить изменения без перезагрузки, что экономит время и ресурсы.
- **`nofail` опция:** Критически важна для предотвращения проблем с загрузкой системы при ошибках монтирования.
- **Использование UUID:** Предпочтительнее использования имени устройства (`/dev/sdb1`), так как UUID стабилен и не зависит от порядка подключения дисков.

## 13. Альтернативные сценарии и сравнение подходов

### 13.1. `gdisk` vs `fdisk`

| Команда | Формат таблицы разделов | Когда использовать |
| :--- | :--- | :--- |
| `gdisk` | Только GPT | Для современных дисков (больше 2 ТБ) |
| `fdisk` | MBR и GPT | Для старых дисков, быстрого просмотра |
*Таб. 5. Сравнение `gdisk` и `fdisk`.*

> **Важное уточнение:** `gdisk` — утилита, **оптимизированная для GPT**, но может работать и с MBR (с ограничениями). `fdisk` — универсальная утилита, работает и с MBR, и с GPT.

### 13.2. `mount` vs `udisksctl`

| Команда     | Что делает                                           | Когда использовать                            |
| :---------- | :--------------------------------------------------- | :-------------------------------------------- |
| `mount`     | Ручное монтирование                                  | Для точного контроля над точкой монтирования  |
| `udisksctl` | Автоматическое создание временных точек монтирования | Для быстрого монтирования без ручных настроек |
*Таб. 6. Сравнение `mount` и `udisksctl`.*

> **Важное уточнение:** `udisksctl` автоматически создаёт временные точки монтирования и монтирует диск. Это удобно для быстрого доступа к данным, но не подходит для постоянного монтирования.

### 13.3. `chmod o+w` vs `chmod u+s`

| Команда | Что делает | Когда использовать |
| :--- | :--- | :--- |
| `chmod o+w` | Даёт право записи всем остальным пользователям | Для общего доступа |
| `chmod u+s` | Устанавливает SUID-бит для владельца | Для специфических задач с привилегиями |
*Таб. 7. Сравнение `chmod o+w` и `chmod u+s`.*

## 14. Влияние на смежные системы и компоненты

### 14.1. Зависимости

- **`/etc/fstab`** — влияет на загрузку системы. Ошибки в этом файле могут привести к невозможности загрузки.
- **`systemd`** — использует `/etc/fstab` для монтирования файловых систем при загрузке. Изменения требуют `systemctl daemon-reload`.
- **`mount`** — влияет на доступность файловых систем для пользователей и процессов.

### 14.2. Влияние на производительность

- **`mkfs.ext4`** — операция создания файловой системы может занять время на больших дисках.
- **`mount -a`** — монтирование всех файловых систем при загрузке может замедлить старт системы, если некоторые разделы недоступны (например, внешние диски).

### 14.3. Влияние на безопасность

- **Неправильная конфигурация монтирования** может привести к потере доступа к данным или непредсказуемому поведению системы при загрузке.
- **Прямой доступ к устройству** (`cat /dev/sdb`) — опасная операция, так как можно повредить данные или столкнуться с фрагментами паролей и ключей шифрования.

## 15. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Неправильные права доступа:** `chmod o+w` даёт доступ на запись всем пользователям. Если диск содержит чувствительные данные, это может привести к их несанкционированному изменению или удалению.
- **Ошибки в `/etc/fstab`:** Могут привести к отказу загрузки системы (DoS-атака на доступность).
- **Использование имени устройства вместо UUID:** Если диски подключаются в разном порядке, имя устройства может измениться, что приведёт к монтированию неправильного раздела.

### 2. Инженерный FAQ

**Вопрос:** _Чем VDI отличается от VMDK и почему VDI плохо переносится в VMware?_

**Ответ:** VDI — проприетарный формат VirtualBox. VMDK — формат VMware. При конвертации VDI в VMDK могут возникнуть проблемы с запуском графических систем. Для лучшей совместимости рекомендуется сразу использовать VMDK.

**Вопрос:** _Что такое `udisksctl` и чем он удобнее `mount`?_

**Ответ:** `udisksctl` автоматически создаёт временные точки монтирования и монтирует диск. Это удобно для быстрого доступа к данным без ручных настроек. Однако для постоянного монтирования лучше использовать `mount` с записью в `/etc/fstab`.

**Вопрос:** _Что делать, если при `sudo mount -a` появляется ошибка "your fstab has been modified, but systemd still uses the old version"?_

**Ответ:** Выполнить `systemctl daemon-reload`, затем повторить `sudo mount -a`. Это обновит конфигурацию systemd.

**Вопрос:** _Почему использование UUID предпочтительнее имени устройства (`/dev/sdb1`) в `/etc/fstab`?_

**Ответ:** UUID стабилен и не зависит от порядка подключения дисков. Имя устройства может измениться при изменении порядка подключения, что приведёт к монтированию неправильного раздела или отказу загрузки.

## Заключение

Полный цикл подключения нового диска в Linux включает создание раздела (`gdisk`), файловой системы (`mkfs.ext4`), монтирование (`mount`) и настройку автоматического монтирования (`/etc/fstab`). Правильное использование UUID и опции `nofail` критически важно для предотвращения проблем с загрузкой системы. Понимание различий между форматами дисков (VDI, VMDK) и командами (gdisk, fdisk, mount, udisksctl) позволяет выбрать оптимальный подход для конкретной задачи.
