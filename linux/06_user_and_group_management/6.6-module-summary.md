# Тема 6.6: Резюме модуля «Управление пользователями». Контрольные вопросы

В данной теме представлены контрольные вопросы для самопроверки по модулю «Управление пользователями». Вопросы охватывают команды для получения информации о пользователях (`id`, `groups`, `whoami`), переключение на суперпользователя (`sudo su`, `su root`, `sudo -i`), создание пользователей (`useradd`, `adduser`), управление паролями (`passwd`), блокировку учётных записей (`usermod -L`), а также файлы конфигурации (`/etc/shadow`, `/etc/sudoers`). Каждый вопрос сопровождается правильным ответом, техническим пояснением и разбором ошибочных вариантов. В конце приведён разбор типичных вопросов и практических кейсов из комментариев.

---

## 1. Контрольные вопросы (с разбором)

### Вопрос 1. Какая команда выведет следующую информацию о пользователе: UID, GID, список групп?

**Варианты:**
- `id`
- `who`
- `groups`
- `whoami`

**Правильный ответ:** `id`.

**Пояснение:** Команда `id` выводит полную информацию о пользователе: UID, GID и список групп с их идентификаторами. `groups` показывает только названия групп, `whoami` — только имя текущего пользователя, `who` — информацию о активных сессиях.

**Разбор ошибочных вариантов:**
- `who` — показывает информацию об активных сессиях, не о группах.
- `groups` — показывает только названия групп, без UID и GID.
- `whoami` — показывает только имя текущего пользователя.

---

### Вопрос 2. Какая (какие) из перечисленных команд позволяют переключиться в режим суперпользователя?

**Варианты:**
- `sudo su`
- `su root`
- `su sudo`
- `user root`

**Правильный ответ:** `sudo su` и `su root`.

**Пояснение:** Обе команды позволяют переключиться на root:
- `su root` — запрашивает пароль root и переключает на него.
- `sudo su` — использует права текущего пользователя (если он в группе `sudo`) и переключает на root без запроса пароля root.

**Важное замечание:** Вопрос предполагает выбор **всех** подходящих вариантов. `su sudo` и `user root` не являются корректными командами.

**Разбор ошибочных вариантов:**
- `su sudo` — неверная команда (нет такой).
- `user root` — неверная команда (нет такой).

> **Примечание:** В реальной практике часто используется также команда `sudo -i`, но в данном тесте она не предлагается в вариантах. Если бы она была, её тоже следовало бы выбрать как подходящий вариант.

### Вопрос 3. Какая команда при создании пользователя позволит сразу задать ему пароль?

**Варианты:**
- `sudo useradd -s /bin/bash -m -d outgoinghr`
- `sudo adduser outgoinghr`
- `sudo useradd -s /bin/bash outgoinghr`
- Все приведенные варианты.

**Правильный ответ:** `sudo adduser outgoinghr`.

**Пояснение:** `adduser` — это интерактивная обёртка, которая при создании пользователя сразу запрашивает пароль и **автоматически создаёт домашний каталог**, в отличие от `useradd`, где это нужно указывать отдельно ключом `-m`. `useradd` (даже с ключами `-s`, `-m`, `-d`) создаёт пользователя без пароля — его нужно устанавливать отдельно через `sudo passwd username`.

**Разбор ошибочных вариантов:**
- `sudo useradd -s /bin/bash -m -d outgoinghr` — создаёт пользователя без пароля.
- `sudo useradd -s /bin/bash outgoinghr` — создаёт пользователя без пароля.
- «Все приведенные варианты» — неверно, так как `useradd` не задаёт пароль.

### Вопрос 4. Какая команда сменит пароль пользователю officemanager?

**Варианты:**
- `sudo passwd officemanager`
- `sudo useradd officemanager`
- `sudo officemanager`
- `su officemanager`

**Правильный ответ:** `sudo passwd officemanager`.

**Пояснение:** Команда `passwd` используется для установки и смены паролей. С префиксом `sudo` она меняет пароль указанного пользователя. Остальные варианты либо создают пользователя, либо не являются корректными командами.

**Разбор ошибочных вариантов:**
- `sudo useradd officemanager` — создаёт нового пользователя, не меняет пароль.
- `sudo officemanager` — неверная команда (нет такой).
- `su officemanager` — переключает на пользователя, не меняет пароль.

### Вопрос 5. В каком файле хранятся хэши паролей пользователей?

**Варианты:**
- `/etc/shadow`
- `/bin/bash`
- `/etc/passwd`
- `/etc/group`

**Правильный ответ:** `/etc/shadow`.

**Пояснение:** Файл `/etc/shadow` содержит хэши паролей пользователей и доступен только для root. `/etc/passwd` содержит основную информацию о пользователях, но пароли там не хранятся (только признак `x`).

**Разбор ошибочных вариантов:**
- `/bin/bash` — это файл командной оболочки.
- `/etc/passwd` — содержит информацию о пользователях, но не пароли.
- `/etc/group` — содержит информацию о группах.

---

### Вопрос 6. Какая команда заблокирует пользователя smileygirl?

**Варианты:**
- `sudo usermod –U smileygirl`
- `su smileygirl`
- `sudo adduser smileygirl`
- `sudo usermod –L smileygirl`

**Правильный ответ:** `sudo usermod –L smileygirl`.

**Пояснение:** Ключ `-L` (lock) блокирует учётную запись пользователя. Ключ `-U` (unlock) разблокирует. `adduser` создаёт пользователя, `su` переключает на него.

**Разбор ошибочных вариантов:**
- `sudo usermod –U smileygirl` — разблокирует, а не блокирует.
- `su smileygirl` — переключает на пользователя, не блокирует.
- `sudo adduser smileygirl` — создаёт нового пользователя.

---

### Вопрос 7. Членство пользователя в группе sudo дает ему права root. Редактирование какого файла позволит это изменить (привилегии для групп)?

**Варианты:**
- `/etc/shadow`
- `/etc/passwd`
- `/etc/users`
- `/etc/sudoers`

**Правильный ответ:** `/etc/sudoers`.

**Пояснение:** Файл `/etc/sudoers` содержит правила, определяющие, кто и какие команды может выполнять с `sudo`. В нём можно изменить привилегии для групп (например, для `%sudo`).

**Разбор ошибочных вариантов:**
- `/etc/shadow` — содержит хэши паролей, не права sudo.
- `/etc/passwd` — содержит информацию о пользователях.
- `/etc/users` — неверный файл (нет такого).

---

### Вопрос 8. Напишите команду, выводящую список групп пользователя root.

**Правильный ответ:** `groups root`.

**Пояснение:** Команда `groups root` выводит список групп, в которые входит пользователь root. Она не требует `sudo`, так как информация о группах является общедоступной.

**Альтернативные способы (не являются обязательными, но технически верны):**
- `id root` — выводит UID, GID и группы с идентификаторами.
- `id -Gn root` — выводит только названия групп (без UID/GID).
- `sudo groups root` — технически работает, но `sudo` здесь не требуется.
- `echo root : root` — некорректно (это просто текст, а не вывод команды).

## 2. Разбор сложных ситуаций и типичных вопросов

### 2.1. Разница между `su root`, `sudo su`, `sudo -i` и `su -`

**Вопрос:** *В чём разница между командами `su root`, `sudo su`, `sudo -i` и `su -`?*

**Ответ:** Это четыре разных подхода к переключению на root. Хотя результат (оболочка root) кажется одинаковым, механизм проверки прав и поведение окружения различаются.

**`su root` (Switch User):**
- **Логика:** «Я знаю секретный пароль главного администратора и хочу им стать».
- **Проверка:** Сверяется с паролем из `/etc/shadow`, который установлен для root.
- **Проблема:** Если пароль root не задан, войти нельзя.
- **Особенность:** Переключает на root и даёт полный доступ, пока пользователь не выйдет.

**`sudo su` (SuperUser Do + Switch User):**
- **Логика:** «Я (обычный пользователь) имею разрешение от системы (sudo) запустить программу переключения пользователя (su)».
- **Проверка:** Система спрашивает **твой** пароль (чтобы убедиться, что это ты), а затем, видя, что ты в группе `sudo`, даёт тебе права root «бесплатно», не спрашивая пароль самого root.
- **Особенность:** Сохраняет переменные окружения текущего пользователя.

**`sudo -i`:**
- **Логика:** Запускает оболочку root с полной инициализацией окружения root.
- **Особенность:** Сбрасывает все переменные окружения пользователя, загружает профиль root. Имитирует вход в систему как root.
- **Преимущество:** Считается более безопасным и предсказуемым.

**`su -`:**
- **Логика:** Переключается на root и загружает его полное окружение (домашний каталог `/root`, профиль, переменные окружения).
- **Особенность:** Эквивалентно входу в систему как root.

**Сравнительная таблица:**

| Команда | Что делает | Логика проверки | Окружение | Особенности |
| :--- | :--- | :--- | :--- | :--- |
| `su root` | Переключение на root | «Я знаю пароль root» — сверка с `/etc/shadow` | Сохраняет текущее | Требует пароль root. В Ubuntu не работает по умолчанию. |
| `sudo su` | Переключение на root через sudo | «Я имею разрешение от системы запустить `su`» — спрашивает **твой** пароль | Сохраняет переменные окружения | Может привести к неожиданным последствиям. |
| `sudo -i` | Запуск оболочки root с инициализацией | Проверяет права в `sudoers` (твой пароль или `NOPASSWD`) | Полностью сбрасывает, загружает профиль root | Безопасный и предсказуемый вариант. |
| `su -` | Переключение на root с полным входом | «Я вхожу как root» — требует пароль root | Загружает полное окружение root | Эквивалентно входу в систему как root. |
*Таб. 1. Сравнение команд переключения на root.*

> **Примечание:** Команда `su -` также позволяет переключиться на root с загрузкой полного окружения, но в данном тесте она не предлагалась в вариантах ответов.

> **Рекомендация:** Для получения прав root рекомендуется использовать `sudo -i`. `sudo su` может привести к неожиданным последствиям из-за сохранения переменных окружения. Команда `su root` в большинстве современных дистрибутивов (Ubuntu, Debian) не работает, так как пароль root не задан по умолчанию.

### 2.2. Почему `su root` может не работать в Ubuntu?

**Вопрос:** *Почему команда `su root` не работает, хотя `sudo su` работает?*

**Ответ:** В Ubuntu (и многих других дистрибутивах) пароль для root **не задаётся по умолчанию**. Вместо этого используется механизм `sudo`, позволяющий администратору выполнять команды от имени root. Команда `su root` пытается переключиться на root с использованием его пароля — если он не установлен, команда не сработает.

**Как исправить:** Чтобы установить пароль для root, выполните:
```bash
sudo passwd root
```
После этого `su root` начнёт работать.

> **Дополнительный нюанс:** Если учётная запись root была заблокирована во время установки 
> или настройки, её можно разблокировать командой:
> 
> ```bash
> sudo usermod -U root
> ```

> **Как проверить, заблокирован ли пользователь:**  
> Посмотрите на хэш пароля в `/etc/shadow`:
> 
> ```bash
> sudo cat /etc/shadow | grep username
> ```
> 
> Если в начале хэша стоит `!` (например, `username:!$6$...`), учётная запись заблокирована. Если `!` отсутствует — разблокирована.

> **Важно:** Длина пароля (например, 4 символа) не влияет на возможность использования `su root`, но короткие пароли считаются менее безопасными и могут не соответствовать политикам безопасности некоторых систем.

### 2.3. Всегда ли `sudo` запрашивает пароль?

**Вопрос:** *Всегда ли `sudo` запрашивает пароль?*

**Ответ:** Не всегда. В файле `/etc/sudoers` можно настроить выполнение команд без запроса пароля с помощью директивы `NOPASSWD`. Например:
```
username ALL=(ALL) NOPASSWD: ALL
```

Это часто используется на Live-дистрибутивах, где вход выполняется без пароля, но при этом нужно иметь возможность выполнять команды с `sudo`.

> **Дополнительно:** `sudo` кэширует успешную аутентификацию. По умолчанию это **15 минут**. В течение этого времени повторный вызов `sudo` пароль не запрашивает.

### 2.4. Почему `groups root` не требует `sudo`?

**Вопрос:** *Почему команда `groups root` не требует `sudo`?*

**Ответ:** Команда `groups` читает информацию из общедоступного файла `/etc/group`. Это публичные данные, которые может просматривать любой пользователь системы. Поэтому `sudo` здесь не нужен.

Это важное отличие от команд, которые изменяют систему — `sudo` требуется только для операций, влияющих на конфигурацию или файлы, а не для чтения общедоступной информации.

> **Важное замечание:** Если вы используете `sudo groups root`, технически это тоже работает, но это избыточно и не является правильным решением для этого вопроса.

### 2.5. Почему `sudo useradd` создаёт пользователя без пароля?

**Вопрос:** *Почему `sudo useradd newuser` создаёт пользователя без пароля?*

**Ответ:** `useradd` — это низкоуровневая утилита. Она добавляет запись в `/etc/passwd`, но **не устанавливает пароль**. Пароль нужно задавать отдельно командой `sudo passwd newuser`.

В отличие от неё, `adduser` является **интерактивной обёрткой**, которая:
- вызывает `useradd` под капотом,
- сразу запрашивает пароль,
- автоматически создаёт домашний каталог,
- не оставляет пароль в истории команд.

**Пример:**
```bash
sudo useradd newuser          # создаёт пользователя без пароля
sudo passwd newuser           # теперь задаём пароль
```

### 2.6. Альтернативные способы вывода групп пользователя

**Вопрос:** *Какие ещё команды могут вывести список групп пользователя root?*

**Ответ:** Технически существует несколько способов:
- `id root` — показывает UID, GID и группы с идентификаторами.
- `id -Gn root` — показывает только названия групп.
- `groups root` — показывает группы (правильный ответ для теста).
- `sudo groups root` — тоже работает, но `sudo` не требуется.

> **Важное замечание:** Вывод `id -Gn root` выглядит так: `root`. Ожидаемый ответ в тесте — `root : root`. Поэтому в данном задании правильным считается именно `groups root`.

Ещё один технически верный, но сложный способ:

```bash
id root | awk -F'[=()]' '{print $3 " : " $6}'
```

Этот вариант показывает, что в реальной жизни одну задачу можно решить множеством способов.

### 2.7. Почему `sudo su` считается не лучшим выбором?

**Вопрос:** *Почему `sudo su` считается не лучшим выбором, хотя оно работает?*

**Ответ:** `sudo su` может привести к неожиданным последствиям из-за того, что оно сохраняет переменные окружения текущего пользователя. Это может вызывать конфликты, если окружение root ожидает другие настройки. `sudo -i` считается более безопасным, так как создаёт полностью изолированное окружение root.

> **Совет:** Если вам нужно просто выполнить одну команду от root, используйте `sudo command`. Если нужно полноценное окружение root — используйте `sudo -i`. `sudo su` лучше избегать, так как оно сохраняет переменные окружения, что может вызвать неожиданное поведение.

## 3. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Неправильное редактирование файла sudoers:** Ошибка в этом файле может полностью заблокировать доступ к `sudo` для всех администраторов. Чтобы избежать этого, необходимо всегда использовать `visudo` для проверки синтаксиса перед сохранением.

- **Права доступа к файлу с паролями:** Файл `/etc/shadow` должен быть доступен только суперпользователю. Если права на него будут расширены (например, `chmod 644`), злоумышленник сможет извлечь хэши паролей и попытаться подобрать их.

- **Скрытые учётные записи с нулевым идентификатором:** Злоумышленник может создать учётную запись с UID 0, чтобы получить права root без входа через `sudo`. Важно регулярно проверять наличие таких записей.

### 2. Инженерный FAQ (по безопасности)

- **Вопрос:** Что делать, если я случайно удалил себя из группы `sudo` и потерял доступ?  
  **Ответ:** Если есть другой пользователь с правами `sudo`, попросите его добавить вас обратно в группу. Если доступа нет ни у кого, потребуется загрузиться в режим восстановления или использовать live-носитель.

- **Вопрос:** Почему не рекомендуется указывать пароль прямо в команде создания пользователя?  
  **Ответ:** Передача хэша пароля аргументом команды (например, через `useradd -p`) оставляет его в истории терминала. Любой, кто получит доступ к истории, сможет его перехватить. Безопасный способ — создать пользователя без пароля, а затем установить его через `passwd`.

- **Вопрос:** Как защититься от атак через `sudo`?  
  **Ответ:** Ограничьте доступ к `sudo` только доверенными пользователями и группами, сократите время кэширования пароля, включите журналирование действий через `sudo` (например, `Defaults logfile=/var/log/sudo.log`) и регулярно проверяйте файл `sudoers`.

- **Вопрос:** Как восстановить доступ, если забыт пароль root?  
  **Ответ:** Можно загрузиться в режим восстановления и сменить пароль root, либо использовать live-носитель, примонтировать корневую файловую систему, перейти в неё через `chroot` и сбросить пароль.

| `/etc/shadow`  | Файл с хэшами паролей.                                  |
| `/etc/sudoers` | Файл с правилами sudo.                                  |

## Заключение

Контрольные вопросы охватывают ключевые темы модуля «Управление пользователями»: получение информации о пользователях, переключение на root, создание пользователей, управление паролями и блокировку. Понимание различий между `su root`, `sudo su` и `sudo -i`, а также знание того, что `groups root` не требует `sudo`, являются важными техническими нюансами, которые часто встречаются на практике.
