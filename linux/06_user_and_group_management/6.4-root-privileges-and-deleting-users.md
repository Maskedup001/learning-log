# Тема 6.4: Права root и удаление пользователей

В данной теме рассматриваются права суперпользователя (root) через группу `sudo`, управление членством в этой группе, а также удаление учётных записей пользователей. Разбираются файл конфигурации `/etc/sudoers`, безопасное редактирование через `visudo`, команды `userdel` и `deluser`, а также практические кейсы по поиску и удалению нелегитимных пользователей.

---

## 1. Права root и группа `sudo` — Базовые свойства

- **Контекст/Уровень:** Системное администрирование / Управление пользователями.
- **Основное назначение:** Предоставление и ограничение привилегий суперпользователя (root) через группу `sudo`.
- **Принцип работы:** Возможность выполнять команды с привилегиями суперпользователя (через `sudo`) определяется членством пользователя в группе `sudo` (в дистрибутивах семейства Debian/Ubuntu) или `wheel` (в дистрибутивах семейства RHEL/Rocky Linux, Arch, Fedora).

### 1.1. Проверка групп пользователя

```bash
groups                  # группы текущего пользователя
groups username         # группы указанного пользователя
```

### 1.2. Сравнение пользователей

- Пользователь `itguy` состоит в группе `sudo` → может выполнять команды с `sudo`.
- Пользователь `smileygirl` не состоит в группе `sudo` → при попытке использования `sudo` получает отказ.

**Ошибка при отсутствии прав:**
```
user is not in the sudoers file.  This incident will be reported.
```

> **Группа `wheel` в других дистрибутивах:**  
> В дистрибутивах семейства RHEL (Rocky Linux, CentOS, Fedora) и в Arch Linux для предоставления прав `sudo` используется группа `wheel`, а не `sudo`.  
> **Добавление в группу:**  
> ```bash
> sudo usermod -aG wheel username
> ```
> **Удаление из группы:**  
> ```bash
> sudo gpasswd -d username wheel
> ```
> В таких дистрибутивах группа `sudo` обычно отсутствует по умолчанию.

## 2. Добавление и удаление пользователя из группы `sudo`

### 2.1. Добавление в группу `sudo`

```bash
sudo usermod -a -G sudo username
```

- `-a` (append) — добавить к существующим группам (без этого ключа пользователь будет удалён из всех других дополнительных групп).
- `-G` — указать список дополнительных групп.
- `sudo` — название группы (регистр важен).

> **Частая ошибка с ключами `-a` и `-G`:**  
> Команда `sudo usermod -Ga sudo username` выдаёт ошибку `usermod: group 'a' does not exist`.  
> Это происходит потому, что ключи **должны идти в порядке** `-a -G` или `-aG`. Если написать `-Ga`, команда сначала обрабатывает `-G` и ждёт имя группы, а `a` воспринимает как имя группы, которой не существует.  
> **Правильный вариант:** `sudo usermod -aG sudo username`.

### 2.2. Удаление из группы `sudo`

```bash
sudo deluser username sudo
```

- Первое `sudo` — запуск команды с правами root.
- `deluser` — команда для удаления пользователя из группы.
- Второе `sudo` — название группы, из которой удаляем.

> **Альтернативный способ удаления из группы:** Вместо `deluser` можно использовать `gpasswd -d`:

```bash
sudo gpasswd -d username sudo
```

Или перезаписать группы, оставив только нужные:

```bash
sudo usermod -G <другие_группы> username
```

### 2.3. Проверка после изменений

```bash
groups smileygirl
```

Вывод должен показывать наличие или отсутствие группы `sudo`.

## 3. Файл `/etc/sudoers` — конфигурация прав `sudo`

### 3.1. Просмотр файла

```bash
sudo cat /etc/sudoers
```

### 3.2. Синтаксис

```
user      ALL=(ALL:ALL) ALL
%group    ALL=(ALL:ALL) ALL
```

| Поле | Значение |
| :--- | :--- |
| `user` / `%group` | Пользователь или группа (группа с префиксом `%`). |
| `ALL` (первое) | Хосты, с которых разрешено выполнение. |
| `(ALL:ALL)` | Пользователь и группа, от имени которых можно выполнять команды. |
| `ALL` (последнее) | Список разрешённых команд. |
*Таб. 1. Синтаксис строки в `/etc/sudoers`.*

### 3.3. Примеры строк в `sudoers`

```
root    ALL=(ALL:ALL) ALL
%admin  ALL=(ALL:ALL) ALL
%sudo   ALL=(ALL:ALL) ALL
```

Именно строка `%sudo ALL=(ALL:ALL) ALL` даёт всем членам группы `sudo` права на выполнение любых команд от имени root.

### 3.4. Важные предостережения

- Изменения в `/etc/sudoers` применяются мгновенно после сохранения.
- Ошибка в файле может лишить всех пользователей (включая себя) прав `sudo`.
- Для безопасного редактирования используется команда:

```bash
sudo visudo
```

`visudo` проверяет синтаксис перед сохранением и предотвращает критические ошибки.

> **Дополнительная информация:** Увидеть список привилегий текущего пользователя можно командой `sudo -l`. Она показывает, какие команды разрешены, от чьего имени, требуется ли ввод пароля.

## 4. Удаление пользователей — `userdel`

Команда **`userdel`** (user delete) удаляет учётную запись пользователя.

### 4.1. Базовый синтаксис

```bash
sudo userdel username
```

- Удаляет запись из `/etc/passwd`, `/etc/shadow`, `/etc/group`.
- **Не удаляет** домашний каталог и почтовый ящик пользователя.

### 4.2. Удаление с домашним каталогом — `-r`

```bash
sudo userdel -r username
```

Ключ `-r` (remove) удаляет:
- Домашний каталог пользователя.
- Почтовый ящик (обычно `/var/mail/username`).

### 4.3. Альтернативное удаление через `deluser`

В некоторых дистрибутивах (Debian/Ubuntu) вместо `userdel -r` можно использовать `deluser` с ключом `--remove-home`:

```bash
sudo deluser --remove-home username
```

Это делает то же самое — удаляет пользователя вместе с домашним каталогом.

### 4.4. Пример

```bash
sudo userdel smileygirl              # домашний каталог остаётся
sudo userdel -r bigboss              # домашний каталог удаляется
sudo deluser --remove-home bigboss   # альтернатива
```

### 4.5. Проверка после удаления

```bash
ls /home                             # домашние каталоги
sudo cat /etc/passwd | grep username # запись отсутствует
sudo cat /etc/shadow | grep username # запись отсутствует
sudo cat /etc/group | grep username  # запись отсутствует
```

## 5. Сравнение команд управления пользователями

| Команда | Ключ | Назначение |
| :--- | :--- | :--- |
| `usermod -a -G` | `-a -G` | Добавить пользователя в дополнительные группы. |
| `deluser user group` | — | Удалить пользователя из группы. |
| `gpasswd -d` | `-d` | Удалить пользователя из группы (альтернатива). |
| `userdel` | — | Удалить пользователя (каталог остаётся). |
| `userdel -r` | `-r` | Удалить пользователя вместе с домашним каталогом. |
| `deluser --remove-home` | `--remove-home` | Удалить пользователя вместе с домашним каталогом. |
*Таб. 2. Сравнение команд для управления пользователями.*

## 6. Практические примеры

### 6.1. Предоставление прав `sudo` пользователю

```bash
sudo usermod -a -G sudo smileygirl
groups smileygirl                    # проверка
su - smileygirl                      # переключиться
sudo apt update                      # теперь работает
```

### 6.2. Лишение прав `sudo`

```bash
sudo deluser smileygirl sudo
groups smileygirl                    # группа sudo отсутствует
```

### 6.3. Удаление пользователей

```bash
sudo userdel smileygirl              # удалить, каталог /home/smileygirl остаётся
sudo userdel -r bigboss              # удалить с домашним каталогом
```

## 7. Разбор сложных инженерных ситуаций, граничных кейсов и аномалий

### 7.1. Права sudo в разных дистрибутивах

**Вопрос:** *В некоторых дистрибутивах группа называется не `sudo`, а `wheel`. Почему?*

**Ответ:** В дистрибутивах семейства Debian/Ubuntu используется группа `sudo`. В дистрибутивах семейства RHEL/Rocky Linux (а также в Arch и Fedora) используется группа `wheel`. Синтаксис добавления пользователя в группу остаётся тем же: `sudo usermod -aG wheel username`.

### 7.2. Почему `-Ga` вызывает ошибку?

**Вопрос:** *Почему команда `sudo usermod -Ga sudo username` выдаёт ошибку `usermod: group 'a' does not exist`?*

**Ответ:** Ключи должны идти в правильном порядке. `-a` (append) используется только с `-G` (groups). Правильный синтаксис — `-a -G` или `-aG`. Если написать `-Ga`, команда воспримет `G` как отдельный ключ и будет искать группу с именем `a`, которая не существует.

### 7.3. Как удалить пользователя с домашним каталогом через `deluser`?

**Вопрос:** *Есть ли альтернативный способ удалить пользователя вместе с домашним каталогом, кроме `userdel -r`?*

**Ответ:** Да, можно использовать команду `deluser` с ключом `--remove-home`:
```bash
sudo deluser --remove-home username
```

Это делает то же самое, что и `sudo userdel -r username`, но с другим синтаксисом.

### 7.4. Поиск и обезвреживание нелегитимных пользователей

**Вопрос:** *Как найти и удалить подозрительную учётную запись с правами root?*

**Ответ:** Для поиска и удаления нелегитимных пользователей можно выполнить следующие действия:

```bash
# 1. Найти пользователей с UID 0 (root-права)
awk -F: '($3 == 0) {print $1}' /etc/passwd

# 2. Проверить группы с root-доступом
getent group sudo
getent group wheel

# 3. Найти недавно созданных пользователей
ls -la /home/

# 4. После обнаружения — заблокировать, завершить процессы и удалить
sudo passwd -l username        # заблокировать вход
sudo pkill -u username         # убить все процессы
sudo userdel -r username       # удалить полностью
```

### 7.5. Как предотвратить прямой вход root

**Вопрос:** *Как защититься от злоумышленника, который пытается войти как root?*

**Ответ:** Заблокируйте пароль root:
```bash
sudo passwd -l root
```

После этого вход под root станет невозможным, и все административные действия будут выполняться только через `sudo`.

### 7.6. Экстренная ситуация: что делать, если удалили единственного администратора?

**Вопрос:** *Что делать, если я случайно удалил себя из группы sudo и потерял доступ к системе?*

**Ответ:** Если вы сохранили доступ через другого пользователя с правами sudo, попросите его добавить вас обратно. Если доступа нет, потребуется загрузка в режиме восстановления (recovery mode) или использование live USB.

При загрузке в recovery mode:
1. Выберите в GRUB `Advanced options` → `Recovery mode` → `root`.
2. Выполните `passwd root` для смены пароля root.

При использовании live USB:
1. Загрузитесь с флешки.
2. Примонтируйте систему: `mount /dev/sda1 /mnt`.
3. Войдите в неё: `chroot /mnt`.
4. Восстановите доступ: `passwd root` или `sudo usermod -aG sudo ваш_пользователь`.

### 7.7. Настройка ограниченного доступа через sudo

**Вопрос:** *Как дать пользователю только ограниченные права через sudo (например, только перезапускать сервисы или обновлять пакеты)?*

**Ответ:** В файле `/etc/sudoers` (или в отдельном файле в `/etc/sudoers.d/`) можно указать конкретные разрешённые команды. Например:

```
username ALL=(ALL) /usr/bin/systemctl, /usr/bin/apt
```

Это позволит пользователю выполнять только указанные команды.

> **Важное предостережение:** Редактирование файлов в `/etc/sudoers.d/` также безопасно, если вы используете `visudo` или соблюдаете синтаксис. Ошибка в любом файле этой директории может нарушить работу `sudo`.

---

## 8. Лимиты, оптимизация и масштабирование

- **Использование `sudo visudo`:** Единственный безопасный способ редактирования `/etc/sudoers`.
- **Использование `userdel -r`:** Удаляет все данные пользователя, освобождая дисковое пространство.
- **Прямое редактирование `/etc/sudoers`:** Категорически не рекомендуется без `visudo`.

## 9. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Ошибка в `/etc/sudoers`:** Может полностью заблокировать доступ к `sudo` для всех пользователей. Всегда используйте `visudo`.
- **Скрытые учётные записи:** Злоумышленник может создать учётную запись с правами root для скрытого доступа. Регулярно проверяйте пользователей с UID 0 и группы `sudo`/`wheel`.
- **Блокировка входа root:** Для повышения безопасности рекомендуется заблокировать прямой вход для root: `sudo passwd -l root`.
- **Логирование sudo-команд:** Для отслеживания действий администраторов можно настроить логирование в `/etc/sudoers` через `Defaults logfile=/var/log/sudo.log`.

### 2. Инженерный FAQ

- **Вопрос:** *Как посмотреть свои привилегии sudo?*  
  **Ответ:** Используйте команду `sudo -l`. Она показывает список разрешённых команд и условия их выполнения.

- **Вопрос:** *Что делать, если я случайно удалил себя из группы sudo?*  
  **Ответ:** Если вы сохранили доступ к системе через другого пользователя с правами sudo, попросите его добавить вас обратно. Если доступа нет, потребуется загрузка в режиме восстановления (recovery mode) или использование live USB для восстановления прав.

- **Вопрос:** *Как настроить ограниченный доступ через sudo?*  
  **Ответ:** В файле `/etc/sudoers` можно указать конкретные разрешённые команды. Например:
  ```
  username ALL=(ALL) /usr/bin/systemctl, /usr/bin/apt
  ```
  Это позволит пользователю выполнять только указанные команды.

| Удаление из группы | `sudo deluser username sudo` или `sudo gpasswd -d username sudo` |

### Ключевые понятия:

- **Группа `sudo`** (в Debian/Ubuntu) или **группа `wheel`** (в RHEL/Rocky Linux) — даёт пользователю право выполнять команды от имени root.
- `/etc/sudoers` — файл, определяющий права `sudo`; редактируется через `visudo`.
- `usermod -a -G` — безопасный способ добавить пользователя в дополнительные группы.
- `userdel -r` — удаляет пользователя вместе с его данными (домашним каталогом, почтой).
- **Важное предостережение:** при редактировании `/etc/sudoers` используйте `visudo` — это предотвращает синтаксические ошибки, которые могут сделать невозможным использование `sudo` для всех пользователей.

## Заключение

В этой теме были рассмотрены права суперпользователя через группу `sudo`, управление членством в этой группе, а также удаление учётных записей. Понимание того, как работает `/etc/sudoers` и почему `visudo` является единственным безопасным способом его редактирования, критично для системного администратора. Добавление и удаление пользователей из группы `sudo` должно выполняться осознанно, с проверкой через `groups` после каждого действия.
