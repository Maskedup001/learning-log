# Тема 6.1: Вывод информации о пользователях

В данной теме рассматриваются команды для получения информации о пользователях и группах в Linux: `whoami`, `groups`, `id`, а также утилиты для просмотра активных сессий (`users`, `who`, `w`). Разбираются переключение между пользователями (`su`, `sudo su`, `sudo -i`), принцип минимальных прав и числовые идентификаторы UID и GID. Также рассматриваются структуры системных файлов `/etc/passwd` и `/etc/group`, в которых хранится информация о пользователях и группах.

---

## 1. Информация о текущем пользователе — Базовые свойства

- **Контекст/Уровень:** Системное администрирование / Управление пользователями.
- **Основное назначение:** Получение информации о текущем пользователе и его группах.
- **Принцип работы:** Команды `whoami`, `groups` и `id` обращаются к системным файлам (`/etc/passwd`, `/etc/group`) и выводят данные о текущем пользователе.

### 1.1. `whoami` — имя текущего пользователя

```bash
whoami
```

**Действие:** Выводит логин пользователя, от имени которого выполняется текущая сессия.

### 1.2. `logname` — имя пользователя, с которого начата сессия

```bash
logname
```

**Действие:** Выводит имя пользователя, с которого была начата сессия (даже если после этого использовался `su`). Полезно, когда вы переключились на другого пользователя, но хотите узнать, кто изначально залогинился.

### 1.3. `groups` — группы пользователя

```bash
groups
```

**Действие:** Выводит список групп, в которые входит текущий пользователь.

### 1.4. `id` — подробная информация о пользователе

```bash
id
```

**Действие:** Выводит:
- `uid` (User ID) — числовой идентификатор пользователя.
- `gid` (Group ID) — числовой идентификатор основной группы.
- `groups` — список дополнительных групп с их идентификаторами.

**Пример вывода:**
```
uid=1000(itguy) gid=1000(itguy) groups=1000(itguy),4(adm),27(sudo)
```

**Разбор вывода `id`:**
- `uid=1000(itguy)` — пользователь `itguy` имеет UID 1000.
- `gid=1000(itguy)` — основная группа пользователя (создаётся автоматически при создании пользователя).
- `groups=1000(itguy),4(adm),27(sudo)` — пользователь входит в основную группу `itguy`, а также в дополнительные группы `adm` (административные привилегии) и `sudo` (право на выполнение команд от имени root).

## 2. Переключение между пользователями

### 2.1. `su` — Switch User

```bash
su username
```

**Действие:** Переключает текущую сессию на указанного пользователя. Требуется ввод пароля целевого пользователя.

**Пример:**
```bash
su salesguy
```

### 2.2. `sudo su` — переключение на root

```bash
sudo su
```

**Действие:** Переключает на пользователя `root` (суперпользователя). Требует ввода пароля текущего пользователя (если он есть в группе `sudo`).

### 2.3. `sudo -i` — альтернативный способ переключения на root

```bash
sudo -i
```

**Действие:** Открывает интерактивную сессию root с инициализацией окружения root. В отличие от `sudo su`, эта команда загружает профиль root (`.bashrc`, `.profile`), что в некоторых сценариях предпочтительнее.

> **Подробнее об инициализации окружения root:**  
> Команда `sudo -i` загружает профиль root (файлы `.bashrc`, `.profile`), устанавливает его переменные окружения и переводит вас в домашнюю директорию root (`/root`).  
>  
> В отличие от неё, команда `sudo su` просто переключает пользователя на root, но **не загружает его окружение** — вы остаётесь в текущей директории, и ваши переменные окружения остаются прежними.  
>  
> На практике это означает, что после `sudo -i` команды будут вести себя так, как ожидает root (например, `pwd` покажет `/root`). После `sudo su` вы останетесь в той же папке, где и были.  
>  
> Если вы не уверены, какую команду использовать, выбирайте `sudo -i` — она даёт более предсказуемое поведение.

### 2.4. `exit` — возврат к предыдущему пользователю

```bash
exit
```

**Действие:** Завершает текущую сессию и возвращает к предыдущему пользователю.

### 2.5. Признаки в командной строке

| Символ в конце приглашения | Значение |
| :--- | :--- |
| `$` | Обычный пользователь |
| `#` | Суперпользователь (root) |
*Таб. 1. Символы приглашения в терминале.*

## 3. Root и принцип минимальных прав

### 3.1. `sudo` — выполнение команды с правами root

```bash
sudo apt install zip
```

**Действие:** Префикс `sudo` позволяет выполнить команду от имени суперпользователя без полного переключения на root.

> **Важное замечание о `sudo`:** `sudo` — это сокращение от **"substitute user do"**, а не "super user do". Команда позволяет выполнить действие от имени другого пользователя (по умолчанию — root). "Super user do" — это народная этимология, которая прижилась из-за частого использования `sudo` с root.

### 3.2. Почему не стоит работать от root постоянно

- **Безопасность:** Случайное выполнение опасной команды может привести к повреждению системы.
- **Принцип минимальных прав:** В Linux принято выдавать пользователю ровно те права, которые необходимы для выполнения текущих задач.
- **Аудит:** При работе через `sudo` действия логируются, что позволяет отследить, кто и что делал.

**Пример:** Если разработчику нужно только читать логи и править конфигурации, администратор выдаст доступ к конкретным файлам, а не права root.

## 4. UID и GID — идентификаторы пользователей и групп

При создании нового пользователя в Linux:
- Назначается уникальный `UID` (User ID) — числовой идентификатор.
- Автоматически создаётся одноимённая группа с `GID` (Group ID).
- Эта группа становится основной (primary) для пользователя.
- Пользователь может быть добавлен в дополнительные (secondary) группы.

| Понятие | Описание |
| :--- | :--- |
| `UID` | User ID — уникальный числовой идентификатор пользователя. |
| `GID` | Group ID — идентификатор основной группы. |
| Основная группа | Группа, присвоенная пользователю по умолчанию (создаётся автоматически). |
| Дополнительные группы | Группы, в которые пользователь включён помимо основной. |
*Таб. 2. Понятия UID и GID.*

### 4.1. Структура файла `/etc/passwd`

Информация о пользователях хранится в файле `/etc/passwd`. Каждая строка имеет формат:

```
username:x:UID:GID:comment:home_directory:shell
```

**Пример:**
```
itguy:x:1000:1000:itguy:/home/itguy:/bin/bash
```

Это означает:
- Пользователь `itguy` имеет UID 1000.
- Основная группа (GID) — 1000.
- Домашняя директория — `/home/itguy`.
- Оболочка — `/bin/bash`.

### 4.2. Структура файла `/etc/group`

Информация о группах хранится в файле `/etc/group`. Каждая строка имеет формат:

```
groupname:x:GID:user1,user2,...
```

**Пример:**
```
sudo:x:27:itguy,salesguy
```

Это означает, что группа `sudo` имеет GID 27, и в неё входят пользователи `itguy` и `salesguy`.

## 5. Информация об активных пользователях

### 5.1. `users` — список логинов

```bash
users
```

**Действие:** Выводит список имён пользователей, которые в данный момент работают в системе (включая удалённые сессии).

### 5.2. `who` — информация о сессиях

```bash
who
```

**Действие:** Выводит таблицу с информацией:
- Логин пользователя.
- Тип терминала (`tty` — локально, `pts` — удалённо).
- Время входа.
- IP-адрес (для удалённых подключений).

### 5.3. `w` — расширенная информация

```bash
w
```

**Действие:** Выводит:
- Текущее время, время работы системы, количество пользователей.
- Для каждого пользователя: логин, терминал, время входа, нагрузку, текущую команду.

**Пример вывода `w`:**
```
 14:30:15 up 2 days,  3:45,  2 users,  load average: 0.08, 0.03, 0.01
USER     TTY      FROM             LOGIN@   IDLE   JCPU   PCPU WHAT
itguy    tty7     :0               10:15    4:12m  2:15   0.20s /usr/bin/gnome-shell
salesguy pts/0    192.168.1.100    14:20    0.00s  0.05s  0.01s sshd: salesguy
```

### 5.4. Разница между `tty` и `pts`

| Обозначение | Значение |
| :--- | :--- |
| `tty` | Терминал, подключённый локально (физическая консоль или виртуальный терминал). |
| `pts` | Псевдо-терминал (удалённое подключение, например, через SSH или графический эмулятор). |
*Таб. 3. Разница между tty и pts.*

## 6. Практические примеры

### 6.1. Просмотр информации о себе

```bash
whoami
logname
groups
id
```

### 6.2. Переключение на другого пользователя

```bash
su salesguy
# ввод пароля salesguy
whoami              # salesguy
exit                # возврат к itguy
```

### 6.3. Выполнение команды с правами root

```bash
sudo apt install zip
```

### 6.4. Переключение на root (три способа)

```bash
sudo su             # через sudo
# или
sudo -i             # с инициализацией окружения root
# или
su -                # если известен пароль root
```

### 6.5. Просмотр активных пользователей

```bash
users
who
w
```

### 6.6. Удалённое подключение (SSH) и проверка

При подключении по SSH под другим пользователем, команды `users`, `who`, `w` покажут обе активные сессии (локальную и удалённую).

## 7. Разбор сложных ситуаций и типичных вопросов

### 7.1. Расшифровка `sudo`

**Вопрос:** *Что означает `sudo`? Это "super user do"?*

**Ответ:** Строго говоря, `sudo` — это сокращение от **"substitute user do"**. Команда позволяет выполнить действие от имени другого пользователя. В большинстве случаев этим пользователем является `root`, поэтому "super user do" — народная этимология, которая прижилась из-за частого использования. Тем не менее, технически правильная расшифровка — **"substitute user do"**.

### 7.2. Почему `users` и `who` могут ничего не показывать?

**Вопрос:** *Команды `users`, `who` и `w` не показывают пользователей, даже если я сам залогинен. Почему?*

**Ответ:** В некоторых системах с высокими настройками безопасности для просмотра информации о других пользователях могут требоваться права суперпользователя. В таких случаях выполнение команд через `sudo` может решить проблему. Например: `sudo who`.

### 7.3. Почему в `who` один пользователь отображается дважды?

**Вопрос:** *Почему пользователь отображается дважды в выводе `who` (например, `seat0` и `:1`)? Что означает `:1`?*

**Ответ:** Это нормальное поведение в графических окружениях (GNOME, KDE, XFCE и т.д.). Первая запись (`seat0`) — это экран приветствия (дисплейный менеджер, например GDM или SDDM). Вторая запись (`:1`) — это ваша текущая графическая сессия (Xorg или Wayland). `:1` — это номер дисплея X11/Wayland. `:0` — это главный дисплей, на котором запущен дисплейный менеджер. Ваша пользовательская сессия запускается на следующем свободном дисплее — `:1`. Нумерация дисплеев начинается с 0 и продолжается последовательно.

Команда `users` выводит только имена пользователей, поэтому если один пользователь имеет две активные сессии, он отобразится дважды — это нормально.

### 7.4. Набор групп зависит от дистрибутива и оборудования

**Вопрос:** *Почему в разных дистрибутивах (Ubuntu, Debian) и на разном оборудовании у одного пользователя разные группы?*

**Ответ:** Набор групп зависит от трёх факторов:
- **Дистрибутив:** У Ubuntu и Debian исторически разные политики безопасности и подходы к правам "из коробки".
- **Графическое окружение:** Графические оболочки подтягивают за собой системные службы, которые требуют членства в определённых группах.
- **Оборудование:** Наличие реального железа (например, Bluetooth) может добавлять соответствующие группы.

Это нормально и не является ошибкой.

## 8. Лимиты, оптимизация и масштабирование

- **Принцип минимальных прав:** Всегда используйте минимально необходимые права для выполнения задачи. Это снижает риск повреждения системы.
- **Аудит:** Работа через `sudo` логируется, что позволяет отследить действия и повышает безопасность.
- **Переключение пользователей:** Использование `su` и `sudo su` требует осторожности. Всегда завершайте сессии через `exit`, чтобы не оставаться с повышенными правами дольше, чем нужно.

## 9. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Работа от root:** Постоянная работа от имени root — одна из главных угроз безопасности. Одна ошибочная команда может уничтожить всю систему. Всегда используйте `sudo` только когда это необходимо.
- **Переключение пользователей:** Если вы переключились на root через `sudo su` и забыли выполнить `exit`, сессия остаётся открытой. Это создаёт риск, если кто-то получит доступ к вашему терминалу.
- **Просмотр информации о пользователях:** Команды `users`, `who` и `w` показывают активные сессии. В средах с высокими требованиями безопасности эта информация может быть скрыта или требовать прав root.

### 2. Инженерный FAQ

- **Вопрос:** *Как создать нового пользователя и задать ему пароль?*  
  **Ответ:** Для создания пользователя используйте `sudo useradd имя_пользователя`. Для задания пароля — `sudo passwd имя_пользователя`. Затем можно подключиться по SSH через `имя_пользователя@ip`.

- **Вопрос:** *Как посмотреть список всех пользователей в системе?*  
  **Ответ:** Список всех пользователей хранится в файле `/etc/passwd`. Для просмотра можно использовать `cat /etc/passwd` или `less /etc/passwd`.

- **Вопрос:** *Как узнать IP-адрес машины для SSH-подключения?*  
  **Ответ:** Используйте команду `hostname -i`. Она выведет IP-адрес, который можно использовать для подключения по SSH.

- **Вопрос:** *Что означают поля в файле `/etc/passwd`?*  
  **Ответ:** Формат строки: `username:x:UID:GID:comment:home_directory:shell`. Поле `x` обычно означает, что пароль хранится в зашифрованном виде в `/etc/shadow`, а не в открытом виде в `/etc/passwd`.

- **Вопрос:** *Как подключиться к Linux-серверу через PuTTY из Windows?*  
  **Ответ:** Создайте пользователя (`sudo useradd username`), задайте ему пароль (`sudo passwd username`), узнайте IP-адрес сервера (`hostname -i`), затем в PuTTY укажите `username@ip` и введите пароль.
