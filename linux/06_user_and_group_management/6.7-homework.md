Задание разбито на части: создание групп, создание пользователей с паролями, проверка прав, блокировка учётной записи и удаление группы. ## 4. Разбор сложных ситуаций и типичных ошибок

### 4.1. Группа не удаляется — ошибка `groupdel: cannot remove the primary group`

**Вопрос:** *Почему команда `sudo groupdel testers` выдаёт ошибку?*

**Ответ:** Это происходит, если группа `testers` является **основной (primary) группой** для какого-либо пользователя. В данном случае `gray_wolf` был создан с группой `testers` как основной. Перед удалением группы нужно либо сменить ему основную группу, либо удалить пользователя.

**Решение:** Сменить основную группу `gray_wolf` на другую (например, `developers`):
```bash
sudo usermod -g developers gray_wolf
sudo groupdel testers
```

> **Важно:** `gpasswd -d` в этом случае **не поможет**, потому что группа `testers` остаётся основной для `gray_wolf`, даже если удалить его из списка дополнительных групп.

---

### 4.2. Нужно ли добавлять группу `admins` в `/etc/sudoers`?

**Вопрос:** *Чтобы члены группы `admins` имели права sudo, нужно ли редактировать `/etc/sudoers`?*

**Ответ:** Да, нужно. Это можно сделать через `sudo visudo` и добавить строку:

```
%admins ALL=(ALL:ALL) ALL
```

Либо добавить через `tee`:

```bash
echo "%admins ALL=(ALL:ALL) ALL" | sudo tee -a /etc/sudoers.d/admins
sudo chmod 440 /etc/sudoers.d/admins
```

> **Обратите внимание:** В некоторых дистрибутивах (например, в Ubuntu/Debian) группа `sudo` уже имеет права по умолчанию. В данном задании требуется создать отдельную группу `admins` и дать ей права.

---

### 4.3. Разница между `useradd` и `adduser` при создании пользователя

**Вопрос:** *Какую команду лучше использовать для создания пользователей?*

**Ответ:** Обе команды работают, но:
- `useradd` — низкоуровневая утилита, требует указания ключей (`-m` для домашнего каталога, `-s` для оболочки).
- `adduser` — интерактивная обёртка, автоматически создаёт домашний каталог и запрашивает пароль.

> **Важное замечание:** В дистрибутивах Debian/Ubuntu **рекомендуется использовать `adduser`**, так как `useradd` считается низкоуровневым инструментом, предназначенным для сценариев, где нужен полный контроль, но не для повседневного использования.

В задании допустимы оба варианта. В примерах выше показаны оба подхода.

---

### 4.4. Зачем нужен ключ `-m` в `useradd`?

**Вопрос:** *Что делает ключ `-m` в команде `useradd`?*

**Ответ:** Ключ `-m` создаёт домашний каталог для пользователя. Без него пользователь будет создан, но не сможет сохранять файлы в `/home/username`. Это важно для полноценной работы пользователя.

---

### 4.5. Путаница между `useradd -m -G` и `usermod -aG`

**Вопрос:** *Почему команда `usermod -m -G` вызывает ошибку?*

**Ответ:** Потому что флаг `-m` в `useradd` и `usermod` делает **совершенно разные вещи**:
- В `useradd`: `-m` создаёт домашний каталог.
- В `usermod`: `-m` перемещает содержимое домашнего каталога (работает с `-d`).

Также:
- `usermod -G` — перезаписывает все дополнительные группы.
- `usermod -aG` — добавляет к существующим группам, не удаляя их.

**Правильно:**
- При создании пользователя: `useradd -m -G group user`
- При изменении существующего: `usermod -aG group user`

---

### 4.6. Альтернативная проверка групп через `getent`

**Вопрос:** *Можно ли проверить созданные группы без чтения `/etc/group`?*

**Ответ:** Да, можно использовать `getent group` (более современный и рекомендуемый способ):
```bash
getent group developers testers admins
```

## 5. Лимиты, оптимизация и масштабирование

- **Использование `adduser`:** Удобнее для новичков, но может отсутствовать в минимальных установках.
- **Использование `useradd`:** Универсальнее, но требует знания ключей (`-m`, `-s`, `-G`).
- **Безопасность `/etc/sudoers`:** Редактировать только через `visudo` или через отдельный файл в `/etc/sudoers.d/` с правами 440. Никогда не используйте `nano` или `vim` напрямую.
- **Удаление групп:** Перед удалением группы убедитесь, что она не является основной для какого-либо пользователя.

## 6. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Установка пароля через аргументы команды:** Передача хэша пароля в команде создания пользователя (например, через `useradd -p`) оставляет его в истории команд. Если злоумышленник получит доступ к истории, он сможет использовать этот хэш. Нужно создавать пользователя без пароля, а затем задавать пароль через `passwd`.

- **Создание скрытых учётных записей с правами root:** Злоумышленник может создать пользователя с UID 0 и получить полный доступ к системе без необходимости вводить пароль root. Администратору следует периодически проверять список пользователей с таким идентификатором (`awk -F: '($3 == 0) {print $1}' /etc/passwd`).

- **Избыточные привилегии через группу администраторов:** Если дать группе администраторов неограниченные права `sudo`, любой её член сможет выполнять произвольные действия. Правильный подход — предоставлять только те команды, которые действительно необходимы.

### 2. Инженерный FAQ (по безопасности)

- **Вопрос:** Как проверить, заблокирован ли пользователь?  
  **Ответ:** В файле `/etc/shadow` в начале строки пользователя должен стоять специальный символ (обычно `!`). Наличие этого символа означает, что учётная запись заблокирована.

- **Вопрос:** Как предотвратить случайное удаление важных групп?  
  **Ответ:** Перед удалением группы проверьте, не является ли она основной для кого-либо из пользователей (например, с помощью `getent group groupname`). Также полезно делать резервные копии файлов `/etc/group`, `/etc/passwd`, `/etc/shadow`.

- **Вопрос:** Можно ли разрешить пользователю выполнять только определённые команды через `sudo`?  
  **Ответ:** Да, в файле `sudoers` можно перечислить конкретные команды, разрешённые для пользователя или группы. Это ограничит его возможности и снизит риск случайных или злонамеренных действий.

## 7. Итоговая шпаргалка по командам

| Действие                        | Команда                                                                                         |
| :------------------------------ | :---------------------------------------------------------------------------------------------- |
| Создать группу                  | `sudo groupadd groupname`<br>или `sudo groupadd {group1,group2,group3}`                         |
| Добавить группу в sudoers       | `sudo visudo`<br>или<br>`echo "%admins ALL=(ALL:ALL) ALL" \| sudo tee -a /etc/sudoers.d/admins` |
| Создать пользователя            | `sudo useradd -m -s /bin/bash username`<br>или<br>`sudo adduser username`                       |
| Установить пароль               | `sudo passwd username`<br>или<br>`echo "username:password" \| sudo chpasswd`                    |
| Добавить пользователя в группу  | `sudo usermod -aG groupname username`                                                           |
| Блокировать пользователя        | `sudo usermod -L username`                                                                      |
| Проверить блокировку            | `sudo cat /etc/shadow`<br>или<br>`sudo tail /etc/shadow`                                        |
| Удалить группу                  | `sudo groupdel groupname`                                                                       |
| Переключиться на пользователя   | `su - username`                                                                                 |
| Выйти из сессии                 | `exit`                                                                                          |
| Проверить группы пользователя   | `groups username`<br>или<br>`getent group`                                                      |
| Вывести UID, GID, группы        | `id username`                                                                                   |
| Проверить текущего пользователя | `whoami`                                                                                        |
*Таб. 1. Итоговая шпаргалка по командам.*
