# Тема 6.2: Создание пользователей

В данной теме рассматриваются команды для создания пользователей в Linux: `useradd` (низкоуровневая утилита) и `adduser` (интерактивная обёртка). Разбираются ключи для настройки домашнего каталога, оболочки, групп и UID, а также управление паролями через `passwd`. Дополнительно рассматриваются структура и назначение файлов `/etc/passwd`, `/etc/shadow` и `/etc/group`, а также категории пользователей по UID.

---

## 1. Создание пользователей — `useradd`

- **Контекст/Уровень:** Системное администрирование / Управление пользователями.
- **Основное назначение:** Создание учётных записей пользователей в системе.
- **Принцип работы:** `useradd` — низкоуровневая утилита, которая добавляет запись в файлы `/etc/passwd` и `/etc/group`. Она присутствует во всех дистрибутивах Linux.

### 1.1. Базовый синтаксис

```bash
sudo useradd username
```

Для создания пользователя требуются права суперпользователя (`sudo`).

### 1.2. Основные ключи `useradd`

| Ключ | Описание |
| :--- | :--- |
| `-m` | Создать домашний каталог для пользователя (обычно `/home/username`). |
| `-d <путь>` | Указать путь к домашнему каталогу (используется вместе с `-m` или вместо него). |
| `-g <группа>` | Задать основную (primary) группу пользователя. |
| `-G <группы>` | Задать дополнительные (secondary) группы (список через запятую без пробелов). |
| `-s <оболочка>` | Указать командную оболочку (например, `/bin/bash`). |
| `-u <UID>` | Задать числовой идентификатор пользователя вручную. |
| `-p <хэш>` | Указать хэш пароля (не рекомендуется — пароль остаётся в истории команд). |
| `-D` | Показать настройки по умолчанию для создания пользователей. |
| `-k <директория>` | Указать директорию с шаблонными файлами (skel) для нового пользователя (используется с `-m`). |
*Таб. 1. Основные ключи команды `useradd`.*

> **Важное замечание о `-p`:** Использование ключа `-p` для указания пароля **крайне не рекомендуется**, так как хэш пароля остаётся в истории команд и может быть скомпрометирован. Правильный способ — создать пользователя без пароля, а затем установить пароль через `sudo passwd username`.

> **Дополнительно о `-k`:** Ключ `-k` (или его полная форма `--skel SKEL_DIR`) позволяет указать директорию, из которой будут скопированы шаблонные файлы (например, `.bashrc`, `.profile`) в домашний каталог нового пользователя. По умолчанию используется `/etc/skel`.

> **Что такое `/etc/skel`?**  
> `/etc/skel` (от skeleton — скелет) — это директория с шаблонными файлами (например, `.bashrc`, `.profile`), которые копируются в домашний каталог нового пользователя при создании (если использован ключ `-m`). Вы можете добавлять туда свои файлы, чтобы они автоматически появлялись у всех новых пользователей.

### 1.3. Примеры создания пользователей

**Создание пользователя без домашнего каталога:**
```bash
sudo useradd officemanager
```
Домашний каталог не создаётся. Такой пользователь не сможет войти в систему без дополнительной настройки.

**Создание пользователя с домашним каталогом:**
```bash
sudo useradd -m smileygirl
```
Домашний каталог: `/home/smileygirl`.

**Создание пользователя с указанием домашнего каталога и оболочки:**
```bash
sudo useradd -m -d /home/theboss -s /bin/bash bigboss
```
- Домашний каталог: `/home/theboss` (а не `/home/bigboss`).
- Оболочка: `/bin/bash`.

**Использование шаблонной директории (`-k`):**
```bash
sudo useradd -m -k /etc/skel newuser
```
Позволяет задать пользовательскую директорию с шаблонными файлами для новых пользователей. По умолчанию используется `/etc/skel`.

## 2. Создание пользователей — `adduser`

- **Контекст/Уровень:** Системное администрирование / Управление пользователями.
- **Основное назначение:** Упрощённое интерактивное создание пользователей.
- **Принцип работы:** `adduser` — это скрипт-обёртка (обычно на Perl), которая вызывает `useradd` под капотом, но добавляет интерактивный диалог и автоматическое создание домашнего каталога.

### 2.1. Использование

```bash
sudo adduser outgoinghr
```

### 2.2. Особенности

- **Интерактивный режим:** запрашивает пароль, имя, номер телефона и другие данные.
- **Автоматически создаёт домашний каталог:** не требует ключа `-m`.
- **Безопасность пароля:** пароль не попадает в историю команд.
- **Под капотом:** вызывает команду `useradd`.

> **Важное замечание:** В некоторых дистрибутивах и версиях команда `adduser` может быть синонимом `useradd` (то есть `adduser == useradd`). Однако в Ubuntu/Debian это именно интерактивная обёртка.

### 2.3. Где находятся исполняемые файлы

```bash
whereis useradd        # /usr/sbin/useradd — бинарный файл
whereis adduser        # /usr/sbin/adduser — Perl-скрипт
```

## 3. Управление паролями — `passwd`

- **Контекст/Уровень:** Системное администрирование / Управление пользователями.
- **Основное назначение:** Установка и смена паролей пользователей.
- **Принцип работы:** `passwd` изменяет хэш пароля в файле `/etc/shadow` (доступен только для root).

### 3.1. Синтаксис

```bash
sudo passwd username    # установить/сменить пароль для указанного пользователя
sudo passwd             # сменить пароль пользователя root
```

### 3.2. Особенности

- Пароль не отображается при вводе.
- Требуется ввод пароля дважды для подтверждения.
- Сами пароли не сохраняются в истории команд, только факт выполнения команды.

---

## 4. Файлы хранения информации о пользователях

В Linux информация о пользователях и группах хранится в текстовых файлах в директории `/etc`.

### 4.1. `/etc/passwd` — информация об учётных записях

```bash
cat /etc/passwd
```

**Формат строки (разделитель — двоеточие `:`):**

| Поле | Описание |
| :--- | :--- |
| 1 | Логин пользователя |
| 2 | `x` — признак того, что хэш пароля хранится в `/etc/shadow` (исторически здесь был хэш) |
| 3 | `UID` (User ID) — числовой идентификатор пользователя |
| 4 | `GID` (Group ID) — идентификатор основной группы |
| 5 | `GECOS` — дополнительная информация (имя, телефон и т.д.) |
| 6 | Путь к домашнему каталогу |
| 7 | Командная оболочка (shell) |
*Таб. 2. Поля файла `/etc/passwd`.*

### 4.2. `/etc/shadow` — хэши паролей

```bash
sudo cat /etc/shadow
```

- Доступен **только для root**.
- Содержит хэши паролей (зашифрованные строки), информацию о сроке действия пароля и другие параметры безопасности.

### 4.3. `/etc/group` — информация о группах

```bash
cat /etc/group
```

Содержит названия групп, GID и список пользователей, входящих в группу.

## 5. UID и категории пользователей

В Linux принята следующая градация UID:

| Диапазон UID | Категория | Описание |
| :--- | :--- | :--- |
| `0` | root | Суперпользователь, имеет неограниченные права. |
| `1–999` | Системные пользователи (демоны) | Учётные записи для запуска служб. У них обычно нет возможности входа (оболочка `/usr/sbin/nologin` или `/bin/false`). |
| `1000+` | Обычные пользователи | Человеческие учётные записи, создаваемые администратором. |
*Таб. 3. Категории пользователей по UID.*

> **Важное замечание о диапазонах UID:** В разных дистрибутивах и версиях границы системных UID могут варьироваться (например, 1–499 или 1–999). Современные дистрибутивы (включая Ubuntu) используют диапазон 1–999 для системных пользователей. Это не ошибка, а особенность конкретной системы. В видеоуроке мог использоваться старый диапазон 1–499 — это нормально.

## 7. Сравнение `useradd` и `adduser`

| Характеристика | `useradd` | `adduser` |
| :--- | :--- | :--- |
| Тип | Бинарный файл | Скрипт-обёртка (Perl) |
| Доступность | Во всех дистрибутивах | Не во всех (есть в Ubuntu/Debian) |
| Интерактивность | Нет (только ключи) | Да (запрашивает пароль, имя и т.д.) |
| Создание домашнего каталога | Только с ключом `-m` | По умолчанию |
| Задание пароля | Требуется отдельная команда `passwd` | Задаётся интерактивно |
| Безопасность пароля | Хэш можно указать ключом `-p` (небезопасно) | Пароль не попадает в историю |
*Таб. 4. Сравнение `useradd` и `adduser`.*

## 8. Разбор сложных ситуаций и типичных вопросов

### 8.1. Право на использование `sudo`

**Вопрос:** *Разве не каждый пользователь может использовать `sudo` и делать действия от имени администратора?*

**Ответ:** Нет. Возможность использовать `sudo` — это привилегия, которую администратор явно предоставляет конкретным пользователям или группам. По умолчанию обычный пользователь не имеет права на выполнение команд через `sudo`.

### 8.2. Расхождение диапазонов UID в видео и конспекте

**Вопрос:** *В видеоуроке демоны указаны как 1–499, а в конспекте 1–999. Почему?*

**Ответ:** Это не ошибка. В разных дистрибутивах и версиях Linux границы системных UID могут отличаться. Современные дистрибутивы (включая Ubuntu) используют диапазон 1–999 для системных пользователей. Видеоурок мог ссылаться на более старую версию или другой дистрибутив.

### 8.3. `adduser` vs `useradd`: когда что использовать?

**Вопрос:** *Какую команду использовать для создания пользователей?*

**Ответ:** Если вы работаете в Ubuntu или Debian — используйте `adduser`, так как она проще и безопаснее. Если вы работаете в минимальной установке или другом дистрибутиве — используйте `useradd` с необходимыми ключами (`-m`, `-s`, `-d`).

### 8.4. Как дать пользователю права sudo?

**Вопрос:** *Как сделать так, чтобы созданный пользователь мог использовать команду `sudo`?*

**Ответ:** После создания пользователя добавьте его в группу `sudo`:

```bash
sudo usermod -aG sudo username
```

### 8.5. Как удалить пользователя?

**Вопрос:** _Как полностью удалить пользователя вместе с его домашним каталогом?_

**Ответ:** Используйте команду `userdel` с ключом `-r`:

```bash
sudo userdel -r username
```

Ключ `-r` удаляет не только учётную запись, но и домашний каталог пользователя, и файлы почтового спула.

---

## 9. Лимиты, оптимизация и масштабирование

- **Использование `adduser`:** Удобнее для новичков, но может отсутствовать в минимальных установках.
- **Использование `useradd`:** Универсальнее, но требует знания ключей и безопасного управления паролями (через `passwd`, а не `-p`).
- **Безопасность паролей:** Никогда не используйте ключ `-p` в `useradd` — хэш пароля остаётся в истории команд.

## 10. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Пароли в истории команд:** Использование ключа `-p` в `useradd` оставляет хэш пароля в истории команд, что делает систему уязвимой. Всегда используйте `sudo passwd username` для установки пароля.
- **Доступ к `/etc/shadow`:** Файл `/etc/shadow` содержит хэши паролей и доступен только для root. Не предоставляйте доступ к этому файлу обычным пользователям.
- **Системные пользователи (демоны):** Эти учётные записи не должны иметь возможность входа в систему. Используйте `/usr/sbin/nologin` или `/bin/false` в качестве оболочки для таких пользователей.

### 2. Инженерный FAQ

- **Вопрос:** *Как создать нового пользователя с правами sudo?*  
  **Ответ:** После создания пользователя добавьте его в группу `sudo`: `sudo usermod -aG sudo username`.

- **Вопрос:** *Как удалить пользователя?*  
  **Ответ:** Используйте команду `sudo userdel -r username`. Ключ `-r` удаляет также домашний каталог пользователя.

- **Вопрос:** *Можно ли изменить UID существующего пользователя?*  
  **Ответ:** Да, с помощью команды `sudo usermod -u новый_UID username`. Будьте осторожны: если пользователь владеет файлами, их права нужно обновить через `sudo chown -R новый_UID username`.

- **Вопрос:** *Где находятся шаблонные файлы для новых пользователей?*  
  **Ответ:** По умолчанию в `/etc/skel`. При создании пользователя с `-m` эти файлы копируются в его домашний каталог.

## 11. Итоговая шпаргалка по командам

| Команда | Назначение |
| :--- | :--- |
| `sudo useradd username` | Создание пользователя (базовый вариант). |
| `sudo useradd -m username` | Создание пользователя с домашним каталогом. |
| `sudo useradd -d <путь> -s <shell> username` | Создание с указанием домашнего каталога и оболочки. |
| `sudo adduser username` | Интерактивное создание пользователя (Ubuntu/Debian). |
| `sudo passwd username` | Установка/смена пароля пользователя. |
| `cat /etc/passwd` | Просмотр информации об учётных записях. |
| `sudo cat /etc/shadow` | Просмотр хэшей паролей (только root). |
| `cat /etc/group` | Просмотр информации о группах. |
| `sudo usermod -aG sudo username` | Добавить пользователя в группу `sudo`. |
| `sudo userdel -r username` | Удалить пользователя вместе с домашним каталогом. |
*Таб. 5. Итоговая шпаргалка по командам.*

### Ключевые понятия:

- **UID** — числовой идентификатор пользователя.
- **GID** — идентификатор основной группы.
- **Системные пользователи (демоны)** — UID 1–999, не имеют возможности входа.
- **Обычные пользователи** — UID от 1000 и выше.
- **Пароли** хранятся в зашифрованном виде в `/etc/shadow`.
- **`adduser`** — удобная обёртка над `useradd`, но может отсутствовать в некоторых дистрибутивах.

## Заключение

В этой теме были рассмотрены инструменты для создания пользователей в Linux: `useradd` и `adduser`. Понимание различий между ними, умение правильно задавать домашний каталог, оболочку, группы и управлять паролями являются базовыми навыками системного администратора. Также важно понимать структуру системных файлов (`/etc/passwd`, `/etc/shadow`, `/etc/group`) и знать категории пользователей по UID для безопасного управления учётными записями.
