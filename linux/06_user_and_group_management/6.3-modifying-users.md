# Тема 6.3: Изменение пользователей

В данной теме рассматривается команда `usermod` для изменения параметров существующих учётных записей пользователей. Разбираются блокировка и разблокировка, изменение домашнего каталога и командной оболочки, управление группами, UID и логином, а также установка даты истечения учётной записи. Отдельно обсуждается прямое редактирование системных файлов и почему его следует избегать.

---

## 1. Введение в `usermod` — Базовые свойства

Команда `usermod` (сокращение от "user modify") используется для изменения параметров существующих учётных записей пользователей. Она имеет практически тот же набор ключей, что и `useradd`, что логично: если параметр можно задать при создании, его же можно и изменить впоследствии.

- **Контекст/Уровень:** Системное администрирование / Управление пользователями.
- **Основное назначение:** Изменение параметров существующих учётных записей пользователей.
- **Принцип работы:** `usermod` (user modify) изменяет записи в файлах `/etc/passwd`, `/etc/shadow` и `/etc/group` с помощью соответствующих ключей.

### 1.1. Базовый синтаксис

```bash
sudo usermod [ключи] username
```

Для изменения пользователя требуются права суперпользователя (`sudo`).

---

## 2. Блокировка и разблокировка пользователя

### 2.1. Блокировка — `-L` (Lock)

```bash
sudo usermod -L username
```

- Запрещает вход пользователя в систему. 
- Пользователь при попытке входа получает сообщение об ошибке аутентификации (без указания причины)

### 2.2. Разблокировка — `-U` (Unlock)

```bash
sudo usermod -U username
```

- Восстанавливает возможность входа.

### 2.3. Механизм блокировки

Блокировка реализуется добавлением символа `!` (восклицательный знак) в начало хэша пароля в файле `/etc/shadow`. При разблокировке этот символ удаляется.

**Проверка:**
```bash
sudo cat /etc/shadow | grep username
```

- **Заблокированный:** `username:!$6$...`
- **Разблокированный:** `username:$6$...`

Для быстрого просмотра последних строк файла можно использовать `tail`:

```bash
sudo tail /etc/shadow
```

> **Почему `!` блокирует вход?**  
> Символ `!` делает хэш пароля невалидным — система не может проверить пароль, потому что он начинается с недопустимого символа. В результате аутентификация всегда проваливается.

> **Важное замечание об ошибке аутентификации:** В комментариях к уроку было отмечено, что корректный термин — «аутентификация», а не «авторизация». Блокировка предотвращает именно этап проверки подлинности (аутентификации), а не проверку прав доступа (авторизацию).

## 3. Изменение домашнего каталога

### 3.1. Изменение пути — `-d` (home directory)

```bash
sudo usermod -d /new/home/path username
```

- Изменяет запись о домашнем каталоге в файле `/etc/passwd`. 
- **Не создаёт новую папку автоматически**.

### 3.2. Изменение пути с созданием папки — `-m` (move)

```bash
sudo usermod -m -d /new/home/path username
```

- Ключ `-m` (move) перемещает содержимое старого домашнего каталога в новый. 
- Новый каталог создаётся автоматически.

> **Важное замечание о `-m`:**  
> Ключ `-m` не только создаёт новую папку, но и **перемещает** содержимое старого домашнего каталога в новый. Если старого каталога не было, `-m` просто создаст пустую новую папку.

### 3.3. Пример: добавление домашнего каталога пользователю без него

Если пользователь был создан без домашнего каталога (например, через `sudo useradd officemanager` без ключа `-m`), ему можно добавить каталог в три шага:

1. **Указать путь в `/etc/passwd`:**
   ```bash
   sudo usermod -d /home/officemanager officemanager
   ```
2. **Создать папку физически:**
   ```bash
   sudo mkdir /home/officemanager
   ```
3. **Назначить владельца и группу:**
   ```bash
   sudo chown officemanager:officemanager /home/officemanager
   ```

> **Примечание:** Создание папки в `/home` требует прав root, поэтому используется `sudo mkdir`. Команда `chown` также требует `sudo`, так как изменяет владельца системного файла.

> **Важное замечание о правах:** Без третьего шага папка будет принадлежать `root`, и пользователь не сможет создавать там файлы или сохранять настройки. Команда `chown` (change owner) назначает правильного владельца и группу.

> **Дополнительное замечание:** В файле `/etc/passwd` путь к домашнему каталогу может существовать ещё до его физического создания. Это не ошибка — запись в файле и фактическое наличие папки независимы.

## 4. Изменение командной оболочки — `-s` (shell)

Командная оболочка (shell) определяет среду, в которой пользователь работает после входа.

### 4.1. Синтаксис

```bash
sudo usermod -s /path/to/shell username
```

### 4.2. Пример: смена оболочки на `/bin/bash`

```bash
sudo usermod -s /bin/bash officemanager
sudo usermod -s /bin/bash smileygirl
```

### 4.3. Распространённые оболочки

| Оболочка | Описание |
| :--- | :--- |
| `/bin/bash` | Bourne Again Shell — наиболее распространённая, богатая функциональностью. |
| `/bin/sh` | Bourne Shell — более простая, часто является ссылкой на `bash` в совместимом режиме. |
| `/bin/zsh` | Z Shell — расширенная альтернатива `bash`. |
| `/usr/sbin/nologin` | Запрещает вход (используется для системных пользователей). |
| `/bin/false` | Немедленно завершает сессию (также запрещает вход). |
*Таб. 1. Распространённые командные оболочки.*

> **Пример различия:**  
> - Если пользователь с оболочкой `/usr/sbin/nologin` попытается войти, он увидит сообщение «This account is currently not available».  
> - Если пользователь с оболочкой `/bin/false` попытается войти, сессия завершится немедленно без какого-либо сообщения.  
>  
> Обе оболочки используются для системных учётных записей (демонов), которые не должны иметь интерактивный вход.

### 4.4. Проверка изменений

```bash
cat /etc/passwd | grep username
```

В последнем поле строки будет указана новая оболочка.

## 5. Другие полезные ключи `usermod`

| Ключ | Описание | Пример |
| :--- | :--- | :--- |
| `-g <группа>` | Изменить основную группу. | `sudo usermod -g developers username` |
| `-G <группы>` | Задать дополнительные группы (список через запятую). | `sudo usermod -G sudo,www-data username` |
| `-a -G <группы>` | Добавить в дополнительные группы (без удаления существующих). | `sudo usermod -a -G docker username` |
| `-u <UID>` | Изменить UID пользователя. | `sudo usermod -u 2000 username` |
| `-l <новый_логин>` | Изменить логин пользователя. | `sudo usermod -l newname oldname` |
| `-e <YYYY-MM-DD>` | Установить дату истечения учётной записи. | `sudo usermod -e 2025-12-31 username` |
*Таб. 2. Дополнительные ключи `usermod`.*

> **Сокращённая форма `-aG`:**  
> Вместо `-a -G` можно использовать `-aG`. Это одно и то же: `sudo usermod -aG sudo username`.

> **Важное замечание о `-a -G`:** При добавлении в дополнительные группы **обязательно** используйте ключ `-a` (append). Без него существующие членства в дополнительных группах будут удалены, и останутся только указанные. Например, без `-a` команда `sudo usermod -G sudo username` удалит пользователя из всех групп, кроме `sudo`.

> **Дополнительная информация об изменении логина:** При изменении логина через `-l` не забудьте также обновить домашний каталог и владельца файлов, если они привязаны к старому имени.

> **Зачем нужен ключ `-e`?**  
> Ключ `-e` позволяет установить дату автоматической блокировки учётной записи. Это полезно для временных сотрудников, стажёров или гостевых пользователей.

## 6. Прямое редактирование файлов пользователей (не рекомендуется)

Технически информацию о пользователях можно изменять, редактируя файлы:
- `/etc/passwd` — основная информация.
- `/etc/shadow` — хэши паролей.
- `/etc/group` — информация о группах.

**Почему этого лучше не делать:**
- Нет проверок на корректность формата.
- Ошибка может привести к невозможности входа в систему.
- Можно случайно удалить или повредить системные учётные записи.
- Специализированные команды (`usermod`, `useradd`, `passwd`) выполняют необходимые проверки и обеспечивают целостность данных.

## 7. Практические примеры

### 7.1. Блокировка и разблокировка пользователя

```bash
sudo usermod -L outgoinghr   # заблокировать
sudo usermod -U outgoinghr   # разблокировать
```

### 7.2. Смена домашнего каталога

```bash
sudo usermod -d /home/newoffice officemanager
sudo mkdir /home/newoffice
sudo chown officemanager:officemanager /home/newoffice
```

### 7.3. Смена оболочки

```bash
sudo usermod -s /bin/bash smileygirl
```

### 7.4. Добавление пользователя в группу `sudo`

```bash
sudo usermod -a -G sudo officemanager
```

> **Важное замечание:** Ключ `-a` (append) обязателен, чтобы не удалить пользователя из других дополнительных групп.

### 7.5. Изменение логина

```bash
sudo usermod -l new_username old_username
```

## 8. Разбор сложных ситуаций и типичных вопросов

### 8.1. Ошибка аутентификации vs авторизации

**Вопрос:** *При блокировке пользователь получает сообщение об ошибке авторизации. Это корректный термин?*

**Ответ:** Строго говоря, это ошибка **аутентификации** (проверка подлинности), а не авторизации (проверка прав доступа). Блокировка через `-L` предотвращает именно этап проверки подлинности. Однако в обиходе эти термины часто смешивают, что не является критичной ошибкой.

### 8.2. Может ли заблокированный пользователь угадать пароль?

**Вопрос:** *Есть ли шанс, что заблокированный пользователь угадает пароль?*

**Ответ:** Шансы стремятся к нулю. Блокировка добавляет `!` в начало хэша, что делает хэш невалидным. Теоретически можно подобрать пароль, хэш которого совпадёт с новым значением, но на практике это невозможно.

### 8.3. Как посмотреть текущую оболочку и список доступных?

**Вопрос:** *Как узнать, какая оболочка используется сейчас, и какие оболочки доступны в системе?*

**Ответ:** Текущую оболочку можно посмотреть с помощью переменной `$SHELL`:
```bash
echo $SHELL
```

Список всех доступных оболочек хранится в файле `/etc/shells`:
```bash
cat /etc/shells
```

Также существует команда `chsh` (change shell), которая позволяет изменить оболочку без использования `usermod`.

### 8.4. Почему у пользователя есть путь в `/etc/passwd`, но нет папки?

**Вопрос:** *В файле `/etc/passwd` у пользователя указан домашний каталог, но физически папки нет. Почему?*

**Ответ:** Это нормально. Запись в `/etc/passwd` — это только указание пути. Физическое создание папки происходит только при использовании ключа `-m` при создании пользователя или при ручном создании через `mkdir`. Поэтому запись может существовать, а папки — нет.

### 8.5. Как изменить оболочку с помощью `chsh`?

**Вопрос:** *Существует ли альтернативный способ изменить оболочку?*

**Ответ:** Да, команда `chsh` (change shell) позволяет изменить оболочку без использования `usermod`. Синтаксис:
```bash
sudo chsh -s /bin/bash username
```

> **Важное замечание:** Если вы меняете оболочку для своей собственной учётной записи, `sudo` не требуется — просто введите `chsh -s /bin/bash` и введите свой пароль. `sudo` нужен только при изменении оболочки для другого пользователя.

---

## 9. Лимиты, оптимизация и масштабирование

- **Использование `usermod`:** Основной и безопасный способ изменения параметров пользователей.
- **Прямое редактирование файлов:** Возможно, но крайне не рекомендуется из-за высокого риска повреждения системы.
- **Блокировка через `-L`:** Используется для временного отключения учётной записи без удаления данных.

## 10. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Прямое редактирование файлов:** Несанкционированное или ошибочное редактирование `/etc/passwd`, `/etc/shadow` или `/etc/group` может привести к потере доступа к системе или компрометации учётных записей.
- **Блокировка учётных записей:** Используется для временного отключения учётной записи, например, при подозрении на компрометацию.
- **Безопасность паролей:** Пароли хранятся в зашифрованном виде в `/etc/shadow`. Убедитесь, что только root имеет доступ к этому файлу.

### 2. Инженерный FAQ

- **Вопрос:** *Как посмотреть все доступные оболочки в системе?*  
  **Ответ:** Файл `/etc/shells` содержит список всех оболочек, разрешённых для использования.

- **Вопрос:** *Что делать, если после изменения домашнего каталога пользователь не может войти?*  
  **Ответ:** Проверьте права на новый каталог (`ls -ld /home/newpath`). Если владелец — `root`, исправьте через `sudo chown username:username /home/newpath`.

- **Вопрос:** *Можно ли изменить оболочку с помощью `chsh`?*  
  **Ответ:** Да, `sudo chsh -s /bin/bash username` меняет оболочку без использования `usermod`.

## 11. Итоговая шпаргалка по командам

| Действие | Команда |
| :--- | :--- |
| Блокировка пользователя | `sudo usermod -L username` |
| Разблокировка | `sudo usermod -U username` |
| Изменить домашний каталог | `sudo usermod -d /path username` |
| Изменить домашний каталог с перемещением содержимого | `sudo usermod -m -d /path username` |
| Изменить оболочку | `sudo usermod -s /bin/bash username` |
| Изменить основную группу | `sudo usermod -g groupname username` |
| Добавить в дополнительные группы | `sudo usermod -a -G group1,group2 username` |
| Изменить логин | `sudo usermod -l newname oldname` |
| Установить срок действия учётной записи | `sudo usermod -e 2025-12-31 username` |
| Показать текущую оболочку | `echo $SHELL` |
| Показать доступные оболочки | `cat /etc/shells` |
| Изменить оболочку через `chsh` | `sudo chsh -s /bin/bash username` |
*Таб. 3. Итоговая шпаргалка по командам.*

### Ключевые понятия:

- **Блокировка** добавляет символ `!` в начало хэша пароля в `/etc/shadow`.
- Команды `useradd` и `usermod` используют одинаковый набор ключей.
- **Прямое редактирование** файлов `/etc/passwd`, `/etc/shadow`, `/etc/group` возможно, но опасно и не рекомендуется.
- При добавлении в дополнительные группы **обязателен ключ `-a`**, иначе существующие членства будут удалены.
- В файле `/etc/passwd` путь к домашнему каталогу может существовать без физической папки.

## Заключение

В этой теме были рассмотрены основные возможности команды `usermod` для изменения параметров существующих пользователей: блокировка и разблокировка, изменение домашнего каталога, командной оболочки, групп, UID, логина и срока действия учётной записи. Важно понимать механизм блокировки через `/etc/shadow` и всегда использовать `usermod` вместо ручного редактирования системных файлов. Ключ `-a` обязателен при добавлении в дополнительные группы, чтобы случайно не удалить существующие привилегии.
