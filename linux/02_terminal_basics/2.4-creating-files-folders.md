# Тема 2.4: Создание файлов и папок

В данной теме рассматриваются основные команды для создания файлов и каталогов в Linux: `mkdir`, `touch`, `tree`, а также способы создания файлов с содержимым через перенаправление вывода (`>`) и команду `cat`. Разбираются ключевые особенности файловой системы Linux: регистрозависимость имён, роль расширений, права доступа и использование `sudo`. В конце приведены практические рекомендации, разбор типичных ошибок и ответы на часто задаваемые вопросы.

---

## 1. Создание каталогов — Базовые свойства

* **Контекст/Уровень:** Системное администрирование / Файловая система.
* **Основное назначение:** Создание новых каталогов (директорий) для организации файловой структуры.
* **Принцип работы:** Команда `mkdir` (Make Directory) создаёт один или несколько каталогов в указанном пути. При необходимости может создавать вложенные структуры с помощью ключа `-p`.

### 1.1. Команда `mkdir` — создание каталогов

```bash
mkdir [ключи] [путь/имя_каталога]
```

**Базовое использование:**

```bash
mkdir LinuxCourse          # создать каталог LinuxCourse в текущей директории
mkdir folder1 folder2      # создать несколько каталогов одновременно
```

**Создание вложенной структуры (ключ `-p`):**

```bash
mkdir -p parent/child/grandchild
```

**Действие:** Ключ `-p` (parents) позволяет создавать цепочки вложенных каталогов одной командой. Если промежуточные каталоги отсутствуют, они будут созданы автоматически.

**Пример структуры после выполнения `mkdir -p 2/3/4`:**
```
2/
└── 3/
    └── 4/
```

> **Пример с относительным путём:** Если вы находитесь в `/home/itguy` и хотите создать папку `Projects` внутри `Documents`, можно использовать относительный путь: `mkdir Documents/Projects`.

> **Примечание:** Этот приём особенно полезен при разворачивании проектов, когда нужно создать полную структуру каталогов одной командой, а не вводить `mkdir` для каждой папки отдельно.

> **Рекомендация:** После создания каталога полезно проверить его наличие командой `ls -l`. В выводе вы увидите новую запись с правами доступа, владельцем и временем создания.

### 1.2. Права доступа и ошибка `Permission denied`

Если при создании каталога возникает ошибка:
```
mkdir: cannot create directory 'name': Permission denied
```
**Причина:** У пользователя нет прав на запись в текущую или целевую директорию.

**Пример:** Если вы находитесь в своей домашней директории (`~`) и пытаетесь создать папку в корневой директории (`/`), обычный пользователь не имеет на это прав, потому что корневая директория защищена.

**Решение:** Если каталог действительно должен создаваться в указанном месте, используйте `sudo` для получения прав суперпользователя:

```bash
sudo mkdir /protected_folder
```

> **Важно:** При использовании `sudo` каталог создаётся с правами владельца `root`. Если путь начинается с `/` (корневая директория), каталог будет создан в корне файловой системы, а не в текущей директории.

### 1.3. Регистрозависимость имён в Linux

В Linux имена файлов и каталогов **регистрозависимы**:
- `folder1` и `Folder1` — это **разные** каталоги.
- В Windows имена, отличающиеся только регистром, считаются одинаковыми.

> **Важно:** Это ключевое отличие Linux от Windows. При работе в терминале всегда учитывайте регистр символов.

## 2. Просмотр структуры каталогов — Базовые свойства

* **Контекст/Уровень:** Системное администрирование / Файловая система.
* **Основное назначение:** Визуализация структуры каталогов в наглядном виде.
* **Принцип работы:** Утилита `tree` рекурсивно обходит указанную директорию и выводит её содержимое в виде древовидной схемы.

### 2.1. Установка и использование `tree`

Утилита `tree` не входит в базовую поставку Ubuntu и требует установки:

```bash
sudo apt install tree
```

**Использование:**

```bash
tree                # показать структуру текущей директории
tree /home          # показать структуру указанной директории
```

**Пример вывода:**
```
/home/
├── itguy/
│   ├── Documents/
│   │   └── notes.txt
│   └── Downloads/
└── root/
```

## 3. Создание файлов — Базовые свойства

* **Контекст/Уровень:** Системное администрирование / Файловая система.
* **Основное назначение:** Создание новых файлов (пустых или с содержимым).
* **Принцип работы:** В Linux существует несколько способов создания файлов: `touch` для пустых файлов, перенаправление вывода (`>`) для файлов с текстом, `cat` для многострочного ввода.

### 3.1. `touch` — создание пустого файла или обновление даты

```bash
touch [имя_файла]
```

**Действие:**
- Если файл **не существует** — создаётся пустой файл.
- Если файл **существует** — обновляется временная метка последнего изменения (mtime), содержимое не изменяется.

**Пример:**
```bash
touch file.txt      # создать пустой файл file.txt
```

### 3.2. Перенаправление вывода (`>`) — создание файла с содержимым

**Через команду `echo`:**

```bash
echo "some text" > file1.txt
```

**Действие:** Создаёт файл `file1.txt` с указанным содержимым. Если файл уже существует, его содержимое **полностью перезаписывается**.

**Без `echo` (только перенаправление):**

```bash
> file2.txt
```

**Действие:** Создаёт пустой файл `file2.txt` (аналог `touch`).

> **Примечание о пробелах:** Символы перенаправления (`>`, `>>`, `<`) служат разделителями для командной оболочки. Пробел между командой и символом не обязателен, но для читаемости скриптов его рекомендуется ставить.

### 3.3. `cat` — создание файла с многострочным содержимым

```bash
cat > file3.txt
```

**Действие:** Команда переводит терминал в режим ввода:
1. Вводите строки текста, нажимая `Enter` после каждой.
2. Для завершения ввода нажмите `Ctrl + D`.

> **Примечание:** `Ctrl + D` — это не комбинация для удаления или выхода из программы, а сигнал конца ввода (EOF). Если вы случайно нажали `Ctrl + D` раньше времени, просто продолжите ввод с новой строки.

**Проверка результата:**

```bash
cat file3.txt       # вывести содержимое файла в терминал
```

> **Важно:** Основное назначение команды `cat` — **вывод содержимого файлов**. Создание файлов через `cat >` является побочным применением. Команда `cat` также позволяет объединять (конкатенировать) несколько файлов.

**Разница между `>` и `>>`:**  
`>` создаёт новый файл или перезаписывает существующий, а `>>` всегда дописывает в конец, не удаляя старое содержимое. Это важно при работе с логами или конфигурационными файлами, где нужно сохранять историю изменений.

**Пример:**
```bash
echo "Первая строка" > log.txt      # создаёт файл с одной строкой
echo "Вторая строка" >> log.txt     # дописывает вторую строку в конец
cat log.txt                         # выведет обе строки
```

### 3.4. Расширения файлов в Linux

В отличие от Windows, **Linux не использует расширения файлов для определения их типа**.
- Расширение (например, `.txt`, `.jpg`) является лишь частью имени и служит для удобства пользователя.
- Файлы могут **не иметь расширения** или иметь любое расширение, не соответствующее фактическому содержимому.
- Система определяет тип файла по его содержимому (magic bytes), а не по расширению.

## 4. Разбор сложных инженерных ситуаций и аномалий

### 4.1. Ошибка `Permission denied` при создании каталога
**Вопрос:** *Почему возникает ошибка `Permission denied` при использовании `mkdir`?*  
**Ответ:** Это происходит, когда у текущего пользователя нет прав на запись в текущую или целевую директорию. Для создания каталога в защищённых местах (например, в `/` или `/etc`) необходимо использовать `sudo`.

### 4.2. Путаница между `cd`, `ls` и `cat`
**Вопрос:** *Какой командой просматривать содержимое файла, а какой — содержимое папки?*  
**Ответ:**
- `cd` — **переход** в каталог, а не просмотр.
- `ls` — **просмотр содержимого каталога**.
- `cat` — **просмотр содержимого файла**.

### 4.3. Перезапись vs добавление (`>` vs `>>`)
**Вопрос:** *Команда `cat > file` перезаписывает файл или добавляет содержимое?*  
**Ответ:** `cat > file` **перезаписывает** файл. Для добавления (дозаписи) в конец файла используется `cat >> file` (два символа `>>`).

> **Важно:** Если вы случайно используете `>` вместо `>>`, вы можете потерять данные, так как `>` полностью очищает файл перед записью.

> **Важно:** Потеря данных из-за случайного использования `>` вместо `>>` часто необратима. Особенно это критично при работе с конфигурационными файлами или логами, где важна каждая строка.

### 4.4. Разница между `touch` и `>`
**Вопрос:** *В чём разница между `touch file` и `> file`?*  
**Ответ:** Обе команды создают пустой файл, но:
- `touch` также обновляет временную метку существующего файла.
- `> file` перезаписывает существующий файл пустым содержимым (т.е. очищает его).

**Пример сценария:** Если вы хотите создать пустой файл для будущей записи логов, лучше использовать `touch` — он не повредит уже существующий файл. Если же вы точно уверены, что файл нужно очистить, используйте `>`.

### 4.5. Создание файла без пробела после `>`
**Вопрос:** *Обязательно ли ставить пробел после `>`? Например, `>123` тоже создаёт файл.*  
**Ответ:** Да, `>123` тоже создаст файл, потому что символы перенаправления служат разделителями для командной оболочки. Однако в рабочих скриптах рекомендуется ставить пробел для читаемости.

## 5. Лимиты, оптимизация и масштабирование

- **Ключ `-p` экономит время:** Вместо нескольких команд `mkdir` для создания вложенной структуры можно использовать один вызов с `-p`.
- **Регистрозависимость требует внимания:** В Linux `file` и `File` — разные имена. Это необходимо учитывать при написании скриптов и работе в терминале.
- **Расширения не влияют на поведение системы:** В отличие от Windows, в Linux расширение файла не определяет, как система его обрабатывает. Это важно помнить при переносе скриптов между ОС.
- **Многообразие способов создания файлов:** Linux предлагает несколько способов сделать одно и то же (`touch`, `>`, `cat >`). Выбор зависит от контекста: пустой файл, одна строка, много строк.
- **Права доступа:** Использование `sudo` без понимания последствий может привести к созданию файлов и каталогов с правами `root`, что усложнит их последующее редактирование обычным пользователем. Чтобы изменить права доступа, используется команда `chmod` (будет рассмотрена в одном из следующих уроков).

> **Важно:** Команда `echo "text" > file` также перезаписывает файл, если он уже существует. Это один из самых частых источников случайной потери данных среди новичков.

## 6. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Ошибки прав доступа и `sudo`:** Использование `sudo` без понимания последствий может привести к созданию файлов и каталогов с правами `root`, что усложнит их последующее редактирование обычным пользователем.
- **Регистрозависимость и скрипты:** Если в скриптах не учитывать регистр, возможны ошибки «файл не найден», которые могут привести к некорректной работе системы.
- **Расширения и обман:** Так как Linux не полагается на расширения, злоумышленник может назвать вредоносный скрипт `image.jpg`, и система не будет считать это подозрительным. Пользователь должен проверять содержимое файлов командой `file`.

### 2. Инженерный FAQ (На основе разбора дискуссий)

- **Вопрос:** *Почему `cat > file` перезаписывает файл, а не добавляет текст?*  
  **Ответ:** Символ `>` означает перенаправление с перезаписью. Для добавления используется `>>`.

- **Вопрос:** *Какая команда показывает содержимое файла?*  
  **Ответ:** Основная команда для просмотра содержимого файла — `cat`. Также можно использовать `less` или `more` для больших файлов — они позволяют листать содержимое постранично и не забивают терминал.

- **Вопрос:** *Если выполнить `tree` в корневой директории, что произойдёт?*  
  **Ответ:** Команда выведет всю структуру файловой системы. Это может занять значительное время, поэтому рекомендуется избегать `tree /` на больших системах.

- **Вопрос:** *Можно ли остановить `tree`, если он уже запущен и выводит слишком много?*  
  **Ответ:** Да, нажмите `Ctrl + C`, чтобы прервать выполнение команды. Это стандартный способ остановить любую команду в терминале.

- **Вопрос:** *Что делать, если `mkdir` пытается создать уже существующую папку?*  
  **Ответ:** Команда `mkdir` выдаст ошибку `File exists`, если папка уже существует. Чтобы избежать этого и не прерывать выполнение скрипта, можно использовать ключ `-p` — он создаёт папку, если её нет, и просто пропускает шаг, если она уже есть.

- **Вопрос:** *Что означают записи `.` и `..` в выводе `ls -la`?*  
  **Ответ:** `.` (одна точка) — ссылка на текущий каталог. `..` (две точки) — ссылка на родительский каталог.

## 7. Итоговая шпаргалка

| Команда    | Пример                   | Назначение                                              |
| :--------- | :----------------------- | :------------------------------------------------------ |
| `mkdir`    | `mkdir folder`           | Создать каталог                                         |
| `mkdir -p` | `mkdir -p a/b/c`         | Создать вложенную структуру                             |
| `tree`     | `tree /home`             | Показать структуру каталогов                            |
| `touch`    | `touch file.txt`         | Создать пустой файл или обновить дату                   |
| `echo >`   | `echo "text" > file.txt` | Создать файл с содержимым (с перезаписью)               |
| `>`        | `> file.txt`             | Создать пустой файл (с перезаписью)                     |
| `cat >`    | `cat > file.txt`         | Создать файл с многострочным содержимым (с перезаписью) |
| `cat >>`   | `cat >> file.txt`        | Добавить содержимое в конец файла (без перезаписи)      |
*Таб. 1. Итоговая шпаргалка по командам для создания файлов и папок.*

## Заключение

Команды `mkdir`, `touch`, `cat`, `tree` и механизмы перенаправления вывода являются основой для управления файловой системой в Linux. Понимание регистрозависимости, прав доступа и роли расширений позволяет эффективно создавать и организовывать файлы и каталоги. Эти навыки необходимы для дальнейшего изучения более сложных операций с файлами и директориями.
