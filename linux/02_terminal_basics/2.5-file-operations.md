# Тема 2.5: Основные операции с файлами

В данной теме рассматриваются основные операции с файлами и каталогами в Linux: копирование (`cp`), перемещение и переименование (`mv`), удаление (`rm`). Разбираются ключевые особенности каждой команды, важные ключи (`-r`, `-f`, `-i`), использование шаблонов (wildcards) и предостережения, связанные с безвозвратным удалением данных. В конце приведены практические рекомендации, разбор типичных ошибок и ответы на часто задаваемые вопросы.

---

## 1. Копирование файлов и каталогов — Базовые свойства

* **Контекст/Уровень:** Системное администрирование / Файловая система.
* **Основное назначение:** Создание копий файлов и каталогов для дублирования или резервного копирования.
* **Принцип работы:** Команда `cp` (Copy) создаёт точную копию указанного объекта в новом месте или под новым именем. Для копирования каталогов требуется ключ `-r` (рекурсивный обход).

### 1.1. Команда `cp` — копирование

```bash
cp [ключи] [исходный_объект] [целевой_объект]
```

**Копирование файлов:**

```bash
cp source_file destination_file
```

**Пример:**
```bash
cp newfile1.txt newfile1_copy.txt
```

**Копирование с использованием шаблонов (wildcards):**

Символ `*` (звёздочка) заменяет любую последовательность символов.

```bash
cp new* folder2/
```

**Действие:** Копирует все файлы, имена которых начинаются с `new`, в каталог `folder2`.

> **Важно:** Обратите внимание: `cp new* folder2/` копирует только файлы, имена которых начинаются с `new`. Папки с таким же началом имени не копируются — для них нужен ключ `-r` (например, `cp -r new* folder2/`).

**Копирование каталогов (ключ `-r`):**

Для копирования каталогов необходимо использовать ключ `-r` (recursive):

```bash
cp -r source_folder destination_folder
```

**Пример:**
```bash
cp -r folder2 folder2_copy
```

## 2. Перемещение и переименование — Базовые свойства

* **Контекст/Уровень:** Системное администрирование / Файловая система.
* **Основное назначение:** Перемещение файлов и каталогов между директориями, а также их переименование.
* **Принцип работы:** Команда `mv` (Move) выполняет перемещение, изменяя путь к объекту. Если целевой путь находится в той же директории, команда выполняет переименование.

### 2.1. Команда `mv` — перемещение и переименование

```bash
mv [исходный_объект] [целевой_объект]
```

**Перемещение файлов:**

```bash
mv file.txt destination_folder/
```

**Пример:** переместить все `.txt` файлы в каталог `folder1`:

```bash
mv *.txt folder1/
```

**Перемещение каталогов:**

```bash
mv source_folder destination_folder/
```

**Переименование (частный случай перемещения):**

В Linux нет отдельной команды для переименования. Переименование выполняется командой `mv`:

```bash
mv old_name.txt new_name.txt
```

> **Важно:** Команда `mv` работает как переименование только в том случае, если источник и цель находятся в одной директории. Если цель находится в другой директории, происходит перемещение.

## 3. Удаление файлов и каталогов — Базовые свойства

* **Контекст/Уровень:** Системное администрирование / Файловая система.
* **Основное назначение:** Удаление файлов и каталогов для освобождения места.
* **Принцип работы:** Команда `rm` (Remove) удаляет указанные объекты. Удаление происходит безвозвратно, без перемещения в корзину.

### 3.1. Команда `rm` — удаление

```bash
rm [ключи] [объект]
```

**Удаление файлов:**

```bash
rm file.txt
```

**Удаление каталогов (ключ `-r`):**

Для удаления каталога с содержимым требуется ключ `-r` (recursive):

```bash
rm -r folder_name
```

**Принудительное удаление (ключ `-f`):**

Ключ `-f` (force) подавляет запросы подтверждения и игнорирует несуществующие файлы:

```bash
rm -rf folder_name
```

> **Практический совет:** В повседневной работе старайтесь избегать `-f` без крайней необходимости. Для удаления важных файлов привыкайте использовать `-i` — он даёт время подумать. `-f` удобен в скриптах, но в руках новичка может стать причиной потери данных.

**Комбинирование ключей:**

Ключи можно объединять:

```bash
rm -rf folder_name          # рекурсивное принудительное удаление
rm -r -f folder_name        # то же самое
```

### 3.2. Важные предостережения

**Удаление не попадает в корзину.** Файлы, удалённые командой `rm`, не перемещаются в корзину и не могут быть восстановлены стандартными средствами. Удаление происходит безвозвратно.

**Отсутствие предупреждений.** По умолчанию `rm` не выводит запросов на подтверждение. Ключ `-i` (interactive) включает режим с подтверждением:

```bash
rm -i important_file.txt
```

**Защита корневой директории.** Начиная с определённой версии, `rm` включает защиту корневой директории. Без ключа `--no-preserve-root` команда `rm -rf /` не выполняется. 

> **Пояснение:** Это означает, что случайное выполнение `rm -rf /` просто выдаст ошибку. Но если вы намеренно добавите `sudo` и `--no-preserve-root`, защита отключается, и система уничтожается полностью. Поэтому не привыкайте проверять эту команду даже на тестовых машинах — однажды вы можете ошибиться с правами.

Чтобы действительно удалить корневую директорию, нужно использовать:

```bash
sudo rm -rf --no-preserve-root /
```

> **Важное предупреждение:** Эта команда практически полностью уничтожает систему. Выполнять её можно только на тестовой или виртуальной машине, но **ни в коем случае на рабочей системе**.

## 4. Разбор сложных инженерных ситуаций и аномалий

### 4.1. Почему `rm -rf /` не выполняется в современных системах?

**Вопрос:** *Почему команда `rm -rf /` не выполняется?*  
**Ответ:** Начиная с определённой версии, `rm` включает защиту корневой директории. Без ключа `--no-preserve-root` команда не выполняется. Чтобы действительно удалить корневую директорию, нужно использовать:

```bash
sudo rm -rf --no-preserve-root /
```

**Дополнение из обсуждения:** Пользователь, выполнивший эту команду на тестовой машине, описывает: *«Система разваливалась постепенно: сначала начали пропадать иконки приложений, потом отлетели виджеты и фон рабочего стола сменился на однотон. После перезагрузки попадаешь в GRUB, из которого уже ничего не сделать, так как ядро стерто.»*

> **Пояснение:** GRUB — это загрузчик Linux. Если ядро удалено, загрузчик не может загрузить систему, и даже переустановка становится сложной.

Это наглядная иллюстрация того, почему команда опасна.

### 4.2. Как защититься от случайного удаления?

**Вопрос:** *Как обезопасить себя от случайного использования `rm -rf`?*  
**Ответ:** Можно создать алиас, который всегда запрашивает подтверждение и защищает корневую директорию:

```bash
alias rm='rm -i --preserve-root'
```

Этот алиас можно добавить в `~/.bashrc`, чтобы он действовал при каждом запуске терминала. Это снижает риск случайного удаления, но не защищает от злоумышленника с правами `sudo`.

### 4.3. Как удалить каталог, не затронув файлы с похожими именами?

**Вопрос:** *Как удалить каталог, но не зацепить файлы с похожими именами?*  
**Ответ:** Используйте команду `find` для выбора нужных объектов с последующим удалением:

```bash
find /путь/к/директории -mindepth 1 ! -name "файл1" ! -name "файл2" -exec rm -rf {} +
```

Этот подход позволяет точно указать, что нужно удалить, а что сохранить. Конструкция `!(s*)` (extglob) в bash работает только после включения `shopt -s extglob`, поэтому `find` — более универсальный и надёжный вариант.

### 4.4. Как правильно использовать `mv` для перемещения в текущую или родительскую папку?

**Вопрос:** *Как переместить файл в текущую или родительскую папку без указания полного пути?*  
**Ответ:** Используйте специальные обозначения `.` (текущая) и `..` (родительская):
```bash
mv file.txt .      # переместить в текущую папку
mv file.txt ..     # переместить на уровень выше
```

### 4.5. Копирование метаданных: `cp` против `rsync`

**Вопрос:** *В чём разница между `cp` и `rsync` при копировании файлов?*  
**Ответ:** `rsync` — утилита для синхронизации файлов, которая сохраняет все метаданные (права доступа, временные метки, символические ссылки, расширенные атрибуты `xattr`). `cp` по умолчанию этого не делает. Кроме того, `rsync` позволяет копировать файлы по сети и возобновлять прерванное копирование. Для простых задач `cp` быстрее, но для сложных или для копирования с сохранением метаданных — `rsync` надёжнее.

## 5. Лимиты, оптимизация и масштабирование

- **Ключ `-r` обязателен для каталогов:** При работе с каталогами всегда используйте `-r`, иначе `cp` или `rm` выдадут ошибку.
- **Шаблоны (wildcards) ускоряют работу:** Использование `*` вместо перечисления всех файлов вручную экономит время и снижает вероятность ошибок.
- **Ключ `-i` спасает от ошибок:** Режим с подтверждением особенно полезен при удалении важных данных.
- **Безвозвратное удаление требует внимания:** В Linux нет корзины для командной строки. Удаляйте только то, в чём уверены.
- **`rsync` как альтернатива `cp` для сложных задач:** Утилита `rsync` сохраняет метаданные, права доступа и временные метки, чего `cp` по умолчанию не делает. Она также позволяет копировать файлы по сети и возобновлять прерванное копирование. Для простых задач `cp` быстрее, но для сложных — `rsync` надёжнее.

## 6. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Безвозвратное удаление:** Удаление через `rm` не оставляет следов в корзине. В случае компрометации системы злоумышленник может использовать `rm -rf`, чтобы скрыть следы активности.
- **Защита корневой директории:** Современные версии `rm` защищают корень по умолчанию. Однако использование `sudo rm -rf --no-preserve-root /` всё ещё возможно и приводит к полной потере системы.
- **Алиасы как средство защиты:** Настройка алиаса `alias rm='rm -i --preserve-root'` снижает риск случайного удаления, но не является панацеей. Если у злоумышленника есть права `sudo`, алиас не спасёт.

### 2. Инженерный FAQ (На основе разбора дискуссий)

- **Вопрос:** *Что произойдёт, если выполнить `rm -rf /`?*  
  **Ответ:** В современных системах команда не выполнится без ключа `--no-preserve-root`. Если же добавить `sudo` и `--no-preserve-root`, система будет полностью уничтожена — вплоть до невозможности загрузки.

- **Вопрос:** *Что такое `rsync` и чем он лучше `cp`?*  
  **Ответ:** `rsync` — утилита для синхронизации файлов, которая сохраняет права доступа, временные метки и символические ссылки. Она также позволяет копировать данные по сети и возобновлять прерванное копирование.

- **Вопрос:** *Как проверить результат операции?*  
  **Ответ:** После копирования, перемещения или удаления используйте `ls` или `ll`, чтобы убедиться в ожидаемом результате. Также можно использовать `tree` для проверки структуры.

- **Вопрос:** *Как отличить перемещение от переименования в `mv`?*  
  **Ответ:** Если источник и цель находятся в одной директории — это переименование. Если в разных — перемещение.

- **Вопрос:** *Существуют ли альтернативы `cp` для копирования метаданных?*  
  **Ответ:** Да, `rsync` и `xattr` позволяют работать с расширенными атрибутами файлов. `rsync` копирует их вместе с файлами, чего `cp` не делает.

- **Вопрос:** *Как правильно именовать файлы и папки в Linux?*  
  **Ответ:** Рекомендуется использовать **строчные буквы, без пробелов, с подчёркиваниями вместо пробелов** (например, `my_folder` вместо `my folder` или `my-folder`). В GNU-стандартах рекомендуется `ignore_space_change_flag`, а не `iCantReadThis`. Используйте `_` для разделения слов, оставьте заглавные буквы для макросов и констант.

- **Вопрос:** *Существует ли безопасный режим удаления, который бы запрашивал подтверждение на каждый шаг?*  
  **Ответ:** Да, ключ `-i` (interactive) включает режим с подтверждением для каждой операции: `rm -ir folder`. Это утомительно, но даёт время подумать.

- **Вопрос:** *Почему Linux считается лучше Windows, несмотря на опасные команды?*  
  **Ответ:** Linux даёт пользователю больше контроля (открытый исходный код, возможность настройки), считается более безопасным за счёт архитектуры и ограниченных прав пользователей. Кроме того, у него огромное сообщество, множество бесплатных инструментов, а также стабильность и производительность на серверах.

## Заключение

Команды `cp`, `mv` и `rm` являются основой для управления файлами и каталогами в Linux. Понимание их ключей (`-r`, `-f`, `-i`), использование шаблонов (`*`) и осознание безвозвратности удаления позволяют эффективно и безопасно управлять данными. Особое внимание следует уделять команде `rm -rf` — она является мощным инструментом, который при неосторожном использовании может привести к полной потере данных. Использование алиасов и интерактивных ключей (`-i`) снижает риск случайных ошибок.
