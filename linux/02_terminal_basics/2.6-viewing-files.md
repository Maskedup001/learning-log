# Тема 2.6: Просмотр файлов

В данной теме рассматриваются основные утилиты для просмотра текстовых файлов в терминале Linux: `wget` для загрузки файлов из интернета, `more` и `less` для постраничного просмотра, `head` для просмотра начала файла, `tail` для просмотра конца файла. Разбираются ключевые особенности каждой команды, важные ключи (`-n`, `-c`, `-N`, `-p`, `-i`, `-I`, `-s`), а также история возникновения `less` и `more`. В конце приведены практические рекомендации, разбор типичных ошибок и ответы на часто задаваемые вопросы.

---

## 1. Подготовка тестового файла — Базовые свойства

* **Контекст/Уровень:** Системное администрирование / Работа с текстовыми файлами.
* **Основное назначение:** Подготовка тестового файла для демонстрации команд просмотра.
* **Принцип работы:** Утилита `wget` загружает файл по указанному URL-адресу из интернета. Для очистки текущей директории используется `rm -r`.

В качестве тестового файла используется текст поэмы Шекспира «[Ромео и Джульетта](https://stepik.org/media/attachments/lesson/1101187/Romeo_and_Juliet_poem.txt)» — он достаточно длинный, чтобы наглядно продемонстрировать постраничный просмотр (`more`, `less`), и находится в свободном доступе.

### 1.1. Очистка текущей директории

```bash
rm -r *
```

**Действие:** Удаляет всё содержимое текущей директории. Удаление происходит безвозвратно.

> **Важно:** Команда `rm -r *` удаляет все файлы и папки в текущей директории. Перед выполнением этой команды всегда проверяйте, где вы находитесь, с помощью `pwd`. Если вы случайно окажетесь в `/` (корень) и выполните `rm -r *`, вы удалите все файлы и папки в корне — и это будет фатальная ошибка.

### 1.2. Скачивание файла из интернета (wget)

```bash
wget <URL>
```

**Действие:** Утилита `wget` загружает файл по указанному адресу.

**Пример (актуальная ссылка на момент написания):**

```bash
wget https://www.gutenberg.org/cache/epub/1513/pg1513.txt
```

> **Примечание о ссылках:** Ссылки на файлы в проекте Gutenberg могут меняться. Ниже приведены несколько проверенных вариантов (на момент создания конспекта):
> - `https://www.gutenberg.org/cache/epub/1513/pg1513.txt` (актуальная)
> - `https://www.gutenberg.org/files/1112/1112-0.txt` (работает, но может устареть)
> - `https://www.gutenberg.org/ebooks/1112.txt.utf-8` (современный вариант)

> **Совет:** Если `wget` не работает или зависает, попробуйте переместиться в домашнюю директорию (`cd ~`) или использовать `sudo` (если проблема в правах доступа).

### 1.3. Переименование файла

```bash
mv old_name.txt new_name.txt
```

**Пример:**

```bash
mv pg1513.txt romeo.txt
```

## 2. Постраничный просмотр: `more` и `less` — Базовые свойства

* **Контекст/Уровень:** Системное администрирование / Работа с текстовыми файлами.
* **Основное назначение:** Постраничный просмотр больших текстовых файлов без загрузки их целиком в память.
* **Принцип работы:** Утилиты `more` и `less` читают файл по частям, отображая только текущую страницу. Это позволяет работать с файлами любого размера без перегрузки памяти.

### 2.1. Исторический контекст: почему появились `more` и `less`

В конце 1970-х годов программисты начали массово пересаживаться со старых печатающих телетайпов (которые выдавали текст на бумажную ленту) на новые видеотерминалы с экранами. Экран того времени вмещал строго 24 строки текста.

Тогда возникла проблема: если использовать команду `cat` для чтения длинного файла, Unix выводила весь текст на экран со скоростью процессора. Строки проносились перед глазами за долю секунды — прочитать начало файла было физически невозможно, так как прокрутки на терминалах тогда ещё не существовало.

В 1978 году студент Калифорнийского университета в Беркли Дэниел Халберт написал утилиту `more`. Логика была простой: программа выводит ровно один экран текста (24 строки), замирает и пишет внизу `--More--`. Пользователь нажимает Пробел, и программа отображает следующий экран.

Однако `more` была «односторонней»: она умела читать только вперёд. Вернуться наверх было нельзя — приходилось закрывать программу и начинать сначала.

В 1984 году программист Марк Ноудол, уставший от этого ограничения, переписал утилиту с нуля, добавив ей возможность перемещаться по файлу в обоих направлениях (вверх и вниз), а также поиск по тексту. Поскольку в английском языке слова `more` (больше) и `less` (меньше) — антонимы, он назвал свою программу `less`. В мире Unix даже есть поговорка: *«Less is more, more or less»* («Меньше — это больше, плюс-минус»).

### 2.2. Команда `more` — постраничный просмотр (вперёд)

Команда `more` — старейшая утилита для постраничного просмотра текстовых файлов.

```bash
more [ключи] [имя_файла]
```

**Базовое использование:**

```bash
more filename.txt
```

| Клавиша | Действие |
| :--- | :--- |
| Пробел | Следующая страница |
| `Q` | Выход |
*Таб. 1. Клавиши управления в `more`.*

**Основные ключи:**

| Ключ | Действие |
| :--- | :--- |
| `-<число>` | Показывать указанное количество строк за раз |
| `+<число>` | Начать вывод с определённой строки |
| `+/<строка>` | Начать вывод со строки, содержащей указанный текст |
| `-s` | «Схлопывает» повторяющиеся пустые строки в одну |
*Таб. 2. Основные ключи команды `more`.*

**Примеры использования:**

```bash
more -10 filename.txt              # по 10 строк на страницу
more +145 filename.txt             # начать со 145-й строки
more +145 -5 filename.txt          # начать со 145-й строки, по 5 строк
more +/Romeo filename.txt          # начать со строки, содержащей Romeo
more -s filename.txt               # схлопнуть пустые строки
```

> **Важно:** Поиск в `more` чувствителен к регистру. Строка `+/romeo` не найдёт `Romeo`.

> **Примечание о ключе `-s`:** Поведение `more -s` может отличаться в зависимости от дистрибутива. В некоторых случаях пустые строки могут содержать невидимые пробелы или символы табуляции, и ключ `-s` их не схлопывает. В таких ситуациях рекомендуется использовать `less -s` — он работает надёжнее.

### 2.3. Команда `less` — постраничный просмотр (в обе стороны)

Команда `less` — более современная и функциональная альтернатива `more`. Название является игрой слов («less is more»).

```bash
less [ключи] [имя_файла]
```

**Базовое использование:**

```bash
less filename.txt
```

**Навигация в `less`:**

| Клавиша | Действие |
| :--- | :--- |
| Пробел | Страница вниз |
| `Page Down` | Страница вниз |
| `Page Up` | Страница вверх |
| Стрелка вверх / вниз | Построчная навигация |
| Стрелка влево / вправо | Горизонтальная прокрутка |
| `Q` | Выход |
*Таб. 3. Клавиши навигации в `less`.*

**Поиск в `less`:**

| Ключ | Действие |
| :--- | :--- |
| `-p "строка"` | Поиск по файлу (чувствительный к регистру) |
| `-i` | Регистронезависимый поиск (только для ASCII) |
| `-I` | Регистронезависимый поиск (для всех символов) |
| `-N` | Выводит номера строк |
*Таб. 4. Ключи поиска и нумерации строк в `less`.*

**Примеры использования:**

```bash
less -p"Romeo" filename.txt                # поиск Romeo (с учётом регистра)
less -i -p"romeo" filename.txt             # поиск без учёта регистра (ASCII)
less -Ip"romeo" filename.txt               # поиск без учёта регистра (все символы)
less -N filename.txt                       # вывести с номерами строк
less -N -i -p"romeo" filename.txt          # комбинирование опций
```

> **Примечание:** Если вы уже находитесь внутри `less`, вы можете нажать `/`, ввести текст для поиска и нажать Enter. Это работает без выхода из программы (утилиты).

> **Важно:** Ключи `-i` и `-I` отличаются: `-i` работает только для символов ASCII, `-I` — для всех символов (включая Unicode). В большинстве случаев `-i` достаточно, но для не-ASCII текстов лучше использовать `-I`.

## 3. Просмотр начала и конца файла: `head` и `tail` — Базовые свойства

* **Контекст/Уровень:** Системное администрирование / Работа с текстовыми файлами.
* **Основное назначение:** Быстрый просмотр первых или последних строк файла без открытия полноценного просмотрщика.
* **Принцип работы:** Команды `head` и `tail` по умолчанию выводят 10 строк и завершают работу, не загружая файл целиком.

### 3.1. `head` — просмотр начала файла

Команда `head` выводит первые строки файла.

```bash
head [ключи] [имя_файла]
```

**Базовое использование:**

```bash
head filename.txt          # по умолчанию 10 строк
```

**Управление количеством строк:**

```bash
head -n 5 filename.txt     # первые 5 строк
head -5 filename.txt       # то же самое (сокращённая запись)
```

**Вывод в байтах:**

```bash
head -c 47 filename.txt    # первые 47 байт
```

### 3.2. `tail` — просмотр конца файла

Команда `tail` выводит последние строки файла.

```bash
tail [ключи] [имя_файла]
```

**Базовое использование:**

```bash
tail filename.txt          # по умолчанию последние 10 строк
```

**Управление количеством строк:**

```bash
tail -n 3 filename.txt     # последние 3 строки
tail -3 filename.txt       # то же самое (сокращённая запись)
```

**Вывод в байтах:**

```bash
tail -c 100 filename.txt   # последние 100 байт
```

> **Полезный совет:** Команда `tail -f` позволяет отслеживать изменения в файле в реальном времени. Это особенно удобно для просмотра логов.

> **Пример:** если вы запустите `tail -f /var/log/syslog`, терминал будет показывать новые строки по мере их появления. Чтобы остановить, нажмите `Ctrl + C`.

## 4. Разбор сложных инженерных ситуаций и аномалий

### 4.1. Почему `wget` не скачивает файл?

**Вопрос:** *Почему `wget` не работает или зависает?*  
**Ответ:** Причин может быть несколько:
- Устаревшая или неверная ссылка (проверьте актуальность URL).
- Отсутствие прав на запись в текущую директорию (попробуйте `cd ~` или `sudo wget ...`).
- Проблемы с сетью или прокси (если вы работаете через WSL, возможно, требуется настройка прокси).

### 4.2. Путаница между `rm * -r` и `rm -r *`

**Вопрос:** *Какая команда верна: `rm * -r` или `rm -r *`?*  
**Ответ:** Обе команды рабочие и делают одно и то же. В Linux флаги можно указывать как до, так и после аргументов — с технической точки зрения это не имеет значения. Однако `rm -r *` — более каноничный вариант, и именно его рекомендуется использовать.

### 4.3. Почему `less` иногда является алиасом `more`?

**Вопрос:** *В некоторых дистрибутивах `less` является алиасом `more`. Это нормально?*  
**Ответ:** В некоторых системах `less` может быть настроен как алиас для `more`, но это не означает, что они идентичны. `less` всегда функциональнее `more`. Если `less` ведёт себя как `more`, проверьте настройки вашего терминала или установите `less` отдельно.

### 4.4. Почему ключ `-s` в `more` не всегда работает?

**Вопрос:** *Почему в `more -s` пустые строки не схлопываются?*  
**Ответ:** Ключ `-s` в `more` схлопывает только строки, состоящие только из символа переноса строки. Если в пустых строках есть невидимые пробелы или табуляция, `-s` не сработает. В таких случаях рекомендуется использовать `less -s`, который работает надёжнее и предсказуемее.

### 4.5. Почему поиск в `more` и `less` чувствителен к регистру?

**Вопрос:** *Почему поиск по умолчанию чувствителен к регистру?*  
**Ответ:** По умолчанию утилиты `more` и `less` используют чувствительный к регистру поиск, потому что так было реализовано исторически. Для регистронезависимого поиска в `less` используйте ключи `-i` (ASCII) или `-I` (все символы).

## 5. Лимиты, оптимизация и масштабирование

- **Утилиты не загружают файл целиком:** `more`, `less`, `head` и `tail` читают файл по частям, что позволяет работать с файлами любого размера без перегрузки памяти.
- **`less` функциональнее `more`:** `less` поддерживает навигацию в обе стороны, поиск с учётом регистра и без, нумерацию строк и другие возможности. В большинстве случаев `less` является предпочтительным выбором.
- **`head` и `tail` удобны для быстрого ознакомления:** Эти команды полезны, когда нужно быстро посмотреть начало или конец файла без открытия полноценного просмотрщика.
- **`tail -f` для отслеживания изменений:** Команда `tail -f` позволяет следить за изменениями в файле в реальном времени — это стандартный способ просмотра логов в Linux.

## 6. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Безвозвратное удаление:** Команда `rm -r *` безвозвратно удаляет всё содержимое текущей директории. Будьте внимательны при её использовании.
- **Скачивание файлов из интернета:** Всегда проверяйте источник файлов перед загрузкой. Скачивание из ненадёжных источников может привести к заражению системы вредоносным ПО.

### 2. Инженерный FAQ (На основе разбора дискуссий)

- **Вопрос:** *Что такое `less` и чем он отличается от `more`?*  
  **Ответ:** `less` — это более функциональная версия `more`, позволяющая перемещаться по файлу в обе стороны, искать текст и выводить номера строк. Её название — игра слов: «less is more».

- **Вопрос:** *Что такое `bat` и зачем он нужен?*  
  **Ответ:** `bat` — это современная альтернатива `cat` с подсветкой синтаксиса, нумерацией строк и интеграцией с Git. Она не является стандартной утилитой и требует установки, но может быть полезна для разработчиков.

- **Вопрос:** *Почему в этом уроке используются стихи Шекспира?*  
  **Ответ:** Это традиция — проект Gutenberg предоставляет бесплатные тексты классической литературы, которые идеально подходят для демонстрации работы с текстовыми файлами любого размера.

- **Вопрос:** *Как настроить общий буфер обмена между Windows и виртуальной машиной?*  
  **Ответ:** В настройках VirtualBox перейдите в «Общие» и установите «Буфер обмена» в значение «Двунаправленный». Если это не работает, проверьте, установлены ли гостевые дополнения.

- **Вопрос:** *А где `cat`?*  
  **Ответ:** Команда `cat` будет рассмотрена в следующих темах, посвящённых работе с содержимым файлов.

## Заключение

Утилиты `wget`, `more`, `less`, `head` и `tail` являются основными инструментами для загрузки и просмотра текстовых файлов в Linux. Понимание их ключей, умение выбирать подходящий инструмент для конкретной задачи и знание истории их возникновения позволяют эффективно и осознанно работать с текстовыми данными. Эти навыки необходимы для дальнейшего изучения более сложных операций с файлами и директориями.
