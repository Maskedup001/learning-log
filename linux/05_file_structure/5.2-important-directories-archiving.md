# Тема 5.2: Важные директории Linux, утилиты df/du, архивирование (tar и zip)

В данной теме рассматриваются стандартные директории корневой файловой системы Linux, утилиты для оценки дискового пространства (`df` и `du`), а также инструменты для архивирования и сжатия файлов (`tar` и `zip`). Разбираются ключевые различия между архивированием и сжатием, практические примеры и типичные ошибки.

---

## 1. Структура корневой директории Linux — Базовые свойства

- **Контекст/Уровень:** Системное администрирование / Файловая система.
- **Основное назначение:** Организация файловой системы Linux: исполняемые файлы, конфигурации, библиотеки, временные данные, логи и т.д.
- **Принцип работы:** Корневая директория (`/`) содержит стандартные каталоги, присутствующие во всех дистрибутивах Linux. Их расположение и назначение регламентируется стандартом FHS (Filesystem Hierarchy Standard).

### 1.1. Таблица важнейших директорий

| Директория | Назначение |
| :--- | :--- |
| `/bin` | Исполняемые файлы основных команд терминала (например, `ls`, `cp`, `mv`). |
| `/boot` | Файлы, необходимые для загрузки ядра операционной системы. |
| `/cdrom` | Историческая точка монтирования CD-дисков (в современных системах используется `/media` или `/mnt`). |
| `/dev` | Файлы устройств (устройства ввода-вывода, диски, терминалы). |
| `/etc` | Конфигурационные файлы системных служб и пользовательских программ. |
| `/home` | Домашние директории пользователей (например, `/home/username`). |
| `/lib`, `/lib32`, `/lib64` | Библиотеки, необходимые для работы системы и загрузки. |
| `/lost+found` | Восстановленные файлы после сбоя файловой системы (проверки `fsck`). |
| `/media` | Точка монтирования сменных носителей (USB-флешки, CD/DVD). |
| `/mnt` | Альтернативная точка для временного монтирования файловых систем. |
| `/opt` | Дополнительное программное обеспечение (optional). |
| `/proc` | Виртуальная файловая система с информацией о запущенных процессах. |
| `/root` | Домашняя директория суперпользователя (`root`). |
| `/run` | Файлы состояния приложений и Unix-сокеты (хранятся в оперативной памяти). |
| `/sbin` | Исполняемые файлы для администрирования (требуют прав `root`). |
| `/srv` | Данные сервисов (например, файлы веб-сервера, FTP). |
| `/tmp` | Временные файлы (очищаются при перезагрузке). |
| `/usr` | Пользовательские программы и данные (user). |
| `/var` | Переменные файлы: логи, кэши, очереди печати, базы данных. |

*Таб. 1. Стандартные директории корневой файловой системы Linux.*

> **Важное замечание о директории `/usr`:** Исторически `/usr` расшифровывалась как *user* (пользовательские данные). В ранних версиях Unix (1970-е) она действительно использовалась для хранения пользовательских данных. Со временем назначение изменилось, и сейчас она содержит разделяемые данные приложений, доступные только для чтения. Современная интерпретация — *Unix System Resources*. Изменяемые данные, специфичные для конкретного хоста, должны храниться в других местах (например, в `/var`).

> **Примечание о `/cdrom`:** В некоторых современных дистрибутивах (например, Debian 12) директория `/cdrom` может отсутствовать, так как CD/DVD-приводы стали редкостью. Это нормально.

## 2. Утилита `df` — информация о дисковом пространстве

- **Контекст/Уровень:** Системное администрирование / Мониторинг ресурсов.
- **Основное назначение:** Отображение информации об использовании дискового пространства всех смонтированных файловых систем.
- **Принцип работы:** `df` (disk free) сканирует смонтированные разделы и выводит данные о размере, занятом и свободном месте.

### 2.1. Базовое использование

```bash
df
```

### 2.2. Основные ключи

| Ключ | Описание |
| :--- | :--- |
| `-h` | Human-readable — размеры в КБ, МБ, ГБ. |
| `-T` | Показывает тип файловой системы. |
| `-i` | Показывает использование inodes (количество файлов). |
*Таб. 2. Основные ключи команды `df`.*

### 2.3. Примеры

```bash
df -h                     # удобочитаемый вывод всех файловых систем
df -hT                    # добавить тип файловой системы
df -h /                   # информация только о корневой файловой системе
df -i                     # информация об использовании inodes
```

### 2.4. Интерпретация вывода

**`df -h /`** показывает:
- `Size` — общий размер раздела.
- `Used` — занятое место.
- `Available` — свободное место.
- `Use%` — процент занятого места.

**`df -i`** показывает:
- `IUsed` — количество использованных inodes.
- `IFree` — количество свободных inodes.
- `IUse%` — процент использованных inodes.

> **Важное замечание об inodes:** В Linux невозможно создать новый файл, если закончились либо свободное место (в МБ), либо свободные inodes (квота на количество файлов). Однако в файловых системах нового поколения (например, Btrfs) inodes не фиксированы и распределяются динамически, поэтому `df -i` может показывать `0` — это нормально для таких файловых систем.

### 2.5. Определение точки монтирования устройства

При подключении внешнего носителя (флешки, CD-ROM, образа диска) он автоматически монтируется в `/media/<username>/<метка_устройства>`. Это можно увидеть в выводе `df -h`.

## 3. Утилита `du` — оценка размера директорий и файлов

- **Контекст/Уровень:** Системное администрирование / Мониторинг ресурсов.
- **Основное назначение:** Показывает, сколько места занимают файлы и директории.
- **Принцип работы:** `du` (disk usage) рекурсивно обходит указанные директории и суммирует размеры всех файлов.

### 3.1. Базовое использование

```bash
du ~                      # размер домашней директории (с разбивкой по подпапкам)
```

### 3.2. Основные ключи

| Ключ | Описание |
| :--- | :--- |
| `-h` | Human-readable — размеры в КБ, МБ, ГБ. |
| `-s` | Summary — только общий итог (без разбивки). |
| `-c` | Total — добавить строку с общим итогом в конце. |
| `-a` | Включить в вывод все файлы, а не только директории. |
| `--exclude="шаблон"` | Исключить файлы, соответствующие шаблону. |
| `--max-depth=N` | Ограничить глубину вывода (например, только первый уровень). |
*Таб. 3. Основные ключи команды `du`.*

### 3.3. Примеры

```bash
du -sh ~                  # общий размер домашней директории
du -h --max-depth=1 ~     # размер файлов и папок первого уровня вложенности
du -ch *.txt              # размер всех .txt файлов с итогом
du -sh --exclude="*.txt"  # размер всех файлов, кроме .txt
```

> **Важное замечание:** Ключ `-h` позволяет читать размеры в удобном формате, но при использовании в скриптах лучше использовать вывод без `-h` (в байтах) для автоматической обработки.

## 4. Архивирование и сжатие

В Linux **архивирование** (объединение файлов в один) и **сжатие** (уменьшение размера) — это разные операции, которые могут выполняться вместе или раздельно.

### 4.1. Утилита `tar` (стандартный инструмент)

`tar` (tape archive) объединяет файлы в один архив. Сжатие подключается отдельными ключами.

#### 4.1.1. Основные ключи `tar`

| Ключ | Описание |
| :--- | :--- |
| `-c` | Create — создать архив. |
| `-x` | Extract — извлечь файлы из архива. |
| `-t` | List — показать содержимое архива. |
| `-f` | File — указать имя файла архива. |
| `-v` | Verbose — подробный вывод (показывать имена файлов). |
| `-z` | Использовать сжатие gzip. |
| `-j` | Использовать сжатие bzip2. |
*Таб. 4. Основные ключи команды `tar`.*

> **Важное замечание о `-f`:** Ключ `-f` задаёт **имя создаваемого или извлекаемого архива**, а не то, что мы архивируем. Например, `tar -cf arch.tar *` создаст архив `arch.tar` из всех файлов в текущей директории.

#### 4.1.2. Создание архива (без сжатия)

```bash
tar -cf archive.tar file1.txt file2.txt
```

Размер такого архива может быть больше исходных файлов из-за служебной информации.

#### 4.1.3. Создание архива со сжатием (gzip)

```bash
tar -czf archive.tar.gz file1.txt file2.txt
```

Ключ `-z` добавляет сжатие. Файл получает расширение `.tar.gz` (или `.tgz`). Размер значительно меньше исходного.

> **Важное пояснение про `.tar.gz`:**  
> `tar` с ключом `-c` (без `-z`) создаёт **несжатый архив** с расширением `.tar`.  
> Если добавить ключ `-z`, то к этому архиву применяется утилита `gzip`, которая сжимает его, и тогда расширение становится `.tar.gz`.  
>  
> Таким образом, **расширение `.tar.gz` — это результат двух шагов**: сначала `tar` упаковывает файлы, затем `gzip` сжимает полученный архив.  
>  
> **Поэтому давать несжатому архиву расширение `.tar.gz` — некорректно**: это вводит в заблуждение при распаковке, потому что любой, кто увидит `.tar.gz`, будет ожидать, что файл сжат, и попытается извлечь его с ключом `-z`, что вызовет ошибку `not in gzip format`.

#### 4.1.4. Просмотр содержимого архива

```bash
tar -tf archive.tar       # список файлов в архиве
tar -tvf archive.tar      # подробный список (с правами, размерами)
```

#### 4.1.5. Извлечение файлов из архива

```bash
tar -xf archive.tar       # извлечь все файлы
tar -xzf archive.tar.gz   # извлечь из сжатого архива
```

### 4.2. Утилита `zip` / `unzip`

`zip` — более привычный для пользователей Windows формат архивации со встроенным сжатием.

#### 4.2.1. Установка

```bash
sudo apt install zip -y
```

#### 4.2.2. Создание zip-архива

```bash
zip archive.zip file1.txt file2.txt
zip archive.zip *.txt                 # все .txt файлы
zip -r archive.zip folder/            # рекурсивно добавить папку
```

#### 4.2.3. Извлечение из zip-архива

```bash
unzip archive.zip
unzip archive.zip -d target_folder/   # извлечь в указанную папку
```

#### 4.2.4. Просмотр содержимого zip-архива (без распаковки)

```bash
unzip -l archive.zip
unzip -v archive.zip
```

> **Важное замечание:** `zip` удобен для кроссплатформенной совместимости с Windows. В отличие от `tar`, он сохраняет структуру папок и может быть открыт штатными средствами Windows без дополнительных утилит.

### 4.3. Сравнение `tar` и `zip`

| Характеристика | `tar` | `zip` |
| :--- | :--- | :--- |
| Предустановлен | Да (в большинстве дистрибутивов) | Нет (требуется установка) |
| Сжатие | Отдельный ключ (`-z`, `-j`) | Встроенное |
| Расширение по умолчанию | `.tar`, `.tar.gz` | `.zip` |
| Сохраняет права доступа | Да | Частично |
| Популярность в Linux | Стандарт | Распространён, но не стандарт |
*Таб. 5. Сравнение `tar` и `zip`.*

> **Важное замечание о двойных расширениях:** Если вы создаёте архив без сжатия (`tar -cf`), не следует давать ему расширение `.tar.gz` — это вводит в заблуждение. Правильное расширение для несжатого архива — `.tar`. Расширение `.tar.gz` означает, что архив был сжат с помощью gzip.

## 6. Разбор сложных ситуаций и типичных вопросов

### 6.1. Почему `tar` без сжатия, а расширение `.tar.gz`?

**Вопрос:** *Почему в некоторых примерах архив создаётся без сжатия, но получает расширение `.tar.gz`? Это некорректно.*

**Ответ:** Да, это распространённая ошибка. `tar` с ключом `-c` (без `-z`) создаёт несжатый архив, который должен иметь расширение `.tar`. Если добавить расширение `.tar.gz`, это вводит в заблуждение, потому что файл на самом деле не сжат. Правильная команда для создания сжатого архива — `tar -czf archive.tar.gz`. В этом случае `-z` активирует сжатие, и расширение `.tar.gz` становится корректным.

### 6.2. Разница между `/usr` как «user» и «Unix System Resources»

**Вопрос:** *Что на самом деле означает `/usr`?*

**Ответ:** Исторически `/usr` расшифровывалась как *user* (пользовательские данные). Со временем назначение изменилось, и сейчас она содержит разделяемые данные приложений, доступные только для чтения. Современная интерпретация — *Unix System Resources*. Это важно: изменяемые данные должны храниться в `/var` или других местах, а не в `/usr`.

### 6.3. В каких случаях `df -i` показывает `0` inodes?

**Вопрос:** *Почему `df -i` иногда показывает `0` inodes? Это ошибка?*

**Ответ:** Это нормально для файловых систем нового поколения, таких как **Btrfs**. В традиционных системах (ext4) inodes фиксированы и подсчитываются. В Btrfs inodes распределяются динамически, поэтому `df -i` может показывать `0` — это не ошибка, а особенность файловой системы.

### 6.4. Как избежать сохранения полного пути в архиве tar?

**Вопрос:** *При распаковке архива tar получается длинная вложенная структура папок. Как этого избежать?*

**Ответ:** Чтобы в архив не попал полный путь, нужно перейти в директорию с файлами перед архивированием и указывать только имена файлов (без путей). Например:

```bash
cd ~/project/
tar -czf backup.tar.gz ./*
```

В этом случае при распаковке файлы окажутся в текущей директории, а не во вложенных папках.

### 6.5. Как склеить несколько частей архива tar?

**Вопрос:** *У меня есть несколько частей архива `archive.tar.gz.001`, `archive.tar.gz.002`... Как их правильно распаковать?*

**Ответ:** Сначала склейте все части в один файл с помощью `cat`, затем распакуйте:

```bash
cat *$(ls -v archive_name.tar.gz*) | tar xzf -
```

Или более простой вариант:
```bash
cat archive_name.tar.gz* > combined.tar.gz
tar -xzf combined.tar.gz
```

## 7. Лимиты, оптимизация и масштабирование

- **Inodes:** В традиционных файловых системах количество inodes фиксировано при создании раздела. Это ограничивает максимальное количество файлов. В Btrfs это ограничение отсутствует благодаря динамическому распределению.
- **Размер архива:** Несжатый архив `tar` может быть больше исходных файлов из-за служебной информации. Сжатие (`-z`, `-j`) уменьшает размер, но увеличивает время архивирования.
- **Выбор инструмента:** `tar` сохраняет права доступа и структуру директорий, что важно для системных бэкапов. `zip` удобен для кроссплатформенной совместимости.

## 8. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Права доступа в архивах:** При извлечении архивов важно проверять права доступа. Злоумышленник может создать архив с правами `777` или с исполняемыми файлами, которые могут навредить системе. Всегда распаковывайте архивы в изолированных директориях.
- **Символические ссылки в архивах:** В архивах могут содержаться символические ссылки. При распаковке они могут указывать на файлы вне целевой директории, что создаёт риск. Проверяйте содержимое архива перед распаковкой.
- **Заполнение диска:** Злоумышленник может использовать `du` для поиска больших файлов и заполнить диск, чтобы нарушить работу системы. Мониторинг дискового пространства — важная часть безопасности.

### 2. Инженерный FAQ

- **Вопрос:** *Почему `tar` остаётся стандартом, а `zip` не предустановлен по умолчанию?*  
  **Ответ:** `tar` изначально заточен под Unix-философию и сохраняет права доступа, что критично для системных бэкапов. `zip` — гость из мира Windows, удобный, но не всегда сохраняет атрибуты Unix. Однако в современных дистрибутивах `zip` часто предустановлен.

- **Вопрос:** *Можно ли использовать `7z` в Linux вместо `tar` и `zip`?*  
  **Ответ:** Да, `7z` (через утилиту `p7zip`) — хороший выбор для кроссплатформенной совместимости. Он поддерживается и в Windows, и в Linux.

- **Вопрос:** *Почему в некоторых дистрибутивах нет `/cdrom`?*  
  **Ответ:** `/cdrom` — историческая директория для монтирования CD/DVD. В современных дистрибутивах (например, Debian 12) она может отсутствовать, так как CD/DVD-приводы перестали быть стандартным оборудованием. Вместо неё используются `/media` и `/mnt`.

- **Вопрос:** *Что такое inodes?*  
  **Ответ:** Inodes (индексные дескрипторы) — это структуры данных, которые хранят метаинформацию о файлах (права доступа, владелец, размер, расположение на диске). В традиционных файловых системах количество inodes фиксировано при создании раздела, поэтому количество файлов ограничено.

## 9. Итоговая шпаргалка по теме 

| Тема | Команды / Ключи |
| :--- | :--- |
| Структура корневой директории | `/bin`, `/etc`, `/home`, `/var`, `/tmp` и др. |
| Просмотр дискового пространства | `df -h`, `df -i`, `df -hT` |
| Оценка размера файлов и папок | `du -sh`, `du -h --max-depth=1`, `du -a` |
| Архивирование без сжатия | `tar -cf archive.tar files` |
| Архивирование со сжатием | `tar -czf archive.tar.gz files` |
| Просмотр содержимого архива | `tar -tf archive.tar`, `tar -tvf archive.tar` |
| Извлечение архива | `tar -xf archive.tar`, `tar -xzf archive.tar.gz` |
| Работа с zip | `zip archive.zip files`, `unzip archive.zip`, `unzip -l archive.zip` |
*Таб. 7. Итоговая шпаргалка по командам и ключам.*

### Важные понятия:

- **inodes** — ограничение на количество файлов в файловой системе. В традиционных файловых системах (ext4) inodes фиксированы. В Btrfs inodes динамические, поэтому `df -i` может показывать `0`.
- Точки монтирования внешних носителей — `/media/<username>/`.
- В Linux **архивирование** (упаковка файлов в один) и **сжатие** (уменьшение размера) — это разные операции. `tar` упаковывает, `gzip` сжимает. Расширение `.tar.gz` — это результат двух шагов: сначала `tar`, затем `gzip`.
- **Ключ `-f`** в `tar` задаёт имя архива, а не то, что мы архивируем.
- Чтобы в архив не попал полный путь (и при распаковке не получилась «матрешка»), перейдите в папку с файлами (`cd`) и используйте `.`.
- `tar` сохраняет права доступа и структуру директорий — это стандарт для системных бэкапов. `zip` удобен для кроссплатформенной совместимости (Linux / Windows).

## Заключение

В этой теме были рассмотрены важнейшие системные директории Linux, утилиты для мониторинга дискового пространства (`df`, `du`) и инструменты архивирования (`tar`, `zip`). Понимание структуры файловой системы позволяет грамотно организовать данные, а навыки работы с архивами необходимы для бэкапов и переноса данных.
