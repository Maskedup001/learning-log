# Тема 5.3: Резюме модуля «Файловая структура». Контрольные вопросы

В данной теме представлены контрольные вопросы для самопроверки по модулю «Файловая структура». Вопросы охватывают системные каталоги Linux, точки монтирования, команды для работы с дисковым пространством (`df`, `du`) и поиск файлов (`find`). Каждый вопрос сопровождается правильным ответом и техническим пояснением. В конце приведён разбор типичных вопросов и нюансов из комментариев.

---

## 1. Контрольные вопросы (с разбором)

### Вопрос 1. В каком системном каталоге принято хранить глобальные конфигурационные файлы, общие для всех пользователей и служб системы?

**Варианты:**
- `/etc`
- `/bin`
- `/var`
- `~`
- `/config`

**Правильный ответ:** `/etc`.

**Пояснение:** Каталог `/etc` (et cetera) — это стандартное место для хранения конфигурационных файлов, общих для всей системы. В нём находятся настройки служб, сетевых интерфейсов, пользователей и т.д. Каталог `~/.config` используется для пользовательских настроек, а `/bin` — для исполняемых файлов.

---

### Вопрос 2. Какой каталог является точкой монтирования внешних дисков по умолчанию в дистрибутивах семейства Ubuntu (Debian)?

**Варианты:**
- `/dev`
- `/cdrom`
- `/tmp`
- `/media`
- `/bin`

**Правильный ответ:** `/media`.

**Пояснение:** В дистрибутивах семейства Ubuntu (Debian) внешние носители (флешки, жёсткие диски) автоматически монтируются в каталог `/media/<username>/<метка_устройства>`. Это стандартное поведение для современных дистрибутивов.

> **Важное замечание:** В некоторых дистрибутивах и окружениях (например, в среде KDE) точка монтирования может отличаться — `/run/media/$USER/mountpoint`. Однако в контексте семейства Ubuntu/Debian правильным ответом является `/media`.

---

### Вопрос 3. Какая команда из перечисленных позволит увидеть путь, по которому был смонтирован дополнительный диск?

**Варианты:**
- `tar -xf`
- `tree ~`
- `df -h`
- `du -sh`

**Правильный ответ:** `df -h`.

**Пояснение:** Команда `df -h` (disk free, human-readable) выводит информацию о всех смонтированных файловых системах, включая точку монтирования. Это позволяет увидеть, куда подключено устройство. `du -sh` показывает размер директорий, `tar -xf` извлекает архивы.

---

### Вопрос 4. Какой из следующих вариантов команды `find` корректно найдёт все файлы с именами из трёх символов в текущей директории и всех поддиректориях?

**Варианты:**
- `find -name *`
- `find * -name ???`
- `find . -name "???"`
- `find . -name "***"`

**Правильный ответ:** `find . -name "???"`.

**Пояснение:** Для поиска файлов с именем из ровно трёх символов используется ключ `-name` с шаблоном `???`, заключённым в кавычки. `find . -name "???"` найдёт файлы с любыми тремя символами (например, `abc.txt`, `123.txt`) в текущей директории и всех поддиректориях.

> **Важное замечание:** Ключ `-name` всегда ищет **только имена файлов**, а не пути. Если вы хотите искать по полным путям, используйте `-path` вместо `-name`. Это важно, потому что `find` без `-name` или с неправильным шаблоном может найти не то, что вы ожидаете.

## 2. Разбор сложных ситуаций и типичных вопросов

### 2.1. Глобальные конфигурационные файлы и пользовательские настройки

**Вопрос:** *Где хранятся глобальные конфигурационные файлы системы?*

**Ответ:** В каталоге `/etc`. Там находятся настройки служб, сетевых интерфейсов, пользователей — всё, что относится к системе в целом. Пользовательские настройки (например, для конкретного пользователя) хранятся в `~/.config`.

### 2.2. Точка монтирования внешних дисков

**Вопрос:** *Всегда ли внешние диски монтируются в `/media`?*

**Ответ:** В дистрибутивах семейства Ubuntu/Debian — да, по умолчанию это `/media/<username>/<метка_устройства>`. Однако в некоторых окружениях (например, KDE) используется `/run/media/$USER/mountpoint`. Это зависит от конкретного дистрибутива и настроек рабочего стола, но для учебных целей правильным ответом является `/media`.

### 2.3. Ключи команды `tar`

**Вопрос:** *Почему ключи команды `tar` так трудно запомнить?*

**Ответ:** Это нормально. Команда `tar` использует много ключей, и даже опытные пользователи часто обращаются к шпаргалкам. Главное — запомнить основные комбинации: `-czf` (создать сжатый архив), `-xzf` (извлечь сжатый архив), `-tf` (просмотреть содержимое). Самостоятельно сделанные шпаргалки помогают запомнить их быстрее.

### 2.4. Поведение `find` с шаблоном `???`

**Вопрос:** *Команда `find ???` (без `-name`) ищет не совсем то, что ожидается. Почему?*

**Ответ:** Команда `find ???` (без `-name`) ищет не файлы с именем из трёх символов, а **полные пути**, в которых хотя бы одна папка имеет имя из трёх символов. Это может дать много лишнего вывода. Для поиска именно файлов с трёхсимвольным именем нужно использовать `find . -name "???"`. Ключ `-name` всегда ищет только имена файлов, а не пути.

## 3. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Конфигурационные файлы в `/etc` как цель атаки:** Каталог `/etc` содержит глобальные настройки системы. Если злоумышленник получает права на запись в `/etc`, он может изменить конфигурации служб, добавить пользователей, подменить ключевые файлы. Это классический путь к повышению привилегий. Важно контролировать права (`chmod 644`, `chown root:root`) и регулярно проверять целостность (`aide`, `tripwire`).
    
- **Автоматическое монтирование съёмных носителей:** Точки монтирования (`/media`, `/run/media`) создаются автоматически при подключении внешних дисков. Если на устройстве есть autorun-скрипты или вредоносные файлы, они могут запуститься при открытии. Рекомендуется отключать автозапуск, монтировать вручную (`udisksctl mount -b /dev/sdb1`) и использовать опции `noexec,nodev`.
    
- **Использование `find` для разведки:** Команда `find /` может раскрыть структуру файловой системы и имена чувствительных файлов (например, бэкапов, ключей). Злоумышленник, получивший доступ к консоли, может быстро просканировать систему на предмет ценных данных. Снизить риск можно, ограничив доступ к каталогам с секретами и используя системы контроля целостности.
    
- **Архивы (`tar`, `zip`) как вектор внедрения:** Архивы сохраняют права доступа и могут содержать файлы с SUID-битом или символические ссылки, ведущие в системные каталоги. Распаковка непроверенного архива может привести к записи в небезопасные места или выполнению кода с повышенными привилегиями. Обязательно проверяйте содержимое (`tar -tvf`, `unzip -l`) перед извлечением.
    

### 2. Инженерный FAQ

- **Вопрос:** _Чем опасен каталог `/etc` с правами `777`?_  
  **Ответ:** Любой пользователь может изменять конфигурационные файлы, что позволяет внедрить вредоносные настройки. Например, изменить `/etc/passwd` для создания нового пользователя с правами root, или подменить конфиг службы для удалённого выполнения кода. Следует использовать `chmod 644` и ограничивать доступ.
	
- **Вопрос:** _Почему внешний диск стоит монтировать с опцией `noexec`?_  
  **Ответ:** Это предотвращает выполнение исполняемых файлов с носителя. Даже если на флешке окажется вредоносный скрипт, он не сможет запуститься без явного разрешения. Дополнительно используют `nodev`, чтобы игнорировать файлы устройств.
    
- **Вопрос:** _Как `find /` может помочь злоумышленнику?_  
  **Ответ:** Команда `find / -type f -name "*.key"` или аналогичные позволяют быстро найти приватные ключи, пароли, бэкапы баз данных. Это один из методов рекогносцировки. Для защиты необходимо хранить чувствительные файлы в каталогах с ограниченным доступом и регулярно проверять, нет ли излишне открытых файлов.
    
- **Вопрос:** _Что делать, если пришлось распаковать архив из ненадёжного источника?_  
  **Ответ:** Сначала просмотрите содержимое (`tar -tf`), затем распакуйте в изолированный каталог (например, `/tmp/archive`), после чего проверьте права на извлечённые файлы: `find /tmp/archive -perm -4000` (SUID) и `find -type l` (символические ссылки). При обнаружении SUID-файлов снимите бит: `chmod u-s file`.
    
- **Вопрос:** _В чём разница между системными и пользовательскими конфигами с точки зрения безопасности?_  
  **Ответ:** Системные конфигурации (`/etc`) влияют на всю систему и требуют прав root для изменения. Пользовательские (`~/.config`) затрагивают только конкретного пользователя. Поэтому компрометация системного конфига опаснее – она может привести к полному захвату системы. Права на `/etc` должны быть максимально строгими.
