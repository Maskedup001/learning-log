# Тема 5.1: Поиск файлов — команда `find`

В данной теме рассматривается команда `find` — один из основных инструментов для поиска файлов и директорий в Linux. Разбираются базовый синтаксис, фильтрация по имени, размеру, типу и глубине поиска, шаблоны (wildcards), комбинирование условий и практические примеры. В конце приведены разбор типичных вопросов и полезные советы из комментариев.

---

## 1. Команда `find` — Базовые свойства

- **Контекст/Уровень:** Системное администрирование / Файловая система.
- **Основное назначение:** Поиск файлов и каталогов в файловой системе по различным критериям (имя, размер, тип, дата изменения и др.).
- **Принцип работы:** `find` рекурсивно обходит указанную директорию и проверяет каждый объект на соответствие заданным условиям. Результат выводится в терминал или может быть передан на дальнейшую обработку.

### 1.1. Базовый синтаксис

```bash
find [путь] [условия] [действия]
```

Если путь не указан, поиск выполняется в текущей директории.

### 1.2. Простейшее использование

```bash
find           # вывести все файлы и папки в текущей директории (рекурсивно)
find .         # то же самое (явное указание текущей директории)
```

> **Важное замечание:** `find` без аргументов выводит всё содержимое текущей директории и всех поддиректорий. Это может быть очень много, если вы находитесь в корневой директории.

> **Важное замечание о `find *`:**  
> Команда `find *` (со звёздочкой) ведёт себя иначе, чем `find` без аргументов.  
> - `find` ищет **все** файлы и папки, включая скрытые (начинающиеся с точки).  
> - `find *` ищет **только не-скрытые** объекты, потому что `*` раскрывается оболочкой и не включает скрытые файлы. Это типичное поведение звёздочки во всех командах Linux.

## 2. Поиск по имени файла

### 2.1. Поиск с учётом регистра — `-name`

```bash
find . -name "NewFile.txt"
```

Поиск файла с точным именем `NewFile.txt` в текущей директории и её подкаталогах. Ключ `-name` выполняет поиск с учётом регистра букв.

### 2.2. Поиск без учёта регистра — `-iname`

```bash
find . -iname "newfile.txt"
find . -iname "NEWFILE.TXT"   # тоже найдёт newfile.txt
```

Ключ `-iname` (insensitive name) игнорирует регистр букв.

---

## 3. Шаблоны поиска (wildcards)

| Символ | Значение | Пример |
| :--- | :--- | :--- |
| `*` | Любая последовательность символов (включая пустую) | `find -name "*.txt"` — все файлы `.txt` |
| `?` | Ровно один любой символ | `find -name "file?.txt"` — `file1.txt`, `fileA.txt`, но не `file10.txt` |
*Таб. 1. Специальные символы для шаблонов поиска.*

### 3.1. Примеры с шаблонами

```bash
find -name "*.txt"                # все файлы с расширением .txt
find -name "report*"              # файлы, начинающиеся с report
find -name "report??"             # report + ровно 2 любых символа (например, report01)
find -name "report???"            # report + ровно 3 любых символа (например, report001)
```

> **Важно:** Шаблоны с `*` и `?` необходимо заключать в кавычки, чтобы оболочка не интерпретировала их до передачи команде `find`.

---

## 4. Указание пути для поиска

По умолчанию `find` ищет в текущей директории. Можно явно указать другой путь:

```bash
find /home/user -name "*.txt"     # поиск в /home/user и всех поддиректориях
find ~ -name "*.conf"             # поиск в домашней директории (~)
find /etc -name "*.conf"          # поиск в /etc
```

---

## 5. Ограничение глубины поиска — `-maxdepth`

Ключ `-maxdepth` ограничивает глубину рекурсивного обхода директорий.

```bash
find ~ -maxdepth 1 -name "*.txt"   # поиск только в домашней директории, без подпапок
find ~ -maxdepth 2 -name "*.txt"   # поиск в домашней директории и на один уровень вложенности
```

---

## 6. Поиск по размеру файла — `-size`

Ключ `-size` позволяет искать файлы по их размеру.

### 6.1. Синтаксис

```bash
find -size [+|-]<число><суффикс>
```

| Символ | Значение |
| :--- | :--- |
| `+` | Больше указанного размера |
| `-` | Меньше указанного размера |
| (без знака) | Точно указанный размер |
*Таб. 2. Символы для сравнения размера.*

### 6.2. Суффиксы размера (из `man find`)

| Суффикс | Единица измерения |
| :--- | :--- |
| `c` | Байты |
| `k` | Килобайты (1024 байта) |
| `M` | Мегабайты (1024 килобайта) |
| `G` | Гигабайты (1024 мегабайта) |
*Таб. 3. Суффиксы размера.*

### 6.3. Примеры

```bash
find -size +10k     # файлы больше 10 КБ
find -size -1M      # файлы меньше 1 МБ
find -size 500k     # файлы размером ровно 500 КБ
find -size +100M    # файлы больше 100 МБ
```

> **Примечание:** Суффиксы чувствительны к регистру: `k` — килобайты, `M` — мегабайты.

---

## 7. Комбинирование условий

Условия можно комбинировать, указывая их последовательно:

```bash
find ~ -maxdepth 2 -name "*.txt" -size +1k
```

Ищет в домашней директории (глубина до 2) файлы `.txt` размером больше 1 КБ.

## 8. Практические примеры

### 8.1. Создание тестовых файлов

```bash
touch report01 report02 report03 report001 report002 report003
```

### 8.2. Поиск с использованием шаблонов

```bash
find -name "report*"        # report01, report02, report03, report001, report002, report003
find -name "report??"       # report01, report02, report03 (ровно 2 символа после report)
find -name "report???"      # report001, report002, report003 (ровно 3 символа)
```

### 8.3. Поиск с разным регистром

```bash
find -name "Newfile.txt"    # не найдёт (если имя newfile.txt)
find -iname "newfile.txt"   # найдёт независимо от регистра
```

## 9. Разбор сложных ситуаций и типичных вопросов

### 9.1. Поиск происходит только в текущей папке?

**Вопрос:** *Команда `find west` выдаёт ошибку `No such file or directory`, хотя файл `west` есть во вложенной папке. Почему?*

**Ответ:** По умолчанию `find` ищет в том месте, где вы его вызываете. Если вы находитесь в одной папке, а файл лежит в подпапке, нужно либо указать путь к корню поиска (`.`, `~`), либо использовать ключ `-name` для поиска по имени во всех поддиректориях.

**Пример:**
```bash
# Неправильно — ищет файл west в текущей папке
find west

# Правильно — ищет файл с именем west во всех подпапках
find -name west
```

**Пример из реальной практики (комментарий пользователя):**

Допустим, у вас есть такая структура каталогов:

```plaintext
.
├── test.txt
└── test2
    ├── folderx
    │   └── testfile.txt
    └── test3
        └── west
```

Если вы находитесь в корневой папке и выполняете:

```bash
find west
```

то получите ошибку `No such file or directory`, потому что `find` ищет файл или папку с именем `west` именно в **текущей** директории.

Правильный способ найти файл `west` во всех вложенных папках:

```bash
find -name west
```

Этот вариант рекурсивно обойдёт все подкаталоги и найдёт `./test2/test3/west`.

### 9.2. Разница между `find` и `find *`

**Вопрос:** *В чём разница между `find` и `find *`?*

**Ответ:** `find` ищет все файлы, включая скрытые (начинающиеся с точки). `find *` ищет только те файлы и папки, которые не начинаются с точки. Это связано с тем, что `*` раскрывается оболочкой, и в неё не попадают скрытые объекты.

### 9.3. `-exec` — выполнение действий над найденными файлами

**Вопрос:** *Как удалить все найденные файлы через `find`?*

**Ответ:** Для выполнения действий над найденными файлами используется ключ `-exec`. Пример удаления всех файлов `.htaccess` в текущей директории и подпапках:

```bash
find . -name ".htaccess" -exec rm -rf {} \;
```

`{}` подставляется вместо имени найденного файла, а `\;` завершает команду. Это мощный инструмент, который требует осторожности — сначала всегда проверяйте, что именно будет удалено.

### 9.4. Расширенный пример: поиск и удаление файлов `.htaccess` в реальной практике

**Контекст:** Apache — это веб-сервер, обрабатывающий запросы к сайту. Файлы `.htaccess` — это его локальные настройки для отдельных папок. Злоумышленники часто используют их для перенаправления трафика или внедрения вредоносного кода.

**Вопрос:** *В каких ситуациях на практике применяется удаление файлов `.htaccess` через `find`?*

**Ответ:** Этот приём часто используется при **лечении заражённых сайтов** (например, на CMS Bitrix или WordPress). Вредоносные скрипты, попадая на сервер, часто создают или модифицируют файлы `.htaccess`, добавляя в них подозрительные правила перезаписи (`RewriteRule`). Эти правила могут:

- перенаправлять трафик на фишинговые страницы;
- подгружать вредоносный код с внешних ресурсов;
- блокировать доступ к административным панелям.

Команда `find . -name ".htaccess" -exec rm -rf {} \;` позволяет **одним вызовом** найти и удалить все такие файлы по всему сайту, что значительно ускоряет процесс очистки.

**Пример реального вредоносного правила в `.htaccess`:**

```apache
RewriteCond %{REQUEST_URI} ^/.*$
RewriteRule ^(.*)$ http://malicious-site.com/tracker.php [L]
```

После выполнения команды поиска и удаления рекомендуется **перезапустить веб-сервер** (например, `sudo systemctl restart apache2` или `nginx -s reload`), чтобы изменения вступили в силу.

> **Важное предостережение:** Перед выполнением команды с `-exec` обязательно **проверьте, что именно будет удалено**. Для этого сначала запустите `find` без `-exec`:

```bash
find . -name ".htaccess"
```

Убедитесь, что среди найденных файлов нет легитимных (например, системных `.htaccess` с корректными настройками). Только после этого выполняйте удаление.

## 10. Лимиты, оптимизация и масштабирование

- **Глубина поиска:** Без ограничения `-maxdepth` `find` может обойти всю файловую систему, что займёт много времени и создаст нагрузку на диск. В больших каталогах всегда ограничивайте глубину.
- **Комбинирование условий:** Чем больше условий, тем точнее результат, но тем дольше выполняется поиск.
- **Использование `-exec`:** Запускает внешнюю команду для каждого найденного файла. Это может быть медленно при большом количестве файлов. Альтернатива — использовать `-exec ... +` для групповой обработки.

## 11. Расширенный ИБ-контекст и инженерный FAQ

### 1. Векторы атак и уязвимости (Security Context)

- **Удаление через `-exec`:** Использование `find ... -exec rm -rf {} \;` без предварительной проверки может привести к потере важных данных. Всегда сначала запускайте `find` без `-exec`, чтобы убедиться, что найдены нужные файлы.
- **Поиск конфиденциальных файлов:** `find` можно использовать для поиска файлов с паролями, ключами или другими чувствительными данными (например, `find . -name "*.key"`). В производственных средах рекомендуется ограничивать доступ к таким данным.

### 2. Инженерный FAQ

- **Вопрос:** *Как найти все файлы с расширением `.conf` в системе?*  
  **Ответ:** Используйте `find / -name "*.conf" 2>/dev/null`. Перенаправление ошибок `2>/dev/null` скрывает сообщения о недоступных директориях.

- **Вопрос:** *Как найти файлы, изменённые за последние N дней?*  
  **Ответ:** Используйте ключ `-mtime`. Например, `find . -mtime -7` — файлы, изменённые за последние 7 дней.

- **Вопрос:** *Как найти файлы определённого типа (например, только директории)?*  
  **Ответ:** Используйте ключ `-type`. `find . -type d` — только директории, `find . -type f` — только файлы.

- **Вопрос:** *Что делать, если `find` выдаёт ошибки «Permission denied»?*  
  **Ответ:** Перенаправьте ошибки в `/dev/null`: `find / -name "*.txt" 2>/dev/null`. Или запустите от имени `sudo`, если вам нужен полный доступ.

- `find` по умолчанию ищет рекурсивно во всех поддиректориях.

## Заключение

Команда `find` является одним из самых мощных и гибких инструментов для поиска файлов в Linux. Умение фильтровать по имени, размеру, глубине и типу позволяет быстро находить нужные объекты даже в огромных файловых системах. Важно помнить о необходимости заключать шаблоны в кавычки и всегда проверять результаты перед использованием опасных действий через `-exec`. Эти навыки являются базовыми для системного администратора и разработчика.
