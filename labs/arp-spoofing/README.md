# ARP-spoofing и MitM-атака

Лабораторная работа по исследованию протокола ARP, реализации атаки ARP-spoofing через библиотеку Scapy и методам защиты.

## 📚 Теоретическая база

**ARP (Address Resolution Protocol)** — протокол канального уровня (L2), который сопоставляет IP-адреса с MAC-адресами в локальной сети. 

**Проблема:** В ARP нет никакой аутентификации. Хост слепо верит любому входящему ARP-ответу (даже если он его не запрашивал). Злоумышленник может отправить поддельный ARP-ответ (unsolicited ARP-reply) и сказать жертве: *«IP шлюза теперь на моём MAC»*. Жертва обновит свой ARP-кэш и начнёт отправлять трафик атакующему.

## 🛠 Стенд
- **Атакующая VM** (Ubuntu 24.04): IP `192.168.99.3`
- **Жертва** (Ubuntu Server 24.04): IP `192.168.99.4`
- **Шлюз**: IP `192.168.99.1`
- **Инструменты**: Scapy, Wireshark, VirtualBox (NAT Network).

## ⚔️ Сценарии атаки

### 1. DoS (Отказ в обслуживании)
Если подставить несуществующий MAC-адрес (например, `aa:bb:cc:dd:ee:ff`), жертва будет отправлять пакеты в пустоту. Связь с сетью полностью пропадёт. Реализовано в файле `arp_spoof.py`.

### 2. Man-in-the-Middle (MitM)
Если подставить реальный MAC-адрес атакующего и включить проброс трафика (`ip_forward=1`), жертва и шлюз будут думать, что общаются напрямую, но весь трафик пойдёт через атакующего. Реализовано в файле `arp_spoof_mitm.py`.

## 🛡 Методы защиты от ARP-spoofing
1. **Static ARP** — ручная привязка IP-MAC для критичных узлов (шлюзов, серверов).
2. **DAI (Dynamic ARP Inspection)** — функция управляемых коммутаторов. Проверяет ARP-пакеты на основе базы DHCP Snooping и блокирует поддельные.
3. **Шифрование** (HTTPS, VPN) — защищает данные, даже если атакующий перехватил трафик (компенсационная мера).

- `arp_spoof_mitm.py` — скрипт двусторонней атаки (MitM).
